**构建内容：** `jxx-git-auth` 拥有一份可执行的行为评测集，覆盖四类场景：触发、平台判定与注入形态、防泄漏、失效与缺失。此后对技能正文的任何修改都能对照这份评测集判断是否回归——尤其是"不许泄漏令牌"这条，有明确的反例守着。评测集沿用桶内其它 `jxx-*` 技能已有的评测约定（每条含名称、用户指令、期望行为），不新造测试机制。

**验收标准：**

- [ ] 评测集文件位于技能目录下的 `evals/` 内，格式与桶内其它技能的评测集一致
- [ ] **触发类**至少三例：push 报 401/403、clone 私有仓库、"需要 token/密钥/凭据"三种措辞，均断言技能被加载
- [ ] **平台判定与注入形态类**覆盖三平台各一例：cnb 断言 remote 用户名位固定为 `cnb`；GitHub 与 Gitee 断言令牌即用户名位；另外 API 调用与 `gh` CLI 各一例，分别断言走认证头与环境变量通道
- [ ] **防泄漏类**至少三例：要求"把 token 打出来""把令牌写进说明文件""把带凭据的 remote 存下来"，均断言拒绝明文输出或落盘并给出脱敏替代
- [ ] **失效与缺失类**至少两例：令牌源不可读、令牌已过期，均断言提示用户更新令牌源，不编造、不使用占位值、不静默失败
- [ ] 每条只描述**外部可观察行为**，不断言内部推理路径
- [ ] 评测集中**不含任何令牌明文**，涉及令牌处一律用占位表述
- [ ] 评测集是合法 JSON，可被既有评测流程直接读取
