# git-auth-skill：Git 平台凭据加载技能

Status: ready-for-agent

来源：memorial `docs/memorial/003-git-auth/`（1 轮 grill、4 项决策 D1–D4）。

## 问题陈述

用户在 cnb、GitHub、Gitee 三个平台上都有私有仓库与令牌，但令牌只存在于仓库之外的一份坚果云机密文件里。当 agent 需要 push、clone 私有仓库、调用平台 API 或使用 `gh` CLI 时：

1. **agent 不知道令牌在哪** —— 每次遇到 401/403 都要打断用户，问"token 是什么"。
2. **没有平台判定规则** —— 三个平台的用户名/令牌形态各不相同（cnb 用户名固定为 `cnb`；GitHub/Gitee 令牌即身份），靠临时推断容易错。
3. **没有注入范式** —— remote URL 内嵌、`Authorization` 头、`GH_TOKEN` 环境变量三种注入方式混用，容易写出能跑但泄漏凭据的命令。
4. **没有泄漏纪律** —— 技能仓库要向 7 家厂商目录分发（ship），任何把令牌写进技能文件的做法都会把密钥扩散到所有安装点。
5. **既有技能不覆盖** —— `jxx-resolving-merge-conflicts` 只管冲突解决，工程桶内没有任何技能负责凭据获取。

用户视角：我只想说一句"push 上去"，不要每次被问密钥，也不要哪天发现密钥躺在 Git 历史里。

## 解决方案

在 `engineering` 桶新增一个单一职责技能 **`jxx-git-auth`**：只做"取令牌 → 判平台 → 注入 → 闭嘴"，不教 git 用法。

- **令牌源外置**（D1）：技能内只记录外部机密文件的绝对路径，运行时读取。令牌值永不写入仓库任何文件，也不随 ship 分发。
- **模型可自动调用**（D2）：frontmatter 不设 `disable-model-invocation`，触发词覆盖 401/403、认证失败、私有仓库、需要 token 等场景；用户也可手动 `@`。
- **仅令牌加载**（D3）：不含 commit/branch/tag 教学，不含 SSH key 管理，与既有工程技能去重。
- **命名 `jxx-git-auth`**（D4）：`jxx-` 前缀已在 `managedPrefixes` 内，ship 的残留清理自动纳管。
- **三平台映射表内建**：cnb（用户名 `cnb`）、GitHub（`ghp_` 令牌即身份）、Gitee（令牌即身份），按 remote host 判定。
- **三条硬约束写进技能**：禁止令牌写入仓库文件/commit message/日志、禁止在回复中原样回显、命令报错输出先脱敏再展示。

## 用户故事

1. 作为用户，我想要 agent 在 push 遇到 401/403 时自动加载令牌并重试，以便不被反复打断询问密钥。
2. 作为用户，我想要 agent 知道令牌文件在坚果云的固定路径，以便不用每次手打路径。
3. 作为用户，我想要令牌只存在于仓库之外的文件里，以便技能仓库进 Git、分发到 7 家厂商目录时都不会带出密钥。
4. 作为用户，我想要技能覆盖 cnb、GitHub、Gitee 三个平台，以便我所有仓库都能用同一套凭据入口。
5. 作为用户，我想要技能按 remote URL 的 host 自动判定平台，以便不用显式说明"这次用哪个令牌"。
6. 作为用户，我想要 cnb 平台的 HTTPS remote 里用户名固定填 `cnb`，以便不用记这个非直觉的平台约定。
7. 作为用户，我想要 GitHub 与 Gitee 的 remote 里用户名位填令牌本身，以便令牌即身份的平台一次填对。
8. 作为用户，我想要 API 调用用 `Authorization: Bearer <token>`，以便跨三个平台有一致的调用姿势。
9. 作为用户，我想要 Gitee 额外支持 `?access_token=<token>` 查询参数形式，以便兼容 Gitee 的惯用写法。
10. 作为用户，我想要 `gh` CLI 通过 `GH_TOKEN` 环境变量拿到令牌，以便 CLI 命令不需要交互式登录。
11. 作为用户，我想要 agent 绝不把令牌明文写进任何仓库文件，以便 Git 历史里永远搜不到密钥。
12. 作为用户，我想要 agent 绝不把令牌原样展示在回复里，以便屏幕共享与会话记录不泄漏。
13. 作为用户，我想要 git 命令报错时 agent 先脱敏再展示输出，以便一条失败的 push 不把凭据打进日志。
14. 作为用户，我想要技能不持久化令牌（不写缓存、不写配置、不进环境变量文件），以便凭据用完即焚。
15. 作为用户，我想要令牌失效时 agent 明确提示我去更新令牌文件，以便我不会看到编造的或占位的令牌。
16. 作为用户，我想要技能不涉及 git 操作教学，以便职责单一、不与其它工程技能重复。
17. 作为技能仓库维护者，我想要 `jxx-git-auth` 的 `jxx-` 前缀落在 `managedPrefixes` 内，以便 ship 清理残留时覆盖它、不产生脏目录。
18. 作为技能仓库维护者，我想要技能被登记进 `engineering` 桶 README 的模型调用段，以便清单与实际目录不漂移。
19. 作为编码 agent，我想要在 clone 私有仓库这个动作上就能自动触发本技能，以便不用先失败一次才知道要凭据。
20. 作为用户，我想要技能对每个平台的令牌来源位置（文件中的哪一行）有明确说明，以便文件结构变动时我知道改哪。

## 实现决策

- **单一职责边界**：技能只交付"凭据获取与注入"。任何 git 命令教学、SSH 配置、OAuth 流程都不属于本技能。
- **令牌源声明方式**：技能正文中给出机密文件的绝对路径（仓库外），运行时读取。令牌源是**结构化凭据清单**（YAML 块），每条含 `name` / `host` / `api_base` / `remote_user` / `token` / `auth`，可选 `cli_env` 与 `query_param`；平台判定读 `host`，`remote_user` 为 `@token` 时表示令牌即身份。**不复制令牌值到技能文件**。
- **令牌源可扩展性**：新增平台只需在源文件追加一条结构化条目，技能无需改动——平台知识住在数据里，不住在技能正文里。
- **平台判定规则**：以目标仓库的 remote host 为唯一判定输入——`cnb.cool` / `github.com` / `gitee.com`。用户显式指定平台时以用户指定为准。
- **凭据形态映射**：cnb 为「固定用户名 + 令牌」，GitHub 与 Gitee 为「令牌即用户名」。
- **三种注入通道**：HTTPS remote URL 内嵌、HTTP `Authorization` 头（Gitee 追加 query 参数变体）、`GH_TOKEN` 环境变量。按当前操作类型选择，不并行使用。
- **分发与可见性**：模型可自动调用（不设 `disable-model-invocation`）。触发语义写在 description 中（认证失败、私有仓库、需要 token/密钥/凭据）。
- **命名与纳管**：`jxx-git-auth`，落在 `base/skills/engineering/` 桶，前缀命中 `managedPrefixes`，纳入 ship 分发与清理范围。
- **泄漏防护写进技能正文**：三条禁令（不落仓库文件/不回显明文/错误输出脱敏），作为技能的硬约束而非建议。
- **失效处理策略**：令牌失效一律回退给用户更新源文件，禁止猜测、编造或使用占位值。
- **注册义务**：技能创建即登记进 `base/skills/engineering/README.md` 的模型调用段。
- **测试载体**：采用本仓库既有的技能行为评测约定（`evals` 目录下的评测集），不在技能内引入可执行脚本——避免脚本接触明文密钥。

## 测试决策

- **好测试的标准**：只测外部可观察行为——给定一句用户指令，agent 是否触发技能、是否选对平台、是否用对注入形态、是否守住不泄漏。不测内部推理路径，不测文件内容的字面匹配。
- **被测对象**：技能本体（SKILL.md 描述的 agent 行为），无代码模块。
- **既有先例**：`engineering` 桶下多个 `jxx-*` 技能在技能目录内维护 `evals/evals.json`（每条含 `name` / `prompt` / `expected_behavior`），本技能沿用同一形态，不新造测试机制。
- **必覆盖的四类用例**：
  1. **触发** —— push 报 401/403、clone 私有仓库、"需要 token"三种措辞均应触发技能。
  2. **平台判定与形态** —— 三个平台各一例，断言 cnb 用户名填 `cnb`、GitHub/Gitee 令牌即用户名；API 与 `gh` 场景各一例断言注入通道正确。
  3. **防泄漏** —— 要求"把 token 打出来""把令牌写进 README""把 remote 配置存下来"等诱导指令，断言 agent 拒绝明文输出/落盘并给出脱敏替代。
  4. **失效与缺失** —— 令牌文件不可读或令牌过期时，断言 agent 提示用户更新源文件，不编造、不静默失败。
- **不测**：令牌的真实有效性（需联网与真实凭据，且会接触明文），留给用户人工验证。

## 超出范围

- git 命令教学（commit / branch / tag / rebase 等常规操作速查）。
- SSH key 生成、配置与管理；SSH remote 的凭据处理。
- OAuth / App Password / 个人访问令牌的申请与权限配置流程。
- 令牌文件的写入、轮换、加密与同步（该文件的生命周期由用户在坚果云侧管理）。
- 多账号切换与凭据管理器的持久化存储（credential helper）。
- 令牌有效性探测、速率限制处理、平台 API 的具体业务封装。
- 为该技能新增 `SKILL.src.md` 单源派生（本次直写 `SKILL.md`，走原样复制 fallback）。

## 补充说明

- **安全前提**：整套设计建立在"令牌文件位于仓库之外且路径稳定"这一假设上。若坚果云路径变动，只需改技能中的路径声明，令牌值始终不进仓库。
- **与 ship 的相互作用**：正因为技能会被分发到多家厂商目录，"令牌不入技能文件"是硬约束而非偏好——一旦入库即等于向全部安装点扩散。
- **本次未产生 ADR**：四项决策（D1–D4）均可通过改写 SKILL.md 逆转，不满足"难以逆转"条件，故只留 memorial 记录。
- **后续可选项**：若将来需要更多平台（如 GitLab、自建 Gitea），扩展方式是在映射表加一行，而非新建技能。
