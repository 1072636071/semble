**「一次性 strict 全量修复」= 254 条错误 / 353 个文件中 53 个文件有错（15%），属于【中】（100–500 档）。**

### 问题 5 · 分批可行性 —— **数据不支持「按目录分批开 strict」**

不是"不太好分"，是 **tsconfig 机制上做不到**。两组硬证据：

1. **`exclude` 挡不住。** 配置 `include: src/**/*.ts` + `exclude: [src/core/**, src/metadata/**]` 实测：
   - 仍有 **204 个 `core`/`metadata` 文件被编译**（该两目录共 219 个，只挡下 15 个叶子文件）；
   - 仍有 **109 条错误**从这两个目录报出来（未 exclude 时是 113 条）。
   - 原因：只要有任何别处的文件 `import` 它们，tsc 就会把整个传递闭包拉进 program，`exclude` 只作用于 glob 展开，不作用于 import 图。
2. **只 `include` 一个叶子目录也照样炸。** 配置 `include: src/utils/**/*.ts`（18 个文件）实测：
   - 实际进入编译 **82 个文件**（多出 64 个被传递拉入）；
   - 报出 23 条错误，其中 **12 条不在 `src/utils` 里**。

**所以**：要么一次性全量；要么上 project references（每目录一个 tsconfig + `composite`，353 个文件拆 references 的成本远高于修 254 条错误，不划算）。

**替代建议（推荐）：不分目录，按「根因批次」推进。** 顺序 = 先清单点根因 → 再啃叶子 → 最后啃核心：

| 批次 | 内容 | 预估错误 | 文件数 | 性质 |
|---|---|---|---|---|
| **批 0（前置，不写代码）** | ① 重新生成 `gateway/generated`（补 OpenAPI spec 里的 wiki/codeGraph path 后跑 kubb）② 定 `SQLInputValue` / 绑定值类型是否接受 `undefined\|null` | **-95 条**（51 + 44） | 1 个决策 + 1 次生成 | 1 个动作消掉 37% |
| **批 1** | `src/cli`(0) + `src/offload-client`(0) + `src/api-trace`(1) + `src/offload_server`(1) + `src/services`(2) + `src/adapters`(4) + 断链 import 14 条 | ~22 | 51 | 纯叶子，几乎零风险 |
| **批 2** | `src/utils`(11) + `src/metadata`(21) | ~32 | 52 | 机械标注为主 |
| **批 3** | `src/offload`(16) | ~16 | 34 | **需重构构造流程**（TS2564 ×11 + TS2729 ×2，加 `!` 是掩盖不是修复） |
| **批 4** | `src/core`(92) | ~92 | 185 | 文件多、密度低，可并行 |
| **批 5** | `src/gateway`(106，批 0 后约剩 55) | ~55 | 32 | 最后啃，含 6 处真 bug |
| **批 6（可选）** | src 外：`index.ts` / `scripts/*` / `pi-plugin` | 23 | 27 | 口径 C 才需要 |

`MemoryCore/` 下 **7 个 tsconfig 全部是 `strict: true`** —— 有现成基线可直接继承，**新根 tsconfig 不是从零设计**：

| `scripts/export-tencent-vdb/tsconfig.json` | `strict: true`, `Node16` | |
| `scripts/migrate-sqlite-to-tcvdb/tsconfig.json` | `strict: true`, `NodeNext` | |
| `scripts/read-local-memory/tsconfig.json` | `strict: true`, `Node16` | |

**建议起点**：以 `openclaw-plugin/tsconfig.json` 为模板（`ESNext` + `bundler` + `strict` + `skipLibCheck` + `types:["node"]`），因为它与 tsdown 实际构建方式一致；`scripts/*` 那三个用 `Node16/NodeNext` 是因为它们要 emit 成真 ESM 产物，根 tsconfig 只做 `--noEmit` 门禁，不需要跟它们对齐。

### 风险提示（不是"加标注就能解决"的部分）

1. **`src/gateway/generated/schemas.ts` 的 51 条不能手改。** 文件头写着 `Generated by Kubb ... Do not edit manually`。根因是生成时 OpenAPI spec 里没有 wiki / codeGraph 这两组 path。这是**流程/构建问题**：要么补 spec 重新生成，要么把生成物移出 strict 范围。手改会被下次生成覆盖。
2. **真 bug（不是类型问题，加标注会掩盖）：**
   - `src/core/skill/conversation-add/add-handler.ts:276` 和 `:311` 两处 **TS1117「对象字面量重复键」** —— 同一对象里写了两个同名属性，运行期后一个静默覆盖前一个。
   - `src/gateway/server.ts` 6 处 `SkillCoreError` **未导入就使用**（`:2507` `:2524` `:2531` `:2537` `:2635` `:2638` `:2646`）。该类在 `src/core/skill/skill-core.ts:101` 有定义并 export，但 server.ts 没 import → 这些分支一旦走到就是 `ReferenceError`。
   - `src/services/pipeline-worker.ts:806-807` `buildPipelineTimerMember` 未定义。
   - `src/metadata/store/mongodb-adapter.ts:144` 和 `sqlite-adapter.ts:137` **找不到 `IMetadataStore`** —— 两个大 adapter（1000+ / 2700+ 行）的类型契约是断的，`implements` 声明形同虚设。
3. **14 条断链 import 需要人来判断「该删还是该补」。** 其中：
