# ADR-0001 · 证据优先：质量结论不得建立在执行者的自述之上

状态：已接受（memorial 020 内部）
日期：2026-09-13

## 背景

本项目由 AI agent 维护。用户工作流已相当成熟（`jxx-implement` 工单流 + `jxx-code-review` 双轴 + `issue-tracker.md` 的 done 双硬闸 + `.scratch` 下 242 个带验收框的工单），但仍出现三个痛点：

- **A · 没信号** —— agent 改错了，没有任何命令能测出来。
- **B · 看不懂** —— agent 一次改一大片，diff 无法 review。
- **漏需求** —— 验收框全部 `- [x]`，但框描述的要求实际没做到。

实证（`.scratch/27-board-quickwins/issues/01-comment-kernel-api.md`）：6 个验收框已全部勾选，而 agent 在 `## 评论` 中自述「非成员 403 分支仍缺直接用例……已记入本轮缺口」——**框勾了，活没干完，缺口的处置是「记一笔」而非挡住关单**。

## 决策

**凡质量结论，必须附可被独立复核的证据。执行者自述不构成证据。**

具体推论：

1. 验收框的 `- [x]` 不再是结论，只表示「该点已分流」。
2. 每一条验收框必须二选一（见 ADR-0002、ADR-0003），**不允许"勾了完事"这第三种状态**。
3. 机器验证项的「证据」必须可复现：用例名可被 grep 到、命令 `exit 0`。
4. 取证与复核必须由**非执行者的独立主体**完成（校验脚本，或独立复核 agent）。

## 理由

三条痛点表面不同，根因同一个：**系统里所有质量判断的输入都是 agent 自己的话**。在「agent 执行 + 人工测试兜底」的混合态下，这等于**把判断权交给被判断者**。因此「通过率高」本身就是自述的产物，它测不出自述的偏差 —— 这正是「通过率不低却仍会漏需求」的解释。

## 被否决的替代方案

- **仅靠更严格的验收框措辞** —— 措辞再细，勾选仍由 agent 判定，不改变输入性质。
- **仅靠人工 review 兜底** —— 人就成了唯一信号源，「怕改坏」永不消失（每天都要靠人测）。
- **纯格式校验（只查 `- [x]` 后有没有写"证据："）** —— 证据可造假（写个不存在的用例名也能过），退回自述。故必须要求可复现。

## 影响

- `jxx-implement` 硬出口新增分流步骤；`issue-tracker.md` 的 done 硬闸需增加「证据可复现性」校验。
- 校验器**从轻**实现（单脚本 + grep），不引入新框架 —— 用户明确要求「不要特别重」。
- 与既有铁律「已验收 ≠ 代码落地」方向一致，本 ADR 为其补上机器可判定的执行机制。
