简介

阿里开源混合架构 AI 代码审查：确定性流水线 + LLM Agent，精准行级评论。

核心特性

  • 混合架构：确定性静态规则流水线 + LLM Agent 双引擎，降低纯 LLM 误报/漏报
  • 精准行级评论：直接定位问题代码行，可贴到 PR/提交
  • 内置多语言规则集：NPE、线程安全、XSS、SQL 注入等开箱即用
  • LLM 兼容：OpenAI / Anthropic 协议，可接 DeepSeek、Qwen 等模型
  • 阿里生产规模实战验证，仓库持续活跃维护

快速开始

前置要求

  • Git ≥ 2.41
  • Node.js ≥ 18（用 Delegation Mode 时可不配 LLM key）
  • 一个 LLM API Key

四步上手

  1. 安装并确认版本（本机已装 v1.12.4）：ocr version
  2. 配置 LLM：ocr config provider 交互式选厂商/填 key/选模型，并自动跑 ocr llm test 校验；非交互环境用 ocr config set（见下）。
  3. 测试连通性：ocr llm test。报 no valid LLM endpoint configured 回头查配置；401/403 表示 token 错或过期。
  4. 跑首次审查（在任意 Git 仓库内）：
审查模式bash
ocr review                                  # workspace 模式（默认）：审查 暂存+未暂存+未跟踪 改动
ocr review --from main --to feature-branch  # 分支区间：审查 feature 相对 main 的 merge-base 以来的变更
ocr review --commit abc123                   # 单提交：审查该提交相对其父的 diff
ocr review --preview                         # 只跑文件过滤，不调 LLM，打印被审/被排除文件及原因
ocr review --format json --audience agent > review.json  # 机器可读 JSON 输出（agent/CI 友好）

配置详解

配置文件

路径 ~/.opencodereview/config.json（Windows：C:\Users\<你>\.opencodereview\config.json）。三种改法：① ocr config provider / ocr config model 交互式；② ocr config set <key> <value> 非交互（CI/脚本）；③ 直接改 JSON（不推荐，下次 set 会被重排）。

自定义 Provider（以 OpenRouter 为例）

OpenRouter 兼容 OpenAI 协议，用自定义 provider 接入（本机已按此配置）：

自定义 OpenAI 兼容厂商bash
ocr config set provider                             openrouter
ocr config set custom_providers.openrouter.url      https://openrouter.ai/api/v1
ocr config set custom_providers.openrouter.protocol openai
ocr config set providers.openrouter.api_key         "$OPENROUTER_API_KEY"
ocr config set model                                nex-agi/nex-n2.5-pro:free

protocol 可选 anthropic / openai / openai-responses / anthropic-bedrock。url 填 API base 或完整 /responses 端点均可，OCR 会归一化。

ℹ️

内置厂商预设 Base URL；要指向其他端点（如自建 LiteLLM 网关）用 ocr config set providers.<name>.url … 覆盖。完整内置列表见官方 Configuration 文档。若 providers.<name>.api_key 为空，OCR 自动回退到对应环境变量。

环境变量

  • OCR_LLM_URL / OCR_LLM_TOKEN / OCR_LLM_MODEL：直接驱动 LLM（无需 config 文件）。
  • 各厂商 key 环境变量（上表）。已配 Claude Code 的 ANTHROPIC_* 会被自动识别。
  • OCR_LLM_TIMEOUT：HTTP 超时（秒，默认 300）；慢模型/大文件调大。
  • OCR_UPDATE_INTERVAL（分钟，默认 18）与 OCR_NO_UPDATE=1：NPM 包装器的后台自更新（静态二进制不参与）。
  • OCR_VERSION / OCR_INSTALL_DIR / OCR_GITHUB_MIRROR：安装脚本用。

密钥进阶

  • 超时：providers.<name>.timeout_sec / custom_providers.<name>.timeout_sec 按厂商覆盖。
  • 从命令取 key（密钥管理器/系统钥匙串）：ocr config set providers.anthropic.api_key_cmd "op read op://dev/anthropic/api-key"。优先级：静态 api_key > api_key_cmd > 环境变量。Windows 经 cmd.exe 执行该命令。
  • 重试码：ocr config set llm.retry_codes 403,400（仅 4xx，SDK 已重试 408/409/429 与全部 5xx）。

审查规则

规则决定 OCR 对每文件「关注什么」。规则文件是 JSON，存在四个层级，按优先级解析（首个匹配 pattern 胜出）：

优先级来源路径
1（最高）--rule flag用户指定的 CLI 覆盖
2项目配置<repoDir>/.opencodereview/rule.json（可提交）
3全局配置~/.opencodereview/rule.json（用户级偏好）
4（最低）系统默认二进制内嵌 system_rules.json（恒在）

规则文件格式

rule.jsonjson
{
  "include": ["src/**/*.{ts,tsx}", "src/**/*.go"],
  "exclude": ["**/*.test.ts", "**/generated/**"],
  "rules": [
    { "path": "src/api/**/*.go", "rule": "所有导出 handler 必须在用前校验请求体。" },
    { "path": "**/*mapper*.xml", "rule": "检查 SQL 注入风险、参数绑定与未闭合标签。" }
  ]
}
  • include：绕过内置默认排除（如测试文件）的 glob，不是白名单——不匹配 include 的文件仍走后续检查。
  • exclude：用户配置过滤中优先级最高，匹配即跳过。
  • rules：按声明顺序求值，首个匹配的 path glob 决定发给模型的提示。
  • glob 用 doublestar：`**` 跨目录、`{a,b}` 花括号展开（注意 {ts,tsx} 别留空格）、大小写不敏感。

文件过滤六关

binary → secret_exclude（内置密钥路径，不可被 include 覆盖）→ user_exclude → user_include（命中即保留）→ unsupported_ext → default_path（内置测试文件排除）。存活且 diff 不超过 max_tokens 80% 的文件才送审。用 ocr review --preview 查看结果。

排查规则

检查某文件命中哪条规则bash
ocr rules check src/main/java/com/example/UserService.java
ocr rules check --rule custom.json src/main/resources/mapper/UserMapper.xml

打印命中的层级与pattern，便于定位「规则不生效」问题（首个匹配胜出，更具体的规则放数组前面）。

常见问题

  • no valid LLM endpoint configured：端点三元组 (URL, token, model) 不完整。用 ocr config set llm.* 或导出 OCR_LLM_*，再 ocr llm test 验证。
  • ocr llm test 显示错误 source：OCR 取第一个完整三元组而非最后一个；要让环境变量生效，需删掉 config 里的 llm.* 键。
  • 401 / 403：token 权限不足/过期，或协议与 URL 形态不匹配（Anthropic 用 /v1/messages，OpenAI 用 /v1/chat/completions）。
  • not a git repository：不在 Git 工作树。cd 进仓库或传 --repo /path/to/repo。
  • My file isn't being reviewed：被过滤器排除。跑 ocr review --preview 看每文件排除原因（user_exclude / unsupported_ext / default_path / too_large）。
  • No tool calls parsed（本地模型/Ollama）：模型不支持原生函数调用（如 deepseek-r1）。换支持 native tool calling 的模型（如 qwen3），必要时调大 timeout_sec。
  • --audience agent 仍有进度行：进度走 stderr，重定向即可：ocr review --audience agent 2>/dev/null。
  • JSON 输出 {files_reviewed:0, comments:[]}：区分「无文件合格」与「审查完无发现」——看 summary.files_reviewed 或 manifest.terminal_state（skipped=无文件，complete=已审查无问题）。
  • Max tool requests reached：模型 100 轮工具调用仍未 task_done。换更强模型、查 session JSONL 是否有工具反复报错、用 --max-tools <n> 提高上限。
