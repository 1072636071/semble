提示词与 Agent 人设方案 · 索引与跨厂商敏感度对照（2026-10）

为什么分五套：不同 LLM 对提示词的敏感度不一样——同一句「用 JSON 输出」、同一段人设、同一个 temperature，在 DeepSeek / GLM / MiniMax / Kimi 上的效果可以相反，甚至在同厂商不同代际之间也相反。本索引把差异压缩成可查的矩阵，五份手册负责给证据与模板。 定稿日期：2026-10-20。检索方式：厂商官方文档站 / 官方 GitHub / 模型卡 / arXiv 论文为主源，社区横评与源码级 harness 分析为副源；每条标证据等级。 安全约定：本文所有形如〈think〉〈｜begin of sentence｜〉的全角尖括号是排版保护写法，绝不能把它们的半角形式写进提示词（见 §5 第一条坑）。

2. 敏感度对照矩阵（六个维度）

2.1 你能改什么：参数可改性（差异最大的一维）

temperaturetop_p惩罚系数结论
DeepSeek默认 1.0，范围 0–2；官方分场景表：代码/数学 0.0、数据分析 1.0、对话/翻译 1.3、创意 1.5。思考模式静默忽略 temperature / presence / frequency（"will not trigger an error but will also have no effect"，A）flash 仅思考生效且区间 0.95–1.0；v4-pro 思考时忽略（带 tools 固定 0.95）整体 deprecated，传了不生效A 开了思考就忘掉采样，控长度只有 reasoning_effort + max_tokens

附带崩法（跨家一致，A/B）：推理模型的 max_tokens 是「思考 + 答案」总预算 → content 空、reasoning_content 很长、finish_reason="length"、HTTP 仍 200。必须三查 finish_reason + content + usage，不能只看返回码。社区点名"给推理模型写死 max_tokens 是反模式"（C）；真实事故：DeepSeek V4-Flash 一次 post-training 让思考链变长，调用代码一行没改就把写死 max_tokens=4096 的老系统打崩（B）。

2.4 工具调用：每家的「静默失效开关」不一样

家最容易漏的那一条罚则
GLM流式工具调用要 stream=True 且 tool_stream=True；阿里云百炼明文"不传 extra_body={"tool_stream": True} 则不返回 tool_calls、工具调用完全不生效"静默不调用（四家里最隐蔽，A+B）
DeepSeek带 tools 时所有后续请求必须完整回传历史 reasoning_content（哪怕那轮没调工具）；官方快捷写法 messages.append(response.choices[0].message)400 报错A
Kimichoice.message 必须"原封不动"回传（含 reasoning_content）；每个 tool_call 必须有对应 tool_call_id 的 tool 消息报错 / 破坏后续工具调用上下文A
MiniMaxfunction_call 已废弃须用 tools；stop_sequences 被忽略，Anthropic 兼容层还忽略 top_k/mcp_servers/context_management静默不生效A
本地部署通用漏 --enable-auto-tool-choice + 对应 parser（Kimi kimi_k2、DeepSeek V4 deepseek_v4）；漏 add_generation_prompt=True"只聊不调"；实测工具成功率 20% vs 官方 99%+，根因是引擎参数不是模型B C

其他跨家事实：

  • 并行调用：Kimi 官方明文支持且"无依赖的工具倾向于并行"，并提醒 tool_calls 出现时 content 偶尔非空（模型在解释要调哪些工具），别当错误（A）；工程共识：有依赖的调用强行并行比串行更糟，宿主需自判依赖、限并发、独立超时、处理部分失败（C）。
  • 要不要在提示里给工具示例：Kimi 官方不需要（走 tools description + Formula 四步，A）；社区一致口径是 description 越具体，误调用/漏调用越少——"查询天气"远不如"查询某城市的实时天气，当用户询问天气状况时调用"（C）。
  • arguments 是字符串不是对象（全四家）：直接传函数 → TypeError；JSON 里常夹换行缩进 → 先 strip() 再 json.loads；tool_call.id 需唯一且回填时逐字符一致（A C）。
  • tool_choice 支持面：GLM 仅 auto（A）；Kimi k3 支持 auto/none/required，K2.6/2.7 不支持 required，且强制指定单个函数与思考模式互斥（400）（A）。

3. 「最小公共子集」：跨四家都成立、可以先写的东西

  1. 人设只写姿态与边界，不写能力断言——「你是世界级专家」被四篇论文一致否定（A，见通用手册 §1）。
  2. 规则条数按 10 条封顶做审计，一条只说一次（A：ManyIFEval 10 条即下降；OpenAI "State each instruction once"）。
  3. 上模型前做矛盾审计——矛盾指令比长指令更致命（A：GPT-5 会烧推理 token 去调和冲突；Anthropic 同观察）。
  4. 长数据置顶 → 指令紧随 → 输出契约收尾（A：Gemini + Anthropic 一致做法；注意 IFScale 显示是首因偏置，核心行为约束放最前，尾部只放短格式契约）。
  5. 参数优先、措辞让位：思考预算用 effort 档，不用「think step by step」；长度用 max_tokens，不用「写 300 字」（四家官方都警告字数控制不精确：Kimi"指示模型生成特定数量的文字并不具有高精度"、GLM"让模型精确的生成一个特定的字数难以实现"，A）。
  6. 格式契约双写：system 定义 + 末次 user 重申（社区多人一致，C；OpenAI 官方认可每 3–5 轮重申，A）。
  7. 每个模型建一张接入清单，只写三件事：思考字段叫什么 / 是否必须回传 / 是否计入预算。
  8. 中途结论外化成显式状态（清单 / 摘要 / 工单打卡），不要指望模型记住沉在中段的临时结论（B C）。
  9. 提示里禁止出现任何特殊 token 字面量（见 §5 第一条）。
  10. 接入验收第一条：最小 tools 请求必须真拿到 tool_calls，别只看 HTTP 200。

4. harness × model 交互：公开数据里没有任何外壳跨模型通吃

opencode 是最好的活教材（B，逐文件源码取证）：system-prompt/ 下 kimi.txt 8.7 KB 完整重写、gpt.txt 2.6 KB、meta.txt 7.9 KB、trinity.txt 7.7 KB，而 anthropic.txt 只有 300 B（append 一条注释密度规则）——即「越需要行为矫正的模型，system 越长」。工具形状也逐模型：只有 gpt-*（非 oss、非 gpt-4）拿 patch，其余拿 edit+write。

另一条已验证的交互（B C）：Claude Code 的超长 system 会压制 GLM「是否思考」的自动判断，删宿主 prompt 能触发思考但驱动不了工具，最终靠提示词注入明确告知"需要思考"。

DeepSeek 侧的反向证据（B）：同一 DeepSeek V4 Flash 任务首包 token 为 opencode 8,084 / DSH 7,626 / pi 1,744，三者都能完成任务 → 长 system 对 DeepSeek 不致命，但会变成每次 prefill 的固定成本。

选型口径（B）：接国产四家想「开箱即用就聪明」→ 选有逐模型 prompt 的框架；要天花板 → 自己配 compat（DSH 路线：一套模型无关 prompt + compat 配置决定 system 放哪个角色、哪个字段限输出、budget 字段名、等级→wire 拼写）。换外壳后必须重测自己的模型。

6. 怎么自己验证（社区可复用的横评方法学）

社区整理、方法可直接复用（C）：

固定同一 system、同一工具权限、同一最大轮数，用自家 20 个真实任务，跑两轮以上，记录四项：一次通过率、人工返工分钟、总 token、失败类型。

补充三条：

  • 长上下文评估要把同一证据随机放在不同位置、配不同干扰长度；并区分标称与有效上下文（C，面经含标准答案口径）。
  • 「哪家对 system 最严格」目前没有直接对照实验，只有 IFBench 类间接证据（见 §7.1）——别信任何「X 家 system 服从率 Y%」的精确数字。
  • 换模型后做规则删除实验（OpenAI 官方方法："one group at a time, then rerun the same evals"）：这是唯一能把「这条规则还有必要吗」问出答案的动作（A）。

7. 证据边界（什么不能当结论用）

7.1 「谁指令遵循最强」只有间接证据

  • MiniMax 领先：IFBench 独立评测 MiniMax-M3 = 82.9%（并列全球第 2，B）；厂商自报 M2.5/M2.1 = 70.0，高于 Claude Opus 4.6 的 53.0（A 但厂商自报）。
  • Kimi 偏弱：国内第三方通用测评中 Kimi-K2.5-Thinking「精确指令遵循」仅 24.45（B，正文未取到，仅检索摘要）。
  • DeepSeek / GLM 缺同口径公开分数。
  • 交叉含义：Kimi 长文读得准，但精确指令遵循偏弱——「读得长」与「守得住格式」必须分开选型（A B）。

7.2 榜单列名歧义（已踩）

DataLearner 带 ?benchmark=IFEval 与 ?benchmark=τ²-Bench 返回首列数值完全一致，实际表头是 HLE / ARC-AGI-2 / FrontierMath / SWE-bench / τ²-Bench，没有 IFEval 列 → 本轮未采用其中任何"IFEval 数字"。

7.3 「官方能力」与「官方产品行为」不可混述

GLM 是否支持 system role 存在矛盾记录（官方文档支持 vs 教程称需并入 user）。真相是两件事：文档支持 system role（A）；GLM 自家产品与 API 不注入 system（A）。

7.4 「关思考后格式更容易崩」缺跨厂商同题实验

官方只给机制事实（参数被忽略 / 强制思考 / 思考档不能靠采样参数救）。已核到的一手崩法只有两种：reasoning 吃满预算导致 content 空（多例）；长宿主 prompt 抑制 GLM 思考判断（1 例动手验证）。

7.4b 托管平台条款 ≠ 厂商规则（本轮抓到并更正的一例）

「不建议同时开启 thinking.type=enabled 与 response_format.type=json_object」这句话在横评阶段被记成 MiniMax 官方冲突条款，逐字复核后发现它出自腾讯云 MaaS 自家指南，且同一句模板文案同时贴在 MiniMax 与 DeepSeek 两份调用指南上（B）。→ 教训：参数兼容性条款必须先确认文档归属方（厂商 API 参考 / 兼容层 / 托管网关），走哪家通道就按哪家的文档；把平台条款当厂商规则会误导跨家迁移。同类已知项：「GLM 不支持 system role 需并入 user」也是教程层与官方文档矛盾的记录（§7.3）。

7.5 内容农场的精确百分比一律抛弃

反复出现但无可复核原始数据：「system 超 120 字后服从率降 40%」「system 最佳 80–150 字」「省 18–34 token」「带 system 0% / 无 system 23% JSON 错」「GLM-4.7 英文低 0.15 CodeBLEU」「成功率 94.9%」「47% 识别率、83% 截断」。 → 只采纳与官方文档同向的定性建议（如 m.php.cn 群三条定性可取：system 只写身份与边界别写任务描述、动词短句优于礼貌修饰、tool_call_id 逐字符一致），数值全部抛弃或自行重测。

7.6 英文社区一手帖不可达（本机限制，已如实记录）

Reddit / Twitter / 小红书专用后端本机不可用（agent-reach CLI 未装、huggingface.co 不可达、curl 直连 000）；Reddit 侧只有二手转述，r/LocalLLaMA 关于四家开源权重 agent 经验的原帖未能直接核对；Hacker News 未找到关于这几家 prompt 模板的一手实操长帖。可复核的二手：note.com（2026-07-05）整理的 X / r/LocalLLaMA 趋势 + 自带 100 请求/模型实测——小模型工具调用原生成功率 0%，加 Tool Call Repair 层后 3 款 0%→100%；phi4-mini 残余 20% 是 arguments 内容本身错，故意不修（错参数被执行比不调用更危险）。该数据针对本地小模型而非四家旗舰，只可借其「修复层 / 回退层」机制思路。

7.7 泄漏 prompt 的使用边界

Kimi K3（≈36 KB）、MiniMax 海螺/M2.5、Claude Code 等属泄漏内容，不可照抄进产品，价值在结构范式（分块顺序、"When to Use / When NOT to Use"、select_tools 按需加载、<meta awareness> 区分主动指令与被动背景、引用格式 [^N^]）。可合法照抄的是各家公开文档骨架：Kimi use-kimi-api-to-complete-tool-calls / response_format、DeepSeek guides/thinking_mode（思考+工具交错完整可运行样例）、GLM 对话补全（tool_stream 双开关）、MiniMax 官方工具调用指南，以及 DeepSeek 官方提示词库（13 类含自定义人设，A）。 另注：opencode 的逐模型 system-prompt 文件是第三方开源、非厂商官方（B），是目前最现成的「给 Kimi/GLM 写 agent prompt 该怎么写」抄本来源。

7.8 思考开关拼写是快照而非契约

七种拼写同代并存、各家按代切换（§2.3），本矩阵写法是 2026-10-20 快照 + 待实测，不可当稳定契约引用。
