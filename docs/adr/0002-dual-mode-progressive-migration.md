# ADR 0002：现有技能双模式渐进迁移

- 日期：2026-08-12
- 状态：已接受

## 上下文

`base/skills/` 下现有 31 个技能均为普通 `SKILL.md`，无 `SKILL.src.md`、无 `x-vendors` 段，且现状 7 家平台全部是原样复制安装（含 CodeArts，从未执行过派生改写）。引入一行命令（ADR 0001）后必须决定对这些存量技能的行为。

备选方案：

1. **双模式渐进迁移**（本决策）：命令检测——有 `SKILL.src.md` 走派生安装，没有则原样复制安装（现状行为）。
2. 一次性批量迁移：脚本将 31 个技能全部转为 src 形态后统一派生。架构最纯，但 CodeArts 英文块与 5 行 description 需一次补齐，质量风险集中爆发。
3. 只支持 src：老技能继续由 PowerShell 安装.md 服务至人工迁移完。职责清晰，但两套脚本并存期最长，易遗忘迁移。

## 决策

采用方案 1。`SKILL.src.md` 的存在与否即派生开关，无需注册表或迁移截止日。

## 后果

- 老技能零回归：未迁移的技能在 7 家平台上的安装内容与现状逐字节一致。
- 新技能从创建起即享受 init → derive → install 全流程。
- 迁移节奏由使用驱动（改哪个迁哪个），无强制 deadline；代价是仓库长期处于混合形态，`SKILL.md` 与 `SKILL.src.md` 并存。
- 派生技能的 CodeArts 安装内容会与原样复制时代不同（name 前缀、5 行 description）——属预期变更，逐个迁移时逐个验证。
