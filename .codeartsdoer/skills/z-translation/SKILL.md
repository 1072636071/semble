# 翻译技能

## 核心原则

1. **信达雅**：准确传达原文含义，表达流畅自然，符合目标语言习惯
2. **术语一致**：技术术语首次出现时附原文，后续使用统一译法
3. **格式保留**：翻译后保持原文的 Markdown、代码块、链接等格式不变
4. **语境感知**：根据上下文选择最合适的译法，避免机械直译

## 翻译流程

### 基本流程

1. 识别源语言和目标语言（未指定时默认中→英或英→中）
2. 分析文本类型（技术文档/代码注释/普通文本/Markdown）
3. 加载术语表（见 [references/terminology.md](references/terminology.md)）
4. 执行翻译，保持格式和结构
5. 校验术语一致性

### 长文档处理

当文档超过 2000 字时：

1. 按语义段落（章节/小节）分段翻译
2. 每段翻译时保留前后文关键信息作为上下文
3. 术语在首段首次出现时标注原文，后续段落沿用统一译法
4. 分段翻译完成后检查全文术语一致性

### 混合语言处理

当源文本中英混杂时：

1. 识别哪些英文是专有名词/术语（保留原文），哪些是可翻译内容
2. 已在术语表中标注"不翻译"的术语保持原文
3. 中文语境中的英文短句翻译为目标语言
4. 保持中英文之间的空格规范

### 歧义处理

遇到一词多义或歧义时：

1. 根据上下文判断最可能的含义
2. 若仍无法确定，在译文中用 `（原文：xxx）` 标注
3. 技术术语优先参考术语表，术语表未收录时选择最通用译法

## 翻译规则

### 通用规则

- 专有名词、产品名、品牌名保持原文不翻译
- 代码变量名、函数名、命令行参数保持原文
- URL、文件路径保持原文
- 中英文之间加空格（中文排版规范）
- 标点符号跟随目标语言规范（中文用全角，英文用半角）
- 数字与中文之间加空格（如"版本 3.0"）

### 技术文档规则

- 技术术语首次出现格式：`中文译名（English Term）`
- 代码块内容不翻译，仅翻译代码注释
- 表格内容翻译时保持对齐
- YAML/JSON frontmatter 中的键名不翻译，值按需翻译
- 命令行示例不翻译，但说明文字翻译

### Markdown 规则

- 标题层级保持一致
- 链接地址不变，链接文本翻译
- 图片 alt 文本翻译
- callout/admonition 类型关键词不翻译（如 note、warning、tip）
- frontmatter 键名不翻译
- 列表缩进层级保持不变
- 表格分隔符对齐保持不变

### 代码注释规则

- 行内注释翻译时保持缩进
- 块注释保持注释风格（`//`、`/* */`、`#`、`"""`）
- TODO/FIXME/HACK 等标记保持原文
- 注释中的代码片段不翻译
- JSDoc/docstring 中的类型标注不翻译，描述部分翻译

### 文件翻译规则

当用户要求翻译整个文件时：

1. 先用 Read 工具读取源文件
2. 执行翻译
3. 若用户要求写入新文件，使用 Write 工具写入目标路径
4. 若用户要求覆盖原文件，确认后使用 Write 工具写入
5. 文件编码保持 UTF-8

## 输出规范

- 翻译结果直接输出，无需额外说明
- 如遇歧义，在译文中用 `（原文：xxx）` 标注
- 长文档分段翻译时，每段之间保持逻辑连贯
- 文件翻译时输出完整内容，不省略任何部分
