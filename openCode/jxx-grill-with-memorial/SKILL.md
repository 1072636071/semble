# Grill with Memorial

通过 grill 打磨计划，全过程持久化到 memorial 目录。解决 grill-with-docs 的假设误判（不可回溯）和会话中断（决策丢失）。

## Guidelines

- 文档先行。grill 期间只做追问和文档操作，禁止修改代码。
- 即时落盘。每轮追问立即追加到 context.md。不攒。
- grill 未结 = 不动手。用户说"可以了""开始实施""够了"后跑 checklist，全绿才算结束。
- 续接 = 重验。会话中断后续接，之前内容只是参考。旧决策需用户重新确认，不默认接受。
- 每个决策问题给出 2-4 个方案，每个方案列出优点和缺点，并标注推荐方案及理由。一次只问一个问题。
- 事实（可通过代码库查到）自己去查；决策交给用户。
- 记录：每轮问答即时追加到追问记录（带时间戳）；决策确定即时写入决策汇总；新浮现的待澄清即时列出。
- ADR：决策同时满足难以逆转、未来读者会惊讶、有真正替代方案被否决三条才创建到 `adr/`。
- 调查委派：创建 `sub-task/NNN.md` 写入任务描述，委派调研 subagent，完成后读取结果继续 grill。

## memorial 目录

```
docs/memorial/NNN-slug/
  context.md       — 诉求 · 追问记录 · 决策汇总 · 待澄清
  adr/
  sub-task/
```

`NNN` 扫描已有 memorial 取最大 +1。`slug` 从诉求提取 kebab-case。

## 初始化

- 新建：确定 NNN + slug，创建完整目录结构，写入 `context.md`（状态「进行中」，诉求段保留用户原话，其余三段置空），汇报创建结果。
- 续接：读取 context.md 作为参考材料（不是结论），从「诉求」段重新开始 grill，逐一重新质疑每个已有决策，汇报参考了 N 项旧决策将从头重新验证。

## 收尾 checklist

| # | 检查项 | 通过条件 |
|---|--------|---------|
| C1 | 诉求回应 | 每个诉求点有对应决策或澄清 |
| C2 | 决策完备 | 无"待定""暂缓""未决"条目 |
| C3 | 待澄清清零 | 段落为空 |
| C4 | 调查闭环 | 所有工单状态「已完成」 |
| C5 | ADR 齐全 | 满足三条件的决策均有 ADR |

全绿后进入回写确认：memorial 是独立工作区，不自动污染项目全局文档。逐一询问是否回写 `CONTEXT.md` 和同步 ADR 到项目全局。用户确认后执行回写；拒绝则保留在 memorial 内部。全部确认后标记「已完成」，汇报追问/决策/ADR/调查数量，建议归档。未全绿则列出缺口继续追问。

归档：移动 `NNN-slug/` 到 `archived/NNN-slug/`。可选：内置 checklist 通过后仍不放心，可手动调 `jxx-plan-review` 做独立语义审查。

## 反模式

- context.md 当 spec 写 — 它是追问与决策记录，不是功能规格。
- 假设不记录 — 每个推断写入追问记录，让用户确认或纠正。
