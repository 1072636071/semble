# Changelog

## 4.2.0 — 2026-07-27

验收到命令化 + 每轮必读块 + 宿主常驻规则 + 独立启动（C+D+E+F）：

- [C] 验收命令化：阶段 2/3 验证改为跑 Acceptance 绑定的验证命令，EVIDENCE.md 表格加"验证命令"列
- [C] 前提检查增加无绑定验收的扫描：发现旧契约缺 `（验证：...）` 时警告并建议补齐
- [C] 阶段 1 拆解要求每切片显式标注关联的 Acceptance 编号——关联不再凭空出现
- [E] PROGRESS.md 模板顶部增加"每轮必读"必读块（轮数/切片/本轮必做/禁止凭记忆续跑），每轮循环首步改为强制重读该块
- [D] 新增"宿主常驻规则（推荐）"小节：可复制进 AGENTS.md 的提醒式规则，无关任务只提醒一次不劫持
- [F] 新增"独立启动"小节：execute 不依赖 mode 路由，可直接被用户或脚本/CI 调用
- 护栏新增"状态在场""可执行验证绑定"两条，反模式由 5 条扩展为 9 条（新增"凭记忆续跑""无命令验收""忽略必读块""跳过验证命令"，移除被"凭记忆续跑"覆盖的旧"无进度记录"）

## 4.1.0 — 2026-07-19

前提检查与交付格式加固：

- 前提检查对齐契约否决门：Constraints / Pause Conditions 不再"可选但推荐"，缺失时显式警告、建议回 jxx-goal-contract 补齐，用户确认后才可继续并记录到循环日志
- 新增交付汇报格式：给用户的交付消息统一模板（验收通过率、证据位置、跳过切片、触发的暂停条件、契约改动、产物位置）

## 4.0.0 — 2026-07-12

多目标隔离与断点恢复增强。新增：

- 目标存储从项目根目录迁移到 `.goals/{name}/` 目录
- 多目标按名称隔离，互不干扰
- 目标定位逻辑（用户指定 / 索引查找 / 候选列表）
- 断点恢复：读取 PROGRESS.md 从断点继续
- 交付证据写入 `.goals/{name}/EVIDENCE.md`
- 更新 `_index.md` 状态追踪
- 进度追踪格式增强（含验收进度表）

## 3.0.0 — 2026-07-09

从 jxx-goal-mode v2 拆分而来。独立负责执行循环：

- 纵向切片拆解
- 执行循环（选→执行→验证→记录→判停）
- 进度追踪（PROGRESS.md）
- 错误恢复（重试→换路→降级→跳过→熔断）
- 自检与交付（独立来源证据）
- Pause Conditions 检查
