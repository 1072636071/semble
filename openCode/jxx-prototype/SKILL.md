# Prototype

Prototype 是回答问题的可丢弃代码。问题决定形态，选错会浪费整个 prototype。

## 选择分支

识别正在回答哪个问题——来自用户提示、周围代码，或直接询问用户：

- **"这个逻辑/状态模型感觉对吗？"** → [LOGIC.md](LOGIC.md)。构建单文件 HTML 交互 demo——状态面板加自由按钮——用户在浏览器里打开、按按钮、观察状态模型在压力下如何表现。
- **"这应该长什么样？"** → [UI.md](UI.md)。在单个路由上生成多个截然不同的 UI 变体，通过 URL 查询参数和浮动底栏切换。

若问题模糊且联系不到用户，默认选择更匹配周围代码的分支（后端模块 → 逻辑；页面或组件 → UI），并在 prototype 顶部声明假设。

## Guidelines

- 从一开始就是一次性的，并明确标记。放在实际使用位置附近（紧挨它为之做 prototype 的模块或页面），命名让随意浏览的读者看出这是 prototype，不是生产代码。遵循项目已有路由约定，不要发明新的顶层结构。
- 一条命令即可运行——或更省事。使用项目现有任务运行器（`pnpm <name>`、`python <path>`、`bun <path>`），或自包含 HTML 文件（零安装、双击即开）。
- 默认不持久化。状态存在于内存中。若问题明确涉及数据库，使用临时数据库或带明显 "PROTOTYPE — wipe me" 名称的本地文件。
- 跳过打磨。不写测试，只做让 prototype 能跑起来的最基本错误处理，不做抽象。目的是快速学到东西然后捕获它。
- 展示状态。每次操作（逻辑）或每次变体切换（UI）后，打印或渲染完整的相关状态。
- 完成后捕获它。提交到 `prototype/<name>` 分支——工作、`NOTES.md`、交接上下文。不要 merge，不要让它留在工作树上腐烂。

## 完成后：捕获

Prototype 回答完问题后，捕获它：

- 提交到 `prototype/<name>` 分支——工作、`NOTES.md`、交接上下文。文件可超出 `.gitignore` 范围；prototype 分支不是 main，就是干这个的。
- 写 `NOTES.md`——问题是什么、答案是什么、关键代码位置的指针、为什么它重要。答案连同证据一起保留。
- 在原本的工作对话里链接到该分支。分支成为主要来源（primary source）；之后任何接手的人都从那里读，而不是从摘要。
- 推送分支。在远端可见，就能被未来的会话找到——包括未来其他 harness 里想知道"这个试过吗"的 agent。

分支持久存在——它是文档，不是交付物。prototype 分支永不 merge 进 main：在需要时被重新打开——当决策被重新讨论、底层假设改变、或新问题问出同一个答案时——通过查看分支本身，而非凭记忆重建。
