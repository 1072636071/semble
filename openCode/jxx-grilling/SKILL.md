# Grilling

对这个计划的每个方面穷追不舍地盘问，直到达成共同理解。逐一走遍设计树的每个分支，逐个解决决策之间的依赖关系。

## Guidelines

- 按轮工作。每一轮：找到决策树的前沿——当前未解决决策中能独立回答的那个极小集合——针对该集合中的每个决策提问，所有问题放在同一条消息里编号列出。每个问题附上推荐的答案。给出答复后，计算新的前沿并继续下一轮。一次问遍整个设计树会让人无所适从——只问当前这一轮。
- 事实查找与决策分开。如果某个事实可以通过探索代码库查到，在提问前自己去查——需要时派一个后台 agent 在事实收集的同时推进本轮提问。但决策是用户的：前沿中的每个决策都交给用户，等待回答。
- 问题格式：`❓ **Q1** - **简短标题**：用一段话说清决策是什么，以及它为什么现在重要。` `➡️ **推荐答案**：你的推荐及一句理由。`
- 若答复引出了没想到的方向，先更新理解中的计划，再计算下一个前沿。
- 在用户确认已达成共同理解之前，不要执行该计划。
