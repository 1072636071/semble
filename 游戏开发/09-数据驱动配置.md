# 数据驱动配置（godot-data-driven-config）

> 将硬编码的 `const` / 魔法数字提取为 Resource 配置表，设计师通过 .tres 或 Inspector 调参。

---

## 规范目录布局

```
res://data/
├── specs/                       # JSON specs，唯一真相源（git 管理）
│   ├── weapon.spec.json
│   └── enemy.spec.json
├── resources/
│   ├── <name>_data.gd           # class_name <Name>Data extends Resource
│   └── data_manager.gd          # Autoload（自动生成）
├── <name>s/                     # 复数目录，每个 .tres 一个条目
│   └── default_<name>.tres
tools/
├── validate_data.gd             # Godot 端 CLI 验证器（自动生成）
└── validate_data.sh             # bash 包装器
```

---

## 工作流程

### Step 1: 发现并提议

1. 读取目标 .gd 文件，收集硬编码常量和字面量
2. 问用户哪个类别（weapon/player/enemy/level/skill/item）
3. 输出字段映射表（源常量 → 新字段 → 范围），等确认

### Step 2: 编写 spec JSON

```json
{
  "name": "weapon",
  "default_id": "default_pistol",
  "fields": [
    { "key": "id", "type": "StringName", "default": "&\"\"", "group": "Identity" },
    { "key": "damage", "type": "int", "default": 10, "range": [0, 9999, 1] },
    { "key": "fire_rate", "type": "float", "default": 0.5, "range": [0.1, 10.0, 0.1] },
    { "key": "range", "type": "float", "default": 100.0, "range": [10, 1000, 10] }
  ],
  "validators": ["damage >= 0", "fire_rate > 0"]
}
```

### Step 3: 运行 scaffold.py

```bash
python3 scaffold.py --project-root <abs path> --spec <spec>.spec.json
```

脚本自动：
- 复制 spec 到 `res://data/specs/`
- 生成 `<name>_data.gd`（首次；`--force-class` 覆盖）
- 生成 `default_<name>.tres`（首次；`--force-tres` 覆盖）
- **重建** `data_manager.gd`（基于所有 spec 文件）
- **重建** `tools/validate_data.gd`
- 写入 `tools/validate_data.sh`
- 幂等地修补 `project.godot` 的 `[autoload]`

### Step 4: 迁移消费者

对每个有硬编码值的 .gd 文件：

```gdscript
# 添加导出变量
@export var weapon_data: WeaponData

# _ready() 中提供 fallback
func _ready() -> void:
    if weapon_data == null:
        weapon_data = DataManager.get_weapon()

# 替换字面量
# JUMP_SPEED → weapon_data.jump_speed
```

保持纯技术常量（碰撞掩码、着色器路径等）不变。

### Step 5: 验证

```bash
bash tools/validate_data.sh
# exit 0 = OK
# exit 1 = 验证失败
# exit 2 = 环境问题
```

### Step 6: 文档

更新 README 或 PROJECT_OVERVIEW：字段映射表 + 设计师工作流 + 验证命令。

## 硬性规则

- 每个类别一个 Resource 类，不做上帝类
- 数值字段必须有 `@export_range`
- 每个 `<Name>Data` 必须有 `id: StringName` 字段
- `DataManager` 永远是名为 `DataManager` 的 Autoload
- `data_manager.gd` 的 getter 返回 `Resource`（非具体类型），调用方 `as WeaponData` 转换
- 禁止运行时修改 Resource（共享引用），需要修改时 `var copy = data.duplicate()`
- 禁止手改 `# region *_AUTOGEN` 代码块

---

## 反模式

| ❌ 避免 | ✅ 正确 |
|---------|--------|
| 运行时加载 CSV/JSON/YAML | 用 Godot 原生 .tres（文本、类型安全、Inspector 可编辑） |
| 全塞一个上帝资源 | 每个类别一个 Resource |
| 脚本和 .tres 各自硬编码不同默认值 | .tres 为主，脚本默认值仅作 fallback |
| 用 FileAccess / JSON.parse 读 .tres | 用 load() / preload() |
