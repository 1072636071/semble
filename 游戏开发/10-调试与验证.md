# 调试与验证（godot-debug + godot-headless-verify）

---

## 在线调试（godot-debug）

> 仅当用户明确报告**已出错**时才激活。使用三个 MCP 单元查询工具。

### 三工具调用流程

```
1. get_debug_errors()           ← 每次激活第一步，全项目扫描
2. get_script_errors(...)       ← 对每个出错脚本逐一调用
3. get_editor_output(...)       ← 仅在编译无问题但运行时崩溃时调用
```

### get_debug_errors

```
get_debug_errors({
  include_log_errors?: boolean,   // 默认 true
  directory?:          string,    // 默认 "res://"
  exclude_addons?:     boolean,   // 默认 true
  project?:            string
})
```

### get_script_errors

```
get_script_errors({
  script_path:        string,     // 必填，如 "res://scripts/player.gd"
  include_warnings?:  boolean,    // 默认 true
  project?:           string
})
```

返回：行号、列号、代码片段、上下文、修复建议、完整脚本内容。

### get_editor_output

```
get_editor_output({
  lines?:   number,               // 1-1000，默认 100
  filter?:  "all" | "errors" | "warnings",
  project?: string
})
```

### 行为约束

- 只做调用 + 美化展示 + 引导，不改代码
- 代码修复交回 godot-dev 场景3
- 禁止自动 run_project → 自动写 debug 循环

## 无头验证（godot-headless-verify）

> 可复制的 CLI 配方集合，无需打开编辑器。

### 配方1: 安全清理缓存

**场景**: 编辑器显示 `Cannot open file 'res://...'` 但文件确实存在。

```bash
cd <project-root>

# 安全重置（保留着色器缓存和编辑器布局）
rm -rf .godot/imported \
       .godot/uid_cache.bin \
       .godot/global_script_class_cache.cfg \
       .godot/scene_groups_cache.cfg \
       .godot/editor/filesystem_cache* \
       .godot/editor/filesystem_update_*

# 重建缓存
godot --headless --import --path .
```

**保留**（不要删）:
- `.godot/shader_cache/` — 已编译着色器
- `.godot/editor/*-folding-*.cfg` — 文件折叠状态
- `.godot/editor/editor_layout.cfg` — 窗口布局

### 配方2: 场景加载烟雾测试

```bash
cat > /tmp/smoke.gd <<'EOF'
extends SceneTree

const SCENES := [
    "res://scenes/boot/main.tscn",
    "res://scenes/levels/arena/arena.tscn",
]

func _initialize() -> void:
    var failed := 0
    for s in SCENES:
        var ps := load(s) as PackedScene
        if ps == null:
            push_error("FAIL load: %s" % s); failed += 1; continue
        var inst := ps.instantiate()
        if inst == null:
            push_error("FAIL instantiate: %s" % s); failed += 1; continue
        print("OK %s (children=%d)" % [s, inst.get_child_count()])
        inst.queue_free()
    quit(0 if failed == 0 else 1)
EOF

godot --headless --path . --script /tmp/smoke.gd 2>&1 | grep -E 'ERROR|OK '
rm -f /tmp/smoke.gd
```

### 配方3: 脚本解析检查

```bash
godot --headless --quit --path . 2>&1 | grep -iE 'SCRIPT ERROR|Parse Error' || echo "all scripts parse OK"
```

### CI 一体化脚本

```bash
#!/usr/bin/env bash
set -euo pipefail
GODOT="${GODOT:-/path/to/godot}"
cd "$(dirname "$0")/.."

# 1. 结构检查
bash tools/check_asset_structure.sh

# 2. 数据表验证
[ -f tools/validate_data.sh ] && bash tools/validate_data.sh

# 3. 场景烟雾测试
"$GODOT" --headless --path . --script tools/smoke.gd

# 4. 无残留脚本错误
"$GODOT" --headless --quit --path . 2>&1 \
    | grep -iE 'SCRIPT ERROR|Parse Error' \
    && { echo "script errors detected"; exit 1; } \
    || echo "clean"
```

## 常见可忽略警告

| 消息 | 来源 | 处理 |
|------|------|------|
| `ObjectDB instances leaked at exit` | Godot 4.6 清理顺序 | 无头一次性脚本忽略 |
| `WARNING: [fbx] ...` | FBX SDK 噪音 | 除非提及你的文件否则忽略 |
| `Physics interpolation ... benign` | 物理插值 | 记录技术债，运行时忽略 |
| 首次运行各场景报 `ERROR: failed loading resource` | 缓存还在重建 | `--import` 完成后重跑 |

## 反模式

- ❌ 删除整个 `.godot/`：会清除 `shader_cache/`，下次打开编辑器需 10+ 分钟重建着色器
- ❌ 编辑器打开时运行维护脚本：编辑器会竞态覆盖你的更改
- ❌ 假设 `--quit` 会等待文件系统扫描完成：用 `--import` 获取完整重扫描
- ❌ 提交的脚本里硬编码 `/Applications/Godot.app/...`：用 `${GODOT:-<default>}` 模式
