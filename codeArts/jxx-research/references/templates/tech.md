# tech — 技术调研报告

用于技术选型、工具对比、API 调研、方案评估。

## 标准节

| 节 | 必填 | 内容 |
| -- | ---- | ---- |
| **摘要** | 是 | 3-5 句概述：调研什么问题、主要发现、推荐结论 |
| **背景与问题** | 是 | 为什么需要这次调研？当前面临什么技术决策？ |
| **调研范围** | 否 | 明确边界：包含什么、不包含什么 |
| **候选方案** | 是 | 每个候选方案独立一节：概述、优势、劣势、适用场景 |
| **方案对比** | 是 | 对比表格：维度（性能/生态/学习曲线/维护成本）到各方案评分 |
| **关键发现** | 是 | 调研过程中发现的重要事实、意外发现、风险点 |
| **建议** | 是 | 推荐哪个方案？为什么？迁移路径或引入策略 |
| **参考来源** | 是 | 所有引用的文档、文章、代码仓库链接 |

## 示例场景

- "调研 React 状态管理库，对比 Zustand、Jotai、Redux"
- "评估是否应该从 REST 迁移到 GraphQL"
- "调研 Stripe 和 PayPal 支付集成的差异"
