# 异常处理

契约固化与目标管理中的异常场景处理表。仅当出现对应异常时加载。

| 异常场景 | 处理方式 |
| --- | --- |
| 目标名称冲突（新建时同名） | 提示用户选择：继续该目标 / 重复该目标 / 使用新名称 |
| GOAL.md 不可解析或损坏 | 提示用户，提供重建选项：从 PROGRESS.md 恢复 / 重新固化契约 |
| `.goals/` 目录不存在 | 自动创建 `.goals/` 目录和 `_index.md` |
| PROGRESS.md 缺失 | 从 GOAL.md 按模板重新初始化（含每轮必读块；轮数=0，所有验收=待验证；验证命令列从 GOAL.md 的 Acceptance 逐条提取） |
| `_index.md` 缺失 | 扫描 `.goals/` 下所有子目录，重建 `_index.md` |
| 契约固化被用户放弃（目录已创建） | 询问是否保留 `.goals/{name}/` 目录；若不保留则删除空目录并从 `_index.md` 移除条目 |
| 否决门检查结果 | 自检和独立检查的否决门结果记录在 PROGRESS.md 的"固化日志"区域 |
| GOAL.md 写入失败（磁盘/权限） | 回滚：删除已创建的 `.goals/{name}/` 目录，提示用户检查磁盘/权限后重试 |
| GOAL.md 已写入但 PROGRESS.md 写入失败 | 回滚：删除 `.goals/{name}/` 目录，从 `_index.md` 移除条目，提示用户重试 |
| GOAL.md 和 PROGRESS.md 已写入但 `_index.md` 更新失败 | 修复：重新执行 `_index.md` 重建逻辑（与"`_index.md` 缺失"处理一致） |

**写入失败回滚原则**：写入序列（GOAL.md → PROGRESS.md → `_index.md`）中途失败时，清理已写入部分回到写入前状态，避免不一致状态残留。
