# 逻辑 Prototype

一个单文件交互式 HTML demo，用户可以在浏览器里打开——没有构建步骤、没有依赖、没有终端。当问题是关于**业务逻辑、状态转换或数据形态**时使用——那种在纸上看起来合理，但只有推入真实用例才会感觉不对的东西。

## 何时使用此形状

- "我不确定这个状态机是否处理了 X 然后 Y 的边界情况。"
- "这个数据模型真的能让我表示……的情况吗？"
- "我想在写 API 之前先摸索它应该长什么样。"
- 任何用户想要**按按钮看状态变化**的场景。

如果问题是"这应该长什么样"——走错分支了。使用 [UI.md](UI.md)。

## 流程

### 1. 陈述问题

在写代码之前，写下你要 prototype 化什么状态模型和什么问题。一段话，放在 HTML 文件顶部——demo 本身可见，而不只是注释。回答了错误问题的逻辑 prototype 是纯粹的浪费——让问题明确，以便之后检查，无论用户现在是否在观看还是 AFK 后回来。

### 2. 将逻辑隔离在可移植模块中

实际逻辑——回答问题的那部分——放在文件内一个清晰的 `<script>` 块中，用纯净的接口包裹，之后可以被提取进真实代码库。围绕它的 UI 是一次性的；逻辑模块不是。

正确的形状取决于问题：

- **纯 reducer**——`(state, action) => state`。适合动作是离散事件且状态是单一值的情况。
- **状态机**——显式的状态和转换。适合"现在哪些动作是合法的"也是问题一部分的情况。
- **纯数据类型上的一小组纯函数**。适合没有隐含当前状态——只有转换的情况。
- **具有清晰方法表面的类或模块**，当逻辑确实拥有持续的内部状态时。

选择最适合所问问题的形状，*不是*最容易连接到 DOM 的。保持纯净：无 DOM 引用、无 `alert`、无用于控制流的 `console.log`。UI 调用它；没有反向数据流。

这就是让 prototype 在其自身生命周期之外有用的原因。当问题被回答后，验证过的 reducer/机器/函数集可以被提取到真实模块中——demo 壳被删除。

### 3. 构建 demo

单个 `.html` 文件，两个区域：

1. **状态面板**——当前状态，渲染为格式化 JSON 或每行一个字段的列表。每次操作后重新渲染——整个面板替换，不是追加日志。让用户能逐字段地 diff 上一次点击和这一次点击之间发生了什么。
2. **自由按钮**——每个动作一个按钮（"添加用户"、"推进时钟"、"取消订单"）。按钮就是状态机提供的动作——不多不少。非法动作禁用或隐藏，让用户看到当前什么是可能的。

用户驱动。每次点击调用逻辑模块并重新渲染状态面板。没有路由，没有页面——一屏一态。

### 4. 构建脚本化场景（可选）

自由按钮回答"我可以探索吗"。当问题其实是"X 然后 Y 然后 Z 会发生什么"时，在自由按钮旁边加一个**场景运行器**：一小组命名的脚本化序列，每个驱动状态机经历一条预设路径，并突出最终状态。用户先跑场景看边界情况爆发，再用自由按钮围绕它探索。

场景只是动作数组——`['addUser', 'addUser', 'removeFirstUser']`——按序 dispatch，最终状态渲染在同一状态面板里。不要单独的框架。

### 5. 交付

把文件交给用户——拖拽进浏览器，双击，或在 harness 里用 `open <file>`。零安装、零命令、零构建步骤。有趣的时刻是当他们说"等等，这不应该可能"或"嗯，我以为 X 会不一样"——这些是*想法*中的 bug，而这正是全部意义。

### 6. 捕获

当 prototype 完成了它的使命，捕获它——见 [SKILL.md](SKILL.md) 的"完成后：捕获"。`NOTES.md` 落在 `prototype/<name>` 分支上，挨着 HTML 文件：问题、答案、关键代码位置的指针。HTML 文件本身就是证据——未来的会话可以打开分支，在浏览器里跑 demo，读 `NOTES.md`。

## 反模式

- **不要添加测试。** 需要测试的 prototype 不再是 prototype。
- **不要连接真实数据库。** 使用内存状态，除非问题专门关于持久化。
- **不要泛化。** 不要"万一以后要支持 X"。prototype 回答一个问题。
- **不要引入依赖。** 没有 npm、没有 CDN 导入、没有框架。vanilla HTML/CSS/JS 对这个形状绰绰有余。
- **不要将逻辑和 DOM 混在一起。** 如果 reducer/状态机引用了 `document`、事件或 `alert`，它就不再可移植了。保持 demo 作为纯模块上的薄壳。
- **不要做成终端应用。** 如果用户必须安装 runtime、克隆并运行命令才能探索逻辑，大多数人永远不会去做。浏览器人人皆有。
