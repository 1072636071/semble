# 目标模式

以结果为导向的自主执行循环。用户只负责设定**目标、验收标准、约束**，AI 自主拆解、执行、自检，直到验收全部通过才交付。

## 路由逻辑

收到用户请求后，按以下决策树分发：

```
用户请求
  │
  ├─ 小任务（步骤明确、一次性完成）→ 建议直接做，不套循环
  │
  ├─ 用户说"列出目标"或"有哪些目标" → 读取 .goals/_index.md 并展示
  │
  ├─ 用户说"继续 {name}" → 检查 .goals/{name}/ 状态
  │    ├─ 执行中/已暂停 → 判断审查保鲜度
  │    │    ├─ REVIEW.md 存在且审查距今 < 24h，PROGRESS.md 无契约改动记录 → 委托 /jxx-goal-execute（断点恢复）
  │    │    ├─ 审查距今 ≥ 24h 或有契约改动记录 → 快速复审查 D2 可行性 + D4 审计就绪性（约 30s），有 ⚠️ 无 ❌ 即可恢复，有 ❌ 则提示先回 contract 修正
  │    │    └─ REVIEW.md 不存在（旧目标从未审查）→ 委托 /jxx-plan-review 全量审查后再恢复
  │    ├─ 契约中 → 委托 /jxx-plan-review 审查 → 准奏后 /jxx-goal-execute（开始执行）
  │    ├─ 已完成/已失败 → 询问：重复 or 新建？
  │    └─ 不存在 → 提示先创建契约
  │
  ├─ 用户说"重复 {name}"或"重做 {name}" → 委托 /jxx-goal-contract（重复模式）
  │
  ├─ .goals/ 目录已有目标且用户给了新目标 → 询问：
  │    ├─ 新建新目标 → 委托 /jxx-goal-contract
  │    ├─ 追加到已有目标 → 委托 /jxx-goal-contract（追加模式）
  │    └─ 替换已有目标 → 委托 /jxx-goal-contract（重写）
  │
  └─ 无 .goals/ 或需要新建契约 → 委托 /jxx-goal-contract
       │
       ├─ 契约固化完成后 → 委托 /jxx-plan-review（语义审查）
       │    │
       │    ├─ 准奏 / 附条件准奏 → 委托 /jxx-goal-execute
       │    └─ 封驳 → 打回 /jxx-goal-contract（读取 REVIEW.md 修正后重新审查）
       │
       └─ 目标仍模糊 → 不启动循环，委托 /jxx-grill-me 追问收敛后重新走 contract
```

### 小任务判断

以下特征说明是小任务，直接执行即可，不必套用循环：

- 一句话翻译、简单改写、单文件改名
- 步骤明确、无路径不确定性
- 预计 1-2 轮即可完成
- 量化锚点：改动限于单文件、无需运行验证命令、无跨文件调用点同步——三条全中才算小任务，任一不中则不武断按小任务处理

对这类任务，说明"目标模式对此类任务只会增加开销"，建议直接执行。

### 列出目标

当用户说"列出目标""有哪些目标""目标列表"时：

1. 读取 `.goals/_index.md`
2. 展示所有目标及其状态
3. 询问用户要操作哪个目标

## 目标存储

目标存储结构（`.goals/{name}/` 目录、`_index.md` 索引、状态取值）的唯一权威定义在 `/jxx-goal-contract`，本技能只读取，不重复定义。

## 子技能

| 子技能               | 职责                                        | 何时调用               |
| -------------------- | ------------------------------------------- | ---------------------- |
| `/jxx-goal-contract` | 契约固化：新建/继续/重复/追加，生成 GOAL.md | 需要创建或修改契约时   |
| `/jxx-grill-me`      | grill 追问：逐维收敛模糊目标                 | contract 发现目标模糊时（由 contract 内部委托） |
| `/jxx-plan-review`   | 语义方案审查（门下省）：审可行性、覆盖、风险 | 契约固化后、执行前     |
| `/jxx-goal-execute`  | 自主执行循环：拆解→执行→验证→交付           | 语义审查准奏后         |

## 适用边界

**适合**——路径不确定、过程繁重的长任务：深度研究、长篇报告、批量修复代码、整理大量文献、撰写综述。

**不适合**——步骤明确的一次性小任务：翻译一句话、回答具体问题、单文件改名。

## 调用关系

- 契约固化：`/jxx-goal-contract`
- 目标收敛：`/jxx-grill-me`（由 contract 目标确认门内部委托）
- 语义审查：`/jxx-plan-review`
- 自主执行：`/jxx-goal-execute`
- 执行内部可委托：`/jxx-tdd`、`/jxx-implement`、`/jxx-research`
- 目标需先成规格文档：先 `/jxx-to-spec`
- 拆解纪律参考：`/jxx-to-issues`
- 工作流需 spec 化：`/jxx-loop-me`
