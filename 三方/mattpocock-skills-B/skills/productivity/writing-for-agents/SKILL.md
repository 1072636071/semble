任何 agent 消费的文档的编写参考——一个技能、一份 `AGENTS.md` / `CLAUDE.md`、一份通过指针到达的文档。打包方式不同；写作本身不变：同样的杠杆使每一份都可预测——agent 每次运行都走同样的*流程*，而不是产出同样的输出。

当你编写的文档是技能时，请阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 了解 frontmatter、调用方式选择和路由技能。

## 上下文指针

**上下文指针（context pointer）** 是保存在 agent 上下文中的一种引用，它点名某些上下文之外的材料，并编码到达它的条件。技能的 description 是一个；`AGENTS.md` 中指向某文档的一行是同一个东西。指针的*措辞*，而非其目标，决定 agent 何时到达该材料——以及有多可靠。一个措辞软弱的指针背后是一个必须有的目标，就是一个方差 bug：先磨锋利措辞，只有当磨锋失败时才内联该材料。

一个指针做两件事——说明材料是什么，并列出应触发到达它的**分支**（分支是文档处理的一个不同情况，因此不同的运行会走文档的不同路径）。一个常驻加载的指针的每个词都在每一次轮转中付出代价，所以它比正文更需要修剪：

- **前置引导词** —— 指针正是在这里完成它的触发工作。
- **每个分支一个触发器。** 只是给同一分支改名的同义词是一个分支被写了两次；合并它们，只保留真正不同的分支。
- **删掉正文已承载的身份信息。**

## 两种负载

你添加的每份文档和指针都会消耗两种预算之一：

- **上下文负载** —— 常驻加载的材料对 agent 窗口的成本：`AGENTS.md` 的一行、一个技能 description、任何每轮都坐在上下文中、无论是否触发都消耗 token 和注意力的东西。
- **认知负载** —— 对人类的成本：存在哪些文档，以及何时取用哪一份。人是索引。这不是一个需要最小化的成本——它是人类能动性的代价；把花费用在人的判断重要之处，在无关之处移除它。

只有通过指针才能到达的材料，以指针自身那一行为代价避开上下文负载；完全没有指针的材料则完全依靠认知负载。

## 信息层级

一份文档由两种内容类型构建——**步骤**（agent 执行的有序动作）和**参考**（按需查阅的定义、规则、事实）——它们可以自由混合：全是步骤（一份菜谱）、全是参考（一次审查的规则、本技能）、或两者兼有。核心决策是每个片段在**信息层级**上落在哪里——一个按 agent 需要该材料的紧迫程度排列的梯子：

1. **文件内步骤** —— 主层级：agent 按顺序做什么。
2. **文件内参考** —— 按需查阅。通常是一个合理扁平的同行集合（一次审查的每条规则在同一级）——这是合理安排，不是坏味道。
3. **披露参考** —— 推到独立文件中，通过上下文指针到达，仅在指针触发时加载。范围从同一文件夹中的同级文件，到可以存在于任何地方、任何文档都能指向的完全外部参考。

往下推得太少，顶层会臃肿；推得太多，你会隐藏 agent 真正需要的材料。这种张力就是全部决策。

**渐进式披露** 是沿梯子向下的动作——从主文件中移出、放到指针之后——让顶层保持清晰可读。它主要不是 token 优化：它是保护层级的方式。分支是最干净的披露测试：把所有分支都需要的内容内联，把只有某些分支会到达的内容放到指针之后。当一份文档有步骤时，本应披露的文件内参考会埋没它们，并使对步骤的关注变成掷硬币——这是方差杠杆，而不仅仅是可读性杠杆。

**同地放置** 是文件内对应的做法：梯子决定一个片段*落多深*，同地放置决定一旦落下后*旁边放什么*。把一个概念的定義、规则和注意事项放在同一标题下，而不是分散各处，这样阅读一部分就会把它的邻居带进来。检验标准：文档读起来应该像为 agent 写的文档——分组的内容读起来就是那样；分散的内容不是。（区别于重复：重复是在两处表达同一意思；分散是把一个意思碎片化成多处。）

**蔓延** 是这里的失败模式：一份文档实在太长，即使每一行都是活跃且唯一的。注意力在多余内容中稀释，每一行额外内容都需要保持相关性。解药是梯子：把参考披露到指针之后，并按分支或序列拆分，使每条路径只携带它需要的部分。

## 步骤与完成标准

每个步骤都以**完成标准**结束——告诉 agent 工作完成的条件。两个属性使它成为杠杆：

- **清晰度** —— agent 能区分完成与未完成吗？一个模糊的边界（"已达成理解"）会招致**过早完成**：在步骤真正完成之前就结束它，注意力滑向*完成了*。前方仍可见的步骤——**完成后的步骤**——提供拉力；标准的清晰度是阻力。按顺序防御：**先磨锋利边界**（局部且廉价）；只有边界不可约地模糊*并且*你观察到赶工，才通过拆分序列来隐藏后面的步骤——而隐藏只有跨越真实的上下文边界才有效（一次交接或一个子 agent 调度；一次内联调用会把后续步骤留在上下文中，清除不了任何东西）。
- **要求度** —— 它要求多少。"每个被修改的模型都有说明"强制了彻底的工作，而"生成一份变更列表"则没有。要求度驱动**苦工** —— agent 在工作内部做的挖掘，潜伏在措辞中而不是写成一个独立步骤——并且它不受步骤约束："每条规则都被应用"绑定一份扁平的参考正文，正如"每个步骤都完成"绑定一个序列——这就是为什么一份全参考的文档仍然携带穷尽性要求。

最强的标准既可检查又穷尽。

## 何时拆分

把一份文档拆成两份会消耗两种负载之一，所以只有在拆分值得时才拆：

- **按序列拆分** —— 拆分一串步骤，此时完成后的步骤会诱使 agent 赶工当前这一步。让它们不可见会推动对当前任务做更多苦工。注意反面：合并序列会让每一步的后续步骤暴露在后面的内容面前，招致过早完成。
- **按调用方式拆分** —— 技能专属：参见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词（leading word）** 是一个紧凑的概念，已经存在于模型的预训练中，agent 在运行文档时用它思考（*lesson*、*fog of war*、*tracer bullets*）。以 token 而非句子的形式重复，它会累积出一个分布式的定义，并以最少的 token 锚定一整个行为区域——通过招募模型已经持有的先验。自创词语如果定义清晰也能奏效，但一个编造的词语招募不到任何先验——你需要为定义付出预训练词免费提供的那些 token；先去找现成的词。

它锚定两次。在正文中，锚定*执行*：每次该词出现时，agent 都会采用相同的行为，而在扁平参考中它把注意力集中在一类要寻找的东西上。在指针中，锚定*调用*：当同一个词存在于你的提示、你的文档和你的代码库中时，agent 会把这种共享语言与该材料关联起来，更可靠地到达它。

寻找用引导词重构的机会。一个在三个地方写出来的三元组、一个花一个句子指向同一个想法的指针——每一段都在乞求被折叠成单个 token：

- "快、确定性、低开销" → *tight*（一个 *tight* 循环）。
- "一个你相信的循环" → *red* —— 一个模糊的门槛变成一个二进制的可观察状态（循环在此 bug 上变 *red*，或不变）。

你赢两次：更少的 token，以及一个更锋利的钩子让 agent 挂起它的思考。假设每份文档都携带了引导词可以退休的重述——去找它们。

**否定** 是紧挨着这个杠杆的失败模式：通过禁止来引导会把被禁行为拖进上下文，使它*更*可用，而不是更少。*别想大象*，那么大象就是全部存在；否定是一个弱势修饰语，被强烈激活的概念会压过它，所以禁令读起来半像是"去做这件事"的指令。提示**正面的**——陈述目标行为（"写单行注释"），这样被禁止的那个永远不会被说出。只有当禁令是一个你无法正面表述的硬护栏时，它才配得上存在；即使如此，也要把它与正面目标配对，让注意力落在要做什么上。

## 修剪

- 把每个含义放在**单一事实来源**中：一个权威位置，这样改变行为就是一处编辑。**重复** —— 同一含义在多处 —— 付出维护和 token 成本，并夸大一个含义在梯子上超过其真实排名的显要度。（引导词的意外反面：它故意重复一个 token，从不重复含义。）
- **环境** 也是事实来源——`package.json` 脚本、配置文件、目录布局、`--help` 输出——而复述它的文档是**缓存**：一次查询的副本，只有当查询昂贵时才配得上它的负载。缓存 agent 无法通过查看找到的东西：未写下的约定、选择背后的原因、没有配置会坦白的陷阱。把单文件、单命令的查询留给环境，那里它们不会过期。
- 逐行检查**相关性**：它是否仍然与文档所做的事情相关？一行内容通过从未与任务相关（纯粹的说明，或一个应被披露的分支）或随着它描述的行为或世界改变而过期，从而失去相关性。更短的文档更容易保持相关。没有修剪纪律，默认命运是**沉淀**：过时的层次堆积起来，因为添加感觉安全、删除感觉危险，直到你必须向下钻穿它们才能找到仍然活跃的东西。
- 逐句寻找**无效操作**：一条模型默认已经服从的指令，说等于白说，却付了负载。检验标准——与默认相比它是否改变行为？——是相对于模型的，而不是相对于读者的：两个对无效操作持不同意见的人，其实是不同意默认行为，并通过运行文档来裁决，而不是通过辩论。当一个句子不成立时，删除整个句子，而不是从中删词。该检验也给引导词打分：一个太弱、打不过默认的词（在 agent 已经差不多彻底时写*要彻底*）就是无效操作，解决办法是一个更强的词（*要锲而不舍*），而不是不同的技巧。
