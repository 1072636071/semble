# 技能机制

[`writing-for-agents`](SKILL.md) 的技能专属分支：当文档是技能时会发生什么变化——frontmatter、调用方式选择，以及路由技能。关于写作的其他一切，都是 `SKILL.md` 中的通用参考。

## 调用方式

两种选择，在两种负载之间权衡：

- **模型调用**的技能保留 `description`，因此 agent 可以自主触发它——其他技能也可以到达它。你仍然可以输入它的名字：模型调用总是*包含*用户到达；description 只会增加 agent 发现，绝不移除人的部分。description 是该技能的顶层上下文指针，被迫始终保持加载——以永久的上下文负载换取可发现性。一个内容全是参考的模型调用技能，也是共享参考的一个家：另一个技能可以调用它，所以几个技能需要的参考可以存在于一个地方。机制：省略 `disable-model-invocation`，并写一个面向模型的 description，携带触发分支（`SKILL.md` 中的指针编写规则完全适用）。
- **用户调用**的技能将 description 从 agent 的触达范围中剥离：只有人类输入它的名字才能调用它，没有其他技能可以。零上下文负载，但它消耗认知负载——你是必须记住它存在的索引。机制：设置 `disable-model-invocation: true`；`description` 变为面向人类的——一行摘要，去掉触发列表。

只有当 agent 必须自行到达该技能、或其他技能必须到达它时，才选择模型调用。如果它只靠手工触发，就做成用户调用，不付上下文负载。

两个用户调用技能都需要的共享参考，不能存在于任何一个之中——没有 description，两者都无法触发对方。把它推到技能系统之外的普通文件中：任何技能都可以指向的外部参考。

## 按调用方式拆分

拆分的调用方式切口（序列切口在 `SKILL.md` 中）：当你有一个应该自行触发它的独立引导词——一个你在提示中真正使用的触发词——或其他技能必须到达它时，拆分出一个模型调用技能。你为新常驻加载的 description 付出上下文负载，所以这种独立到达必须值得。

## 路由技能

当用户调用技能的数量超出你能记住的范围时，堆积的认知负载由**路由技能**治愈：一个用户调用的技能，点名其他技能以及何时取用每一个，这样人类只需要记住一个技能而不是许多个。它只能提示，绝不能触发它们：用户调用技能没有 description，所以除了人类，没有东西能到达它们。
