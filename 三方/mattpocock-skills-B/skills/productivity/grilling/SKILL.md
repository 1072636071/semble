---
name: grilling
description: 毫不留情地访谈用户关于一个计划、决策或想法。当用户想要压力测试他们的思考，或使用任何 'grill' 触发短语时使用。
---

毫不留情地访谈用户，直到达成共享理解。把它映射为一棵**设计树**：每个决策分支到挂在它下面的决策。

以**轮次**处理这棵树。**前沿**是每个前提已确定的决策——你现在*可以*问的问题，不用猜测你还没听到的答案。在一轮中问完整个前沿：给每个问题编号并给出你的推荐答案。然后等待用户的回答再进入下一轮。

每个问题应按如下格式：

```
❓ **Q1** - **<问题标题>**: <问题正文，可能多个段落，包括多个选项>

➡️ <你的推荐答案>
```

每轮用户的回答重塑这棵树——已确定的决策把前沿向外推，解除依赖它们的阻塞问题。重新计算前沿并问下一轮。一个回答依赖本轮中另一个仍开放的问题的问题，属于*后面*的一轮，而不是这一轮。

寻找_事实_是你的工作，绝不是用户的。当一个前沿问题需要来自环境的事实（文件系统、工具等）时，派遣一个子 agent 去找——不要问用户任何你可以自己查找的东西。不要阻塞在它上面：一个运行中的探索是一个未确定的前提，所以只有它下游的问题等待子 agent 报告——现在问前沿的其余部分。_决策_是用户的——把每个都放到他们面前并等待。

当前沿为空时会话完成：设计树的每个分支都被访问过，没有东西被默默假设。在用户确认你们达成共享理解之前，不要对结果采取行动。
