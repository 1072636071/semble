一个松散的想法到达了——对单个 agent 会话来说太大，而且被迷雾包裹：从这里到**目的地**的路还不可见。Wayfinding 是关于找到那条路，而不是冲向目的地。本技能把这条路绘制为仓库 issue 跟踪器上一张**共享地图**，然后处理它的**决策工单**——问题的解决是一个决策，而不是要执行的构建切片——一次一个，直到路线清晰。

目的地因努力而异，给目的地命名是绘图的第一行为——它塑造每一张工单。它可能是一份要交接并迭代的规格、一个在规划开始前要锁定的决策，或一个就地完成的变更，如数据结构迁移。地图与领域无关——工程工作、课程内容，任何符合形态的东西。

## 规划，而不是执行

Wayfinder 默认是**规划**：每张工单解决一个决策，地图在道路清晰时完成——在某人去做这件事之前，没有留下任何要决定的。直接去做工作的冲动通常是信号：你已经到达了地图的边缘，是时候交接了。一项努力可以在其**Notes** 中覆盖这一点——把执行本身带进地图——但除非那样，产出决策，而不是交付物。

## 用名字引用

每个地图和工单都是一个 issue，所以它有一个**名字**——它的标题。在人类读到的一切中——叙述、地图的 Decisions-so-far——用那个名字引用它，绝不用裸 id、编号或 slug。一墙的 `#42, #43, #44` 是难以阅读的；名字一眼就能读。id 和 URL 不会消失——一个名字包裹它的链接——但它们待在名字*内部*，绝不代替它。

## 地图

地图是 issue 跟踪器上的单个 issue，标记为 `wayfinder:map`——规范工件。它的工单是地图的子 issue。

地图是一个**索引**，不是仓库。它列出已做的决策并指向持有其细节的工单；一个决策恰好存在于一个地方——它的工单——所以地图从不复述它，只摘录并链接。

**地图、其子工单、阻塞和前沿查询实际存放在哪里取决于跟踪器。** issue 跟踪器应已提供给你——若未提供，运行 `/setup-matt-pocock-skills`。查阅跟踪器文档的"Wayfinding operations"一节，了解_本_仓库如何表达它们。如果没有提供跟踪器，默认为本地 markdown 跟踪器。

### 地图正文

整张地图的低分辨率视图，每个会话加载一次。打开的工单**不**列出——它们是打开的子 issue，通过查询找到。

```markdown
## Destination

<到达这张地图尽头是什么样子——这项努力正在找到路的规格、决策或变更。一两行；每个会话在选择工单之前都以此为方向。>

## Notes

<领域；每个会话都应查阅的技能；这项努力的常设偏好>

## Decisions so far

<!-- 索引——每个已关闭工单一行：足以判断相关性，然后放大链接查看工单持有的细节 -->

- [<已关闭工单标题>](link) — <答案的一行摘要>

## Not yet specified

<!-- 参见 "Fog of war"：范围内但你还无法工单化的迷雾；随前沿推进而毕业 -->

## Out of scope

```

### 工单

每张工单是地图的一个**子 issue**；跟踪器的 issue id 是它的身份。它的正文是问题，大小适合一个 100K token 的 agent 会话：

```markdown
## Question

<这张工单解决的决策或调查>
```

每张工单携带一个 `wayfinder:<type>` 标签——`research`、`prototype`、`grilling`、`task` 之一（参见[工单类型](#工单类型)）。

一个会话**认领**一张工单的方式是，在任何工作之前，**先**把它分配给驱动地图的开发——这样并发会话会跳过它。那个被分配者_就是_认领：一张打开的、未分配的工单就是未认领的。

阻塞使用跟踪器的**原生**依赖关系——这很关键，因为它让前沿在跟踪器自己的 UI 中_视觉上_渲染，所以人类不用打开地图就能看到什么可拿取。只有缺乏原生阻塞的跟踪器才回退到正文约定。当阻塞它的每张工单都关闭时，一张工单是**未阻塞**的；**前沿**是打开的、未阻塞的、未认领的子工单——已知的边缘。

答案不是正文的一部分——它在解决时记录（参见[穿过地图工作](#穿过地图工作)）。解决一张工单时创建的资产从 issue 链接，而不是粘贴进去。

## 工单类型

每张工单要么是 **HITL**——人类在环里，与一个能为自己说话的人类一起工作——要么是 **AFK**，由 agent 独自驱动。一张 HITL 工单只能通过那种实时交流解决；agent 绝不代替人类那一侧（一个回答自己问题的访谈 agent 已经打破了这一点）。

- **研究**（AFK）：阅读文档、第三方 API 或本地资源如知识库，以浮出一个决策等待的事实。由 `/research` **子 agent** 解决。当需要当前工作目录之外的知识时使用。
- **原型**（HITL）：通过制作一个便宜、粗糙、具体的工件来提高讨论的保真度——一个大纲、一个粗略的立场、一个存根，或通过 /prototype 技能的 UI/逻辑代码。把原型作为资产链接。当"它应该长什么样"或"它应该怎么表现"是关键问题时使用。
- **访谈**（HITL）：对话。默认情况。总是调用 /grilling 和 /domain-modeling 技能。
- **任务**（HITL 或 AFK）：在能做出_决策_之前必须发生的手工工作——没有要决定的、要原型化的或要研究的，但讨论被阻塞，直到它完成。注册一个服务以便判断它的 API、供应访问权限、移动数据以便看到它的形态。这是唯一一种_做_而不是决定的类型——它通过解除一个决策的阻塞来赢得自己的位置，而不是通过交付目的地。agent 在它能独自完成的地方独自驱动（AFK）；否则它交给人类一份精确的清单（HITL）。在工作完成时解决；答案记录做了什么，以及后续工单依赖的任何结果事实（凭据位置、新 URL、行数）。

## 迷雾战争

地图是_故意_不完整的：不要绘制你还看不到的东西。在活跃工单之外是**迷雾战争**——你能看出即将到来的决策和调查的模糊视野，但还无法锁定，因为它们挂在你仍打开的的问题上。解决一张工单会清除它前面的迷雾，把现在可明确化的东西毕业为新的工单——一次一个，直到通往目的地的道路清晰、不再有工单残留。

地图的 **Not yet specified** 部分就是写下那个模糊视野的地方：怀疑的问题、稍后要重新访问的区域。它是_朝向_目的地的未发现前沿——这里的一切都在范围内，只是还不够锋利到工单化。按视野允许的松散或完整程度来写；它兼作协作者阅读努力走向的路标。

**迷雾还是工单？** 检验标准是你是否能现在就精确陈述这个问题——_不是_你是否能现在就回答它。

- **工单化当**问题已经锋利——即使它被阻塞、你还不能行动。
- **Not yet specified 当**你还不能那样锋利地表述它。不要把迷雾预先切成工单大小的碎片：它比工单更粗，当前沿到达它时，一片可能毕业成几张工单，或一张也没有。

**Not yet specified** 排除了已经决定的（Decisions so far）、已经是活跃工单的，以及超出范围的（下一节）。

## 超出范围

迷雾只_朝向_目的地聚集。目的地固定了范围，所以超出它的工作**超出范围**——它不是迷雾，也不属于 **Not yet specified**。它在地图上得到自己的 **Out of scope** 部分：你有意识地排除在_这项_努力之外的工作。是范围，而不是锋利度，让它落在这里。

超出范围的工作绝不毕业——前沿在目的地停止——所以它只在目的地被重画时返回，而且是作为一个新的努力返回，而不是恢复。

把某事裁定为超出范围是一个界定范围的行为，不是路线上的一步。当一张已经存在的工单结果落在目的地之外——绘图时误纳入范围，或由一次解决暴露出来——**关闭它**（一张关闭的工单明确地不在前沿上），并在 **Out of scope** 部分留下一行：摘要加为什么超出范围，链接关闭的工单。它保持不进入 **Decisions so far**，后者记录实际走过的路线——一个范围边界不是它的一步。

## 调用

两种模式。无论哪种方式，**每个会话绝不解决超过一张工单**——研究工单除外。

### 绘制地图

用户带一个松散的想法调用。

1. **命名目的地。** 运行一个 `/grilling` 和 `/domain-modeling` 会话，确定这张地图正在找到路去的地方——规格、决策或变更。目的地固定范围，所以它先被确定。
2. **绘制前沿。** 再次访谈，这次**广度优先**：在整片空间中展开，而不是在任何一个线程上深入，浮出开放的决策和现在可采取的第一步。**如果这没有浮出迷雾**——通往目的地的路已经清晰，整个旅程小到单个会话能承载——你不需要地图。停下并问用户他们想如何继续。
3. **创建地图**（标签 `wayfinder:map`）：Destination 和 Notes 已填，Decisions-so-far 为空，迷雾被勾画进 **Not yet specified**。
4. **创建你现在可以明确的工单**作为地图的子 issue——然后在**第二遍**中接线阻塞边（issue 在能相互引用之前需要 id）。接线把它们排序为前沿和被阻塞的；你还不能明确的一切留在迷雾中——**Not yet specified** 部分。
5. **发射研究子 agent。** 对每张你刚创建的 `research` 工单，启动一个 `/research` 子 agent 并行解决它，把它的发现捕获在一个一次性的 `research/<name>` 分支上，并从工单留下一个上下文指针。
6. 停下——绘图是单个会话的工作；它手工解决任何东西。

### 穿过地图工作

用户带一张地图（URL 或编号）调用。一张工单是**可选**的——没有的话，你挑选下一个决策，而不是用户。

1. 加载**地图**——低分辨率视图，不是每张工单正文。
2. 选择工单。如果用户指定了，用它。否则按顺序取第一张前沿工单。**认领它**：在任何工作之前把它分配给你自己。
3. 解决它——**按需放大**：按需获取任何相关或已关闭工单的完整正文；调用 `## Notes` 块命名的技能。如果拿不准，使用 `/grilling` 和 `/domain-modeling`。
4. 记录解决方案：把答案发布为**解决评论**，**关闭** issue，并在地图的 Decisions-so-far 中**追加一个上下文指针**。
5. 添加新浮出的工单（先创建后接线）；把答案已使其可明确化的任何迷雾毕业，从 **Not yet specified** 中清除每个毕业的片块，让它只以新工单的形式存在。如果答案揭示一张工单——这张或其他——落在目的地之外，把它**裁定为超出范围**，而不是在路线上解决它。如果决策使地图的其他部分失效，更新或删除那些工单。

用户可能并行运行未阻塞的工单，所以预期其他会话会并发编辑跟踪器。
