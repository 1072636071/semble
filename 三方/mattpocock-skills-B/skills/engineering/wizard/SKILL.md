# 向导

**向导（wizard）** 是一个 bash 脚本，逐步引导人类完成一个手动流程——这个流程手动做很繁琐，每次向 AI 重新解释也很繁琐。它打开每个 URL，准确说明要点击和复制什么，捕获各个值，把它们写入该去的地方（`.env`、GitHub 机密），在每个阶段确认，并显示还剩多少个阶段。它可能配置第三方服务、运行一次性迁移，或将项目从一个状态移到另一个状态。

令人愉悦的 UX 已经由 [template.sh](template.sh) 解决了——逐阶段进度、确认闸门、跨平台 URL 打开（包括 WSL）、隐藏的机密输入、幂等的 `.env` 增补、`gh secret`/`gh variable` 写入，以及结束汇总。**你的工作只是界定流程范围并编写各个阶段。** `STAGES` 标记上方的库在每个向导中都是相同的；这种一致性正是关键所在——永远不要手工编辑它。

向导默认是临时性的——为一次运行而构建，保存到 scratch 或 `scripts/` 路径，工作完成后删除。只有当用户想要一个应该保存在仓库中的可重复设置路径时，才提交它。

## 流程

### 1. 界定流程范围

弄清人类必须采取的每个手动步骤，以及沿途捕获的每个值。先读仓库——不要冷问：

- 对于设置：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置，以及 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是一个向导必须产出的值）。
- 对于迁移或转换：当前状态、目标状态，以及它们之间不可逆的操作。

然后向用户展示有序的阶段列表以及每个阶段产出的值，并确认——他们可以增删或重排。

**完成标准：** 每个阶段都按顺序命名，并且对于每个捕获的值，你知道 (a) 人类从哪里获取它，(b) 它被写入哪里（`.env`、GitHub 机密、两者，或都不写——有些阶段是纯操作），以及 (c) 它是机密（隐藏输入）还是公开的。

### 2. 映射每个阶段的旅程

为每个阶段写出人类遵循的精确路径：打开哪个 URL、在那里做什么、值在哪里显示、它填充哪个变量——例如"仪表盘 → 开发者 → API 密钥 → 显示测试密钥 → 复制"。当你并不真正知道当前的 UI 或确切的命令时，如实说明并向用户询问或查阅文档——永远不要编造可能不存在的步骤。

**完成标准：** 每个阶段都能追溯到陌生人可以遵循的具体指令。

### 3. 编写向导

将 `template.sh` 复制到目标路径。用一个 `stage` 替换示例阶段，每个步骤一个，按依赖顺序排列。使用库辅助函数——`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`——并将 `TOTAL_STAGES` 设置为你编写的阶段数。

坚持模板设定的标准：在询问其值之前打开 URL，对任何机密使用 `ask_secret`，对每个持久化的值使用 `write_env`，只对 CI 实际需要的值使用 `set_secret`，在任何不可逆操作前使用 `confirm`。每个 `stage` 都会清屏，使只有当前步骤可见——让一个阶段只聚焦一个任务，这样人类需要的内容就不会滚出屏幕。不要触碰标记上方的库。

### 4. 验证并交接

- `bash -n <script>`；如果可用则运行 `shellcheck`。
- `chmod +x <script>`。
- 不要自己端到端运行它——它会打开浏览器并阻塞在人类输入上。改为静态追踪：第 1 步中的每个值都被捕获，并落到第 1 步所说的位置，并且每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用完全匹配。
- 告诉用户如何运行它。如果它是可重复的设置路径，提交它并从 README 链接，这样下一个人运行脚本而不是询问 AI。
