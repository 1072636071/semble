## 它做什么

`improve-codebase-architecture` 勘察代码库寻找**深化机会**——浅模块（接口几乎和它隐藏的东西一样复杂）能变成深模块的地方——把它们写成一个自包含的 HTML 报告，然后[访谈](https://www.aihero.dev/ai-coding-dictionary/grilling)你选中的任何一个。

它从不改变代码。整个运行在操作系统的临时目录中产出一个 HTML 文件，加上一段对话；重构本身稍后发生，在一个单独的[会话](https://www.aihero.dev/ai-coding-dictionary/session)里，穿过正常的构建流程。那正是让它成为勘察而不是重构工具的东西，也是为什么这个技能值得在你还没准备好触碰的代码库上运行。

两个过滤器让报告不变成通用的清理建议。每个候选者都必须通过**删除测试**——移除这个模块会把复杂性集中在一个更小的接口后面，还是只是把它散布到调用者上？只有"集中"的情况赚到一张卡片。而且除非你把它指向一个特定区域，它先读近期的 commit 历史，把扫描偏向正在积极变化的路径，理由是：在没人碰的代码中深化是一个你永远不会兑现的重构。

## 何时使用

你通过输入 `/improve-codebase-architecture` 调用它——[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不会自行触发它。

它坐在构建循环之外——它不是主循环中的一步，而是你定期运行、为改善代码库排队更多工作的东西。它被使用的四种情况：

| 情况 | 如何使用它 |
| --- | --- |
| 例行维护 | 每几天运行它，或每当有空闲时刻出现，以阻止结构在功能之间腐烂。 |
| 大构建之前 | 把它指向[规格](https://www.aihero.dev/ai-coding-dictionary/spec)："我们怎么让这个变更变容易？"这是对它最有效的提示。 |
| 棕地审计 | 在一个大型、无结构或[vibe-coded](https://www.aihero.dev/ai-coding-dictionary/vibe-coding)的仓库上运行，找出它实际处于什么形态。 |
| 遗留测试工作 | 在针对不可测试的代码写测试之前，用它先找到缺失的接缝。 |

它在哪里与兄弟技能混淆：

- 设计一个你已经选定的模块，用 [codebase-design](https://aihero.dev/skills-codebase-design)——那是工作台，这是找什么放上去的勘察。
- 对单个会话装不下的大努力，用 [wayfinder](https://aihero.dev/skills-wayfinder)。
- 对"这个具体的东西坏了"，用 [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)。当真正的发现是没有好的接缝锁住 bug 时，它在这里交接。

## 前提条件

运行它不需要任何东西。如果存在，它读取 `CONTEXT.md` 和 `docs/adr/` 中的任何 ADR，并在它们存在时用你领域自己的名词说话——一个候选者读作"深化 Order 接收模块"，而不是"重构 FooBarHandler"。

它在两个地方写。报告去 `<tmpdir>/architecture-review-<timestamp>.html`，在仓库之外。在访谈循环中它会添加或磨锋利 `CONTEXT.md` 中的术语，在文件不存在时创建它，并提议把一个被拒绝的候选者记录为 ADR，这样未来的运行不会重新建议它。

## 深度，和寻找它的报告

技能靠一个想法运转：**深度**。一个深模块把大量行为放在一个小而稳定的接口后面。一个浅模块让它的实现穿过一个几乎和它下面的代码一样宽的接口泄漏。报告是一次对浅度的追猎——只为了可测试性提取的纯函数，而真正的 bug 住在它们如何被调用中（没有**局部性**）、跨它们的**接缝**泄漏的模块、一个不开五个文件就无法理解的概念——以及修复它的深化提案。

每个候选者是一张卡片：涉及的文件、摩擦、一个通俗英语的解决方案、用**局部性**和**杠杆**表述的收益、一个前/后图，和一个强度徽章。

| 徽章 | 它对你意味着什么 |
| --- | --- |
| `强` | 删除测试清晰通过，摩擦是真的。认真对待这些。 |
| `值得探索` | 合理的深化，但回报取决于代码接下来走向哪里。 |
| `推测性` | 为了完整性而浮出。这些大多数可以安全忽略。 |

报告以一个**首选建议**结束——它会先处理的那个——然后技能停下，问你想探索哪个候选者。在那个时刻什么都还没被决定，没有代码动过。

## 你选中一个之后会发生什么

选中一个候选者开始一场针对它的[访谈](https://www.aihero.dev/ai-coding-dictionary/grilling)会话：约束、接缝后面坐着什么、哪些测试存活、深化的接口应该长什么样。那个会话的输出是一个决策，不是一个 diff。从那里走正常流程——把决策带进 [to-spec](https://aihero.dev/skills-to-spec)，然后 [to-tickets](https://aihero.dev/skills-to-tickets)，然后 [implement](https://aihero.dev/skills-implement)。

## 常见问题

**它关于一个想法访谈了我一个小时，而不是给我看选项。我能关掉那个吗？**

能——在你调用时说一声（"别访谈我，只给我看报告"）。这是这个技能最大的抱怨。一个用户直言不讳：他们喜欢它作为"获得深入分析改进的便捷方式"，在访谈循环被添加后发现它"近乎不可用"，报告会话中它提出一个单一方案然后问"几十或几百个问题"。设计意图是报告先来，访谈只在你选择的候选者上开始，但较弱的[模型](https://www.aihero.dev/ai-coding-dictionary/model)跳过直接访谈他们第一个想法。那个线程中的报告因模型而异很大，而且它是一个开放 issue——技能还没有一个记录在案的 no-grill 模式。

**报告作为无样式的原始 HTML 打开，没有图。发生了什么？**

报告从 CDN 加载 Tailwind 和 Mermaid，所以它打开时需要网络访问，而且当某些东西阻止那些脚本时会静默损坏。提交的案例是一个要求 SRI 哈希的安全钩子：agent 添加了它们，CDN 给浏览器提供的字节与用于计算哈希的 `curl` 不同，浏览器阻止了脚本。离线和锁定环境撞到同一堵墙。agent 看不到这个，因为它从不渲染页面。变通办法是要求内联 CSS 和手工构建的 SVG 图，而不是 CDN 脚手架。这是一个开放 issue 和一个真实的粗糙边缘。

**它给了十二个候选者。我在同一个会话中处理它们还是开一个新会话？**

一个会话一个候选者。在一个对话中处理几个会同时用报告、访谈、领域模型编辑和代码变更填满[上下文窗口](https://www.aihero.dev/ai-coding-dictionary/context-window)。报告只住在临时文件中，所以携带候选者本身而不是文件：选一个、访谈它、把决策带进 `/to-spec`，把其余变成你以后可以独立拿起的[工单](https://www.aihero.dev/ai-coding-dictionary/ticket)。把选中的改进放进一份规格，而不是直接去实现。这是一个反复出现的问题，技能本身没有记录的工作流。

**我应该怎么提示它？**

带着你接下来要构建的东西在脑中。一个大构建要来时，把它指向规格并问"我们怎么让这个变更变容易？"一个无提示的运行会自行扫描热点，这对例行维护很好，但点名一个方向是让报告可操作的东西。

**它在一个大型遗留代码库上有效吗？**

部分。它擅长缺乏一致结构的大型现有代码库，而且它是任何一次性结构设置之后的推荐维护机制。诚实的反向：真正失控项目的用户报告它"帮助了一点但仍然不够"，一个八年代码库的开发者报告模型在转圈，而同样的技能在一个整洁的仓库上产出干净的图。那个情况还没有专门的 `/refactor` 技能。如果代码库完全没有任何共享词汇，先 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 建立一个，往往会让这个技能的输出好得多。

**这和 `/codebase-design` 有什么不同？**

`/codebase-design` 是一个参考，不是一个会话驱动。它提供词汇——模块、接口、深度、接缝、适配器、杠杆、局部性——而这个技能借用它。把一个全新 agent 指向 `/codebase-design` 作为要"做"的东西是一个已知失败：没有自己的流程可循，agent 发明一个、重新探索代码、在问你任何东西之前跑非常久。用这个技能驱动；消费那一个。

**它会告诉我代码库没问题吗？**

很少，而且你应该进去就知道。技能被构建为输出发现，所以框架推着它产出候选者，而不是得出没有问题的结论。强度徽章是防线——一个所有东西都是`推测性`的报告，是技能在用它唯一知道的方式告诉你它什么都没找到。

**它在 Codex 或另一个 harness 里有效吗？**

部分。探索步骤直接用 `subagent_type=Explore` 点名 Claude Code 的 `Agent` 工具，所以没有那个工具的[harness](https://www.aihero.dev/ai-coding-dictionary/harness) 可能跳过并行探索而不是替代它自己的。技能仍然运行；只是扫描没那么彻底。一个 harness 中立的改写被提议了但没合并。

**我怎么在 TypeScript 里实际实现深模块？**

技能没有随附好的答案。反复出现的请求是给一个 `TYPESCRIPT.md` 提供这些原则的具体文件和模块布局，它不存在。技能会告诉你深化属于哪里、什么应该坐在接缝后面；把它翻译成包或目录结构目前靠你。

## 正常工作的标志

- 候选者点名你领域的概念，而不是发明的类名——"Order 接收模块"，而不是"FooBarHandler"。
- 候选者聚集在你最近编辑的文件中，而不是在仓库的休眠角落。
- 运行期间没有代码改变。唯一的新文件是临时目录里的 HTML 报告。
- 它在报告后停下，问你要哪个候选者，而不是自己继续。
- 每张卡片把回报解释为局部性或杠杆，并说哪些测试变简单——而不只是"这更干净"。
- 为一个持久的原因拒绝候选者，你会得到一个记录 ADR 的提议，这样下次运行不会重新建议它。

## 在流程中的位置

`improve-codebase-architecture` 是**定期维护**——每几天运行它，在任何链之外，为了排队工作而不是做它。它的邻居是 [codebase-design](https://aihero.dev/skills-codebase-design)，它拥有每个候选者都用其写成的深度和接缝词汇；[grilling](https://aihero.dev/skills-grilling)，在你选中一个候选者后走决策树；以及 [domain-modeling](https://aihero.dev/skills-domain-modeling)，它在决策落定时保持 `CONTEXT.md` 和 ADR 最新。它产出的是一个想法，在 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 或 [to-spec](https://aihero.dev/skills-to-spec) 重新进入主构建流程。对于哪个技能适合某个情况，[ask-matt](https://aihero.dev/skills-ask-matt) 是整套的路由器。
