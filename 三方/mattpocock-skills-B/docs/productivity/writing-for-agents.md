## 它做什么

`writing-for-agents` 是你对着它写 agent 面向文档的参考——一个技能、一份 `AGENTS.md` / `CLAUDE.md`、一份[规格](https://www.aihero.dev/ai-coding-dictionary/spec)、一个运行时提示、一个 README、任何[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 读的文档。打包方式不同；写作本身不变：同样的杠杆让每一份都可预测，所以 agent 每次运行都走同样的*流程*，而不是产出同样的输出。

它的默认走法是删除，不是解释。让一个 agent 为另一个 agent 写指令，它会把大部分话花在解释[模型](https://www.aihero.dev/ai-coding-dictionary/model)已经知道的东西上——那些行每一行都是一个**无效操作**，付[上下文](https://www.aihero.dev/ai-coding-dictionary/context)却不改变任何行为。这个参考是找到它们的透镜，这正是为什么它在你已经有的文档上至少和在一份空白文件上一样经常赚它的养料。

它直到 v1.1 都被称为 `writing-great-skills`。重命名追踪它底下一直是什么：其中几乎没有任何东西是技能特有的。技能唯一的机制——frontmatter、模型调用对比用户调用的选择、路由技能——被披露到一个链接的 `SKILL-MECHANICS.md`，只有当你面前的文档是一个技能时才读它。

## 何时使用

输入 `/writing-for-agents`，或当你正在创建或编辑一个技能、修改 `AGENTS.md` 或 `CLAUDE.md` 时 agent 自行触发它。

用手取用它对 agent 读的其他一切：你的文档、规格和[工单](https://www.aihero.dev/ai-coding-dictionary/ticket)、系统提示和[AFK](https://www.aihero.dev/ai-coding-dictionary/afk)提示。检验标准是一个问题——有 agent 读这个吗？——而且文档如何到它面前不重要，无论是一个指针点名它、一个人粘贴它，还是它只是坐在仓库里。要首先弄清一个代码库实际包含什么，用 [grill-with-docs](https://aihero.dev/skills-grill-with-docs)——这个参考管一份文档怎么读，不管它知道什么。

## 两种负载

整个参考围绕的是一对预算，每份文档和指针都花：

- **上下文负载**——常驻加载的材料在 agent 窗口上的成本：一个 `AGENTS.md` 行、一个技能 description、任何每[轮](https://www.aihero.dev/ai-coding-dictionary/turn)都坐在上下文里、无论是否触发的东西。
- **认知负载**——对你的成本：存在哪些文档，以及何时取用每一份。你是索引。不是一个要最小化的成本——它是人类能动性的价格。

一旦你用这两种负载思考，大多数写作决策——拆分或不、内联或披露、指向或推——都变成在不同地方做的同一个权衡。

## 杠杆

- **[上下文指针](https://www.aihero.dev/ai-coding-dictionary/context-pointer)**——保存在上下文中的参考，点名上下文之外的材料并编码何时够到它。一个技能 description 和一个点名某文档的 `AGENTS.md` 行是同一个对象；指针的*措辞*，而不是它的目标，决定 agent 通过它够到得多可靠。
- **信息层级**——从文件内步骤，到文件内参考，到指针后面的披露参考的梯子。**[渐进式披露](https://www.aihero.dev/ai-coding-dictionary/progressive-disclosure)** 是沿梯子向下的动作，让顶层保持可读。
- **完成标准**——每个步骤完成条件的清晰度和要求度，以及那个要求驱动的**苦工**；对**过早完成**的防御。
- **引导词**——一个已经在模型预训练中的紧凑概念（*tight*、*red*、*tracer bullet*），agent 在运行文档时用它思考。它锚定两次：正文中的执行，指针中的调用。
- **修剪**——单一事实来源、相关性，以及逐句应用的无效操作检验，对抗**重复**、**沉淀**和**蔓延**。

## 常见问题

**`/writing-great-skills` 去哪了？**

它就是这技能，在 v1.1 重命名。实践者在名字追上之前很久就已经把它指向 `AGENTS.md`、文档、规格、工单和运行时提示；结构、引导词和修剪结果是任何 agent 读的文本的工艺。没有别名——在新名字下重新安装。

**"为 agent 写作"——所以是 agent 做写作？**

反过来。你是作者；agent 是读者。那正是这个文体的全部困难：你在为一个已经读过一切的读者写作，所以解释是浪费，精确是全部工作。

**我就不能让它为我写吗？**

你可以，而它会产出某种啰嗦的东西。放任不管，模型解释它已经知道的东西，而且它不会自己应用无效操作检验或够到一个引导词。在草稿上使用这个参考——一次审查通过正是它大部分价值落下的地方。

**我让一个 agent 修剪一份文档，它切掉了功能。**

被告诉"streamline"的 agent 为长度优化，因为长度是它们能看到的东西。无效操作检验是行为性的，不是美学的：删除那行，问 agent 的行为是否改变了。当一个句子不成立时，删除整个句子，而不是从它削词——并通过运行文档来落定关于它的分歧，而不是争论。

**我怎么知道它何时完成？**

当它有效，而且你再也找不到重复、沉淀或无效操作时。这里没有自动评估；检查是一次手动运行加上失败模式词汇作为诊断。当一份文档行为异常时，那个词汇也是维修工具包——先命名失败模式，然后修复那个。

**这应该住在 `CLAUDE.md` 还是别处？**

问你想付哪种负载。`CLAUDE.md` 无条件加载进每个[会话](https://www.aihero.dev/ai-coding-dictionary/session)；一个指针后面的材料在它触发之前只花指针自己那一行。任何十分之一上下文都适用的东西，其他九次都在付上下文负载。

**我需要为每个新模型重写我的文档吗？**

大多不需要，而且对一个模型过度拟合是它自己的陷阱。为一个新模型更新通常是一次另一个无效操作通过，而不是一次重写。

**我的技能只在它被构建的那个确切任务上有效。**

常见的路线——做一次工作，然后让 agent 把它写成技能——对那一次运行过度索引，而范例出来太具体。把运行留作证据，然后刻意抽象：剥掉属于那个仓库和那些文件的东西，为那类任务写。

**英语不是我的第一语言。我会失去引导词优势吗？**

不会——找到把最多行为打包进最少[token](https://www.aihero.dev/ai-coding-dictionary/token)的那个词正是这个参考为你做的工作。那是它存在的目的之一。

## 正常工作的标志

- 文档随着变好而变短，而你惊讶于剩下多少。
- 你能指着一个引导词，看着它在不止一个地方做事。
- 没有东西以任何形式被陈述两次。重复是最可靠的迹象，表明一份文档从未被测试过。
- 只有一个分支需要的参考坐在一个指针后面，而不是在主文件里。

## 在流程中的位置

这是一个随时可取的独立参考。它在链中没有邻居，因为它坐在整套的*下面*，而不是任何单个技能*旁边*：这里的每个技能都是对着它写的，而其他技能留下的文档——一份 `CONTEXT.md` 和它的 ADR、一份规格、一张工单——正是当 agent 必须读它们时它所管辖的文本。当你不确定哪个技能或流程适合一个任务时，[ask-matt](https://aihero.dev/skills-ask-matt) 在整套之上为你路由。
