## 它做什么

`grilling` 是在任何人采取行动之前压力测试一个计划、一个决策或一个想法的访谈循环。它把主题映射为一棵**设计树**——每个决策分支到挂在它下面的决策——并逐分支访谈你，直到没有东西被默默假设。

它不一次问一个问题，也不一次问所有东西。每**轮**问整个**前沿**：每一个前提已经落定的决策，仅此而已。如果一个问题依赖另一个，两个问题从不共享一轮——一个悬在一个仍然打开的答案上的问题属于后面的一轮。你的回答落定决策，前沿向外移动，下一轮问被解除阻塞的东西。十三个问题通常落在大约三轮里，而不是十三轮。

## 何时使用

输入 `/grilling`，或当一个任务合适时[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 自行触发它。它是访谈家族中唯一模型调用的[技能](https://www.aihero.dev/ai-coding-dictionary/skill)，这正是你很少输入它的原因：通常一个你*确实*输入的技能在为你运行它。

直接输入 `/grilling` 给你的是纯粹的访谈，没有别的。你想要的超过那个时：

| 你拥有什么 | 取用 |
| --- | --- |
| 你不在一个工作目录里工作 | [grill-me](https://aihero.dev/skills-grill-me)——同一个[会话](https://www.aihero.dev/ai-coding-dictionary/session)，在一个 agent 绝不会自行发射的名字下 |
| 你在一个工作目录里 | [grill-with-docs](https://aihero.dev/skills-grill-with-docs)——同一个会话，而且它边走边写 `CONTEXT.md` 和 ADR |
| 一项大到单个会话装不下的努力 | [wayfinder](https://aihero.dev/skills-wayfinder)——它绘制一张地图，在决策工单内部运行访谈 |
| 一个交谈无法落定的问题——某样东西应该看起来或感觉怎样 | [prototype](https://aihero.dev/skills-prototype)——构建那个一次性版本，然后回来 |
| 一个你自己的、需要一个访谈的技能 | 从它调用 `/grilling`，而不是写另一个访谈 |

## 轮次、前沿，以及谁决定

三个想法携带整个技能。

**设计树**是主题的模型：决策下面挂着决策。**前沿**是前提全部落定的决策集——现在还能诚实地问的问题。**一轮**是一个前沿，被完整地问、被完整地回答。

在一轮内部，每个问题以固定形态到达：在 `❓` 后面编号和命名，然后是正文，然后是 agent 的推荐答案单独在一行 `➡️` 上。那是让一轮可以按编号回答的东西——"1 是，2 第二个选项，3 否，原因如下"——而不是把问题引用回去。格式有一个已知粗糙边缘：推荐有时*反驳*问题本身的措辞，所以同意推荐意味着对问题回答"否"。当那发生时，回答推荐并说出来。

设计的另一半是事实与决策的拆分。事实是技能自己的工作：当一个前沿问题需要[环境](https://www.aihero.dev/ai-coding-dictionary/environment)能落定的东西时，它派一个[子代理](https://www.aihero.dev/ai-coding-dictionary/subagent)去查，而不是问你。它不在那上面阻塞——只有运行中的探索下游的问题等待。决策是你的，而它必须等它们。一个运行 `grilling` 却回答自己决策的 agent 已经打破了技能，而不是自由解读了它。会话在前沿为空时结束，而且在你确认你们达成共享理解之前，它不会对你同意的东西采取行动。

诚实的局限：前沿是 agent 的判断，不是一个计算的图。它可以在同一轮里放两个问题，之后才发现一个答案本应改变另一个。对此没有守卫，除非告诉它，那会在下一轮重新打开受影响的那个分支。

## 常见问题

**我能回到一次一个问题吗？**

能，而且受众中很大一部分这样做。把这加到你全局的 `CLAUDE.md`：

```
When grilling, ask one question at a time.
```

基于轮次的默认是真正被争论的。慢慢读的实践者、用第二语言工作的、或把顺序格式用作专注脚手架的，都报告一次一个的节奏对他们更好，而且退出是被支持而不是被容忍的。

**`/batch-grill-me` 去哪了？**

进了这个技能。基于轮次的提问短暂地作为一个独立技能发布，然后移进 `grilling` 本身，所以每一个建立在这个原语上的东西——`grill-me`、`grill-with-docs`、`triage`、`wayfinder`——立刻都得到了它。没有 `batch-grill-me` 要安装，也没有独立的顺序技能；上面的 `CLAUDE.md` 一行是回到一次一个的方式。

**一次问整轮肯定丢掉我早先的答案会引出的问题。不是吗？**

这是对轮次设计最常见的反对，而前沿正是答案：一轮只包含彼此不依赖的问题，所以一轮中没有任何答案能使那轮中的另一个问题失效。答案仍然重塑一切下游——下一轮被重新计算，而不是预先写好。你失去的小于"一次所有问题"所暗示的，大于零：见上面前沿的局限。

**它的问题用完了，然后开始构建。**

一个确认闸门正是为此存在：技能在前沿清空时不算完成，它在你说了解是共享时才算完成。更弱更快的[模型](https://www.aihero.dev/ai-coding-dictionary/model)仍然打破它——这最常在低努力或非前沿模型上被报告，它们把"访谈直到共享理解"塌缩成几个问题加一个大纲。如果你的会这样，可靠的修复是把你自己的 `AGENTS.md` 或 `CLAUDE.md` 里的一行告诉 agent 未经许可不实现。

**它回答了自己的问题而不是问我。**

那是运行中的一个 bug，不是预期行为，而且那是事实和决策在技能文字中被拆分的原因。它最常在另一个技能在"解决这张工单"的框架内运行 `grilling` 时出现，在那里周围的任务读起来像继续移动的许可。同样的约束也是为什么没有异步模式：人们要求过一个读 GitHub issue 并发布一份合并决策备忘录的变体，而那是另一个技能，因为一个没人回答的访谈会话产出的是 agent 的意见而不是你的。

**我能限制问题的数量吗？**

不能，而一个上限被刻意排除在范围外。有些计划需要三个问题，有些需要五十个；一个固定天花板要么截断困难的情况，要么在容易的上面感觉武断。用通俗语言引导是预期控制——告诉它收尾，或停下并接受计划停在的地方。如果一个会话跑得非常长，原因通常是范围太大；拆开工作，访谈那些碎片。

**我自己安装了 `grill-me`，什么都没发生。**

`grill-me` 是一个一行的技能，整个正文是"运行一场 `/grilling` 会话"，所以它需要这个技能也被安装。`grill-with-docs` 同样，它另外需要 [domain-modeling](https://aihero.dev/skills-domain-modeling)。安装整套避免问题；选择性安装意味着也安装原语。

**`grill-with-docs` 运行了，但它从不加载 `grilling`。**

一个真实的、未修复的粗糙边缘，跨[harness](https://www.aihero.dev/ai-coding-dictionary/harness)和模型被报告：一个点名另一个技能的技能不能可靠地使那个技能加载，而 `grill-with-docs` 点了两个。信号是一场一次问所有东西、不带任何推荐的会话——那是模型在即兴一场访谈而不是运行这一个。直接问 agent 它是否加载了 `grilling` 和 `domain-modeling` 通常能恢复它。

## 正常工作的标志

- 一轮作为编号列表到达，每个问题带它的推荐在单独一行 `➡️` 上，而且你能按编号回答整轮。
- 一轮中没有东西需要同一轮中另一个问题先被回答。
- 后面的轮次问第一轮不可能问的东西。
- 它去查事实——读文件、派一个子代理——而不是问它本来能查出来的东西。
- 后台运行的研究不让轮次停滞；只有依赖它的问题等待。
- 它在结尾停下，要求你确认理解是共享的，而不是开始工作。
- 问题数保持高，而轮次数保持低。

## 在流程中的位置

`grilling` 是一个**原语**，不是一个你安排的步骤：访谈技术的单一事实来源，保持在一个地方，这样每个需要访谈的技能都够到它，而不是发明一个。[grill-me](https://aihero.dev/skills-grill-me) 和 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 是它的两个用户调用前门，而 `grill-with-docs` 是主构建链开始的地方，在 [to-spec](https://aihero.dev/skills-to-spec) 之前。[wayfinder](https://aihero.dev/skills-wayfinder) 运行它来解决决策工单，[triage](https://aihero.dev/skills-triage) 访谈一个含糊的报告变成一个可工作的，而 [improve-codebase-architecture](https://aihero.dev/skills-improve-codebase-architecture) 在你挑了一个要深化的候选者后走这棵树。当你不确定哪个入口点合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 为你路由。
