## 它做什么

`handoff` 把你所在的对话压缩成一份**交接文档**——一个 markdown 文件，写到你的操作系统临时目录而不是工作区——一个全新的[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 可以读它来捡起工作。

它买到的是**可移植性**，不是压缩。那让技能比它听起来更窄。只有当工作必须*旅行*时你才需要一个文件——到一个新[harness](https://www.aihero.dev/ai-coding-dictionary/harness)、一个新目录、一个同事，或一个你想分叉出去的附带任务。如果没有东西在旅行，你不需要交接：留在[会话](https://www.aihero.dev/ai-coding-dictionary/session)里、`/clear`、一个[子代理](https://www.aihero.dev/ai-coding-dictionary/subagent)和 `/compact` 覆盖了普通的阶段末尾情况，而 `/compact` 比这个技能更常覆盖它。

## 何时使用

你通过输入 `/handoff` 调用它——agent 不会自行触发它。传一条关于下一个会话是做什么的说明，文档就为它而写。

四个情况就是全部触发：

| 情况 | 为什么一个文件 |
| --- | --- |
| 换 harness——Claude → Codex | 新 harness 看不到旧的[上下文](https://www.aihero.dev/ai-coding-dictionary/context) |
| 移到一个不同的目录或仓库 | 原型目录是常见情况 |
| 把工作送给一个同事 | 他们需要他们能读的东西 |
| 分叉一个阶段中途发现的附带任务 | 你继续工作；第二个 agent 拿走分叉 |

对其他任何东西——同一个 harness、同一个目录、你[访谈](https://www.aihero.dev/ai-coding-dictionary/grilling)完了要去实现——`/compact` 是那一手。[ask-matt](https://aihero.dev/skills-ask-matt) 在一个阶段边界上携带所有五个选项的有序树。

## 分叉是人们跳过的那种用法

技能的描述读起来像会话恢复：写一份摘要，在这里结束，在那里恢复。那样读它看起来像一个更差的 `/compact`，所以它被略过。分叉情况才是值得知道的那个。你**留在你的会话里**，把积累上下文的副本交给一个并行工作的第二个 agent。

那正是穿过 [prototype](https://aihero.dev/skills-prototype) 的绕道所用的。你深陷一场设计对话，你撞上一个只有运行代码才能落定的问题，而你不想把建好的线程花在查明上。交接给一个原型会话，拿到答案，把答案交接回来，从原始线程引用它。两次穿越，一场活对话，没有东西被重新解释。

阶段边界处的五个选项中三个保留不同的东西：`/compact` 保留你的意图，`/clear` 什么都不保留，`/handoff` 保留工作移动的能力。

## 什么旅行，什么不

文档携带活线程——什么在飞行中、为什么、接下来是什么——加上一个**建议技能**部分，点名下一个 agent 应该取用什么。机密在写之前被脱敏。

它刻意不携带任何已经写下来的东西。规格、计划、ADR、issue、commit 和 diff 按路径或 URL 引用，绝不复制。那让文件保持小，并把已落定的细节保持在同一个地方，而不是两个漂移的地方。

## 常见问题

**Handoff 还是 compact？**

除非有东西在旅行，否则 `/compact`。留在同一个任务上是压缩，不是交接——同一个 harness、同一个目录、你需要留在环里，就是阶段边界树大多数日子落点。`/handoff` 的优势不是它总结得更好；而是结果是一个你能带到一个 `/compact` 够不到的地方的文件。

**那 compact、clear 和 handoff 的实际区别是什么？**

三样不同的东西被保留。`/compact` 压缩这个上下文，让你在一个全新窗口里继续——意图存活。`/clear` 清空窗口，从零开始——当你身后的一切都是可丢弃时正确，如果不是则单向。`/handoff` 写一个可移植的文件——工作活过移到别处。注意所有三个都把**[首要来源](https://www.aihero.dev/ai-coding-dictionary/primary-source)**（按它发生的样子存在的会话）变成**[次要来源](https://www.aihero.dev/ai-coding-dictionary/secondary-source)**（它的摘要）。继续是唯一不这样做的走法，这正是它第一个被排除的原因。

**我的交接文件去哪了？**

临时目录，那是关于这个技能被报告最多的摩擦：路径长、每个 OS 不同、在 Windows 上 agent 有时要试几次才能找到正确的那个。要回路径并在继续前保存它。临时是刻意的：交接是一份过境文档，不是一份你维护的工件。它也不是持久的——见下一个问题。

**我的交接在会话之间消失了。**

有些环境在会话之间清除临时——报告过的案例是 Codex——而 `/private/tmp` 在重启时消失。如果下一个会话不是在一小时内开始，或是在不同 harness 下开始，一写完就自己把文件复制到某处持久的地方。同样的适用于文档*指向*的任何东西：一份引用临时中其他文件的派发，是下一个 agent 无法跟随的派发。

**我怎么实际把它交给下一个 agent？**

打开全新会话，把它指向路径：读这个文件，然后继续。指向文件而不是把摘要粘贴进一个 shell 命令——一个含反引号或 `$(...)` 的摘要当它被插值进 `claude "<summary>"` 时会被弄坏，而通常的失败是静默截断而不是报错，所以新 agent 从一个安静地不完整的简报开始。

**这和 `/branch`、`--fork-session` 或内置的 `/handoff` 一样吗？**

类似，不一样，而 `/branch` 在这里不是一个已发布的技能——`/handoff` 是规范名字。一个 fork 继承上下文的一份精确副本；这个技能产出一个*定向*压缩，瞄准一个已陈述的下一个任务，在一个文件里。在 fork 能做的地方——同一台机器、同一个 harness、同一个目录——fork 工作量更少。文件在目的地是 fork 去不了的地方的那一刻获胜。

**什么东西反而属于 `CLAUDE.md`？**

问它下个月还是真的吗。`CLAUDE.md` 是关于项目的常驻上下文，每次会话都加载，无论相不相关。交接是关于一件在飞行中的工作，一旦那工作落地就死了。一直要被重新解释的事实是一个 `CLAUDE.md` 问题；一个半成品任务是一次交接。

**它捕获了是什么，不是为什么。**

一个公平且重复的批评。两件事有帮助。传参数——告诉它下一个会话是做什么的——让与*那个*相关的推理被保留而不是被压平。并留意会话从未真正验证的自信声明："X 没构建"、"Y 完成了"。下一个 agent 把文档当作契约，不会重新检查它，所以一个写成事实的信念变成之后一切的一个错误前提。在交给它之前读文档，把任何你只是假设的东西降级。

**为什么它是一个技能而不是一个斜杠命令？**

两者都有效；它们适合不同的情况。作为一个技能，它通过和这里其他一切相同的安装路径发布和更新，那是让它可共享的东西——agent 不会自行触发它的约束由它的 frontmatter 设置，而不是由机制。

## 正常工作的标志

- 文档是会话的一小部分，而规格、issue 和 diff 以路径和 URL 出现，而不是作为复制的文本。
- 你能冷读它，不用原始会话打开，就知道接下来做什么。
- 全新 agent 开始工作，而不是让你重新解释设置。
- 在分叉情况下，你回来时你的原始会话仍坐在那里没被动过。
- 建议技能部分点名你自己会取用的那个技能。
- 其中没有任何东西是密钥、token 或密码。

## 在流程中的位置

`handoff` 是一个**随时可取的独立项**，住在会话之间的接缝而不是构建链内部——但一条窄的，而且诚实地图是你使用它的频率会低于阶段边界处的其他四个选项。它最近的邻居是 [prototype](https://aihero.dev/skills-prototype)，因为一个原型住在它自己的目录里，而出去再回来的往返正是这个技能所服务的穿越。当你在一个边界上、不确定继续、清除、交接、委托还是压缩时，[ask-matt](https://aihero.dev/skills-ask-matt) 携带给那五个排序的树——并在整套之上为你路由。
