## 它做什么

`grill-me` 拿一个**松散的想法**，访谈你直到你能承诺它。你不需要一个成形的计划来开始——产出一个正是这个[会话](https://www.aihero.dev/ai-coding-dictionary/session)的目的。它按**轮次**问：每轮是整个**前沿**——每一个前提你已经落定的问题——所以你从不会被问一个悬在它还没听到的答案上的问题。

它是**[无状态的](https://www.aihero.dev/ai-coding-dictionary/stateless)**。它不写文件，不留工作区。它留下的唯一东西是一个更锋利版本的想法，在你自己的脑子里。

## 何时使用

你通过输入 `/grill-me` 调用它——[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不会自行触发它。在**全新对话**中开始它，而不是在你有 agent 已经写过的计划之上。

一旦你有一个值得认真对待的想法就取用它——一个功能、一个产品方向、一个商业决策、一篇写作——远在你弄清楚它涉及什么之前。含糊不是等待的理由；它正是这个会话吃的东西。如果你已经能精确地明确化这个东西，你不需要访谈它。

三个访谈技能中你想要哪个取决于你面前有什么：

- **任何东西，任何地方**——`grill-me`。它不需要仓库，不写文件，主题也不必须是代码。
- **一个要对齐的代码库**——[grill-with-docs](https://aihero.dev/skills-grill-with-docs)。同样的访谈，但是[有状态的](https://www.aihero.dev/ai-coding-dictionary/stateful)：它读你的代码，把学到的东西保存在 `CONTEXT.md` 和 ADR 中。
- **对单个会话太大**——[wayfinder](https://aihero.dev/skills-wayfinder)。它把努力绘制为一张地图，在它内部运行访谈会话。

关掉[计划模式](https://www.aihero.dev/ai-coding-dictionary/agent-mode)。计划模式让 agent 急着去产出计划，那与停留在探究中是相反的。

## 这是一场对话，不是一次面试

技能问问题，但**你**拥有范围。那是人们错过的地方，也是把一场把想法变成决策的会话与一场产出自信的废话的会话分开的东西。

失败模式是**被动**——对四十个问题回答"同意，同意，同意"，出来一个 agent 写的、你点头通过的计划。它感觉有成效，因为它长。实际上什么都没被决定，而且结果带着它没挣得的确定性。

主动意味着引导。推回一个低于你所需保真度的问题。在范围漂移时说出来。回答"我不知道"并当真。这个技能被构建为帮助一个工程师，而不是替代一个：出来的东西追踪的是你答案的质量，而不是被问问题的数量。

相反的错误是真实的但更罕见——在访谈里待太久，永远到不了代码。

## 可访谈的与不可访谈的

有些问题可以通过交谈回答。其他的不能，而无论多少访谈都不会让你到那里。

"一个长表单还是三个页面？"和"这个交互应该感觉怎样？"是**不可访谈的**——它们需要某种东西去反应。当你撞上一个时，停下访谈。用 [prototype](https://aihero.dev/skills-prototype) 构建那个一次性版本，看看它，然后回来用一行回答。

交谈着穿过一个不可访谈的问题正是会话膨胀的地方。agent 不断重述，你不断猜，范围增长去填满不确定性。

## 正常工作的标志

- 你不同意某样东西。一场没有你推回的会话是一场你不需要的会话。
- 问题在几轮里到达，而不是一条长的滴流，而且后面的轮次明显建立在你早先说的东西上。
- 你结束在一个你没想到的地方，因为一个问题浮出了一个你一直在隐式做出的决策。
- 在结尾你能向一个不在场的人辩护每个选择。

## 常见问题

**我应该期待多少问题，我怎么知道它何时结束？**

数轮次，不数问题。四轮跨 46 个问题是一场普通会话。它在前沿为空时结束——每个分支被访问，没有东西被默默假设。

**它问了我两百个问题。哪里出错了？**

通常是范围太大。让 agent 先把工作拆成小块，然后访谈每一块。非常长的会话也漂移进**[傻区](https://www.aihero.dev/ai-coding-dictionary/smart-zone)**，在那里[上下文窗口](https://www.aihero.dev/ai-coding-dictionary/context-window)足够满，问题变得糟了。

**我能回到一次一个问题吗？**

能。把这加到你全局的 `CLAUDE.md`：

```
When grilling, ask one question at a time.
```

**如果我真心不知道答案呢？**

说出来。"我不知道"是一个真实的答案，而一个你无法回答的问题通常是该原型化而不是猜的信号。

**我在写规格前开始一个全新会话吗？**

不。会话的价值正是你刚构建的[上下文](https://www.aihero.dev/ai-coding-dictionary/context)。把同一个对话直接交给 [to-spec](https://aihero.dev/skills-to-spec)。

**模型重要吗？**

比大多数技能更重要。访谈依靠[模型](https://www.aihero.dev/ai-coding-dictionary/model)自己对系统如何坏的感知，所以给它你最好的。实现大多跟随上下文，能容忍更便宜的模型。

## 在流程中的位置

`grill-me` 是一个**独立项，你可以在任何地方、对任何东西运行它**。无状态正是让它可移植的东西：没有仓库、没有工作区、没有设置，而且不假设这个想法甚至与软件有关。人们把它指向商业决策、指向写作、指向接下来做什么——任何在他们脑子里坐不住的东西。

那个可移植性正是与 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 的全部区别，后者运行同样的访谈，但读一个代码库来对齐，并把学到的东西记录为 `CONTEXT.md` 和 ADR。两者都坐在 [grilling](https://aihero.dev/skills-grilling) 原语上；`grill-me` 是用户调用的前门，随身什么也不带。

如果你访谈的东西结果真是软件，你可以把同一个对话交给 [to-spec](https://aihero.dev/skills-to-spec)，继续进入构建流程——一个选项，不是技能的重点。当你不确定哪个流程合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 为你路由。
