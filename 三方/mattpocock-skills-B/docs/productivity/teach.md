## 它做什么

`teach` 把你运行它的目录变成一个常设的教学工作空间，并在多个[会话](https://www.aihero.dev/ai-coding-dictionary/session)中教你一个主题，以简短的、自包含的 HTML 课程。

它不教[模型](https://www.aihero.dev/ai-coding-dictionary/model)已经知道的东西。[参数化知识](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge)被当作不可信：在教之前，它去找高信任的资源，把它们记录在 `RESOURCES.md`，并在每节课程内部引用它们。另一个结构事实是它是[有状态的](https://www.aihero.dev/ai-coding-dictionary/stateful)——使命、资源、课程和你已学东西的记录都作为文件住在目录里，所以下一个会话从那些文件继续，而不是从上一个对话剩下的任何东西。

## 何时使用

你通过输入 `/teach` 调用它——[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不会自行触发它。

当学习本身就是项目时取用它：一门语言、一个框架、一个你刚加入的代码库、瑜伽、着色器、一个认证。它不是顺带解释一件事的工具。

| 你想要什么 | 取用什么 |
| --- | --- |
| 在几周内学习一个主题，带积累的会话 | `teach` |
| 一个想法在你已经在的会话内部被解释 | 就在那个会话里问 |
| agent 的最后一条消息因为它没落地而被重新推销 | [wait-what](https://aihero.dev/skills-wait-what) |
| 磨锋利你已经有的思考，而不是获取新材料 | [grill-me](https://aihero.dev/skills-grill-me) |
| 一个后台 agent 读[首要来源](https://www.aihero.dev/ai-coding-dictionary/primary-source)并给你留一份带引用的文档 | [research](https://aihero.dev/skills-research) |
| 在访谈中途出现的东西，不偏离[访谈](https://www.aihero.dev/ai-coding-dictionary/grilling)去学它 | [handoff](https://aihero.dev/skills-handoff) 到一个教学工作空间，然后在那里 `teach` |

## 前提条件

`teach` 构建一个目录而不是产出一个文件，而且技能假设每个工作空间一个使命——所以在你乐意为一个单一主题让出来的地方运行它。让它远离你正在工作的项目：一个独立的仓库是推荐的家，而不是一个全局 `~/.learnings/` 文件夹或工作项目本身。一个专门的仓库也让课程可以提交，那是团队分享它们的方式。

那个目录中积累的：

| 路径 | 它持有 |
| --- | --- |
| `MISSION.md` | 你为什么学这个。其他一切挂在它下面；如果它缺失，`teach` 做的第一件事是访谈你直到它不缺失 |
| `RESOURCES.md` | 它从那里教的经验证的来源，拆分为 Knowledge 和 Wisdom（社区） |
| `lessons/*.html` | 编号课程——教学的主要单元 |
| `reference/*.html` | 压缩的速查表、算法、词汇表：你实际回去的文档 |
| `learning-records/*.md` | 关于你已证明学到什么的 ADR 风格笔记，用于决定接下来教什么 |
| `assets/*` | 可复用组件——首先一个共享样式表——所以课程看起来像一门课 |
| `NOTES.md` | 你陈述的教学偏好 |

对那个列表的两个诚实说明。词汇表适合大多数主题，但技能发布的 `GLOSSARY-FORMAT.md` 是 `SKILL.md` 不再链接到的，所以你只有要求时才会得到一个（[issue #559](https://github.com/mattpocock/skills/issues/559)）。而且工作空间不总是在你预期的地方被创建——见下面的第一个问题，在它之上构建一门长课之前。

## 存储强度，不是流畅度

要用来思考的词是**存储强度**：长期保留，对比**流畅度**，即读时感觉像掌握、一周后就消失的即时回忆。`teach` 通过合意困难构建前者——检索练习、间隔、交错。知识先来，在那里困难是敌人，因为它吃你需要用于理解的工作记忆；然后技能通过一个紧凑的反馈循环被操练，在那里困难是工具。

两样东西引导你被教什么。**使命**——你想要它的具体现实世界理由——给每节课程立足点；没有它课程漂向抽象，没有东西决定接下来是什么。从使命和学习记录，`teach` 在你的**最近发展区**内挑下一课：足够挑战以付出努力，不要远到它变得不可学。

这也是技能推回而不是迁就的原因。一个需要**智慧**——现实世界判断——的问题得到一个尝试过的答案，然后是一个指向你可以在那里测试它的社区的指针。一个测验是一道闸门，不是一道手续：一个用户报告说了"多谢"而被告诉操练仍然在进行。

## 课程、参考和组件

**课程**是一个自包含的 HTML 文件，短到能在一口气内完成，绑到使命上，给一个具体的胜利。它引用它的来源，推荐一个值得自己去看的首要来源，并链接到兄弟课程和参考文档。

值得知道的拆分：课程很少被重访，参考文档被重访。所以一节课程的压缩精华——语法表、算法、姿势序列、词汇表——属于 `reference/`，而不是埋在引入它的课程里。

课程由 `assets/` 中的**组件**构建：样式表、测验小部件、模拟器、图表辅助。复用是默认。agent 在写一节课程之前读 `assets/`，从那里已有的构建，任何第二节课程可能用的新东西被写成一个组件而不是内联。共享样式表是每个工作空间挣到的第一个组件；它是阻止输出变成一堆一次性的东西。

## 常见问题

**它把文件放在哪？我的最后在 `~/.claude/skills`。**

一个真实的、开放的 bug（[#377](https://github.com/mattpocock/skills/issues/377)）。`SKILL.md` 同时用 `./` 指两个不同的根：`./MISSION-FORMAT.md` 和它的兄弟真的坐在已安装技能中 `SKILL.md` 旁边，而 `./lessons/`、`./reference/`、`./learning-records/` 和 `./assets/` 意在放你的目录。一个把第一种按技能的安装目录解析的 agent 会继续把第二种也解析到那里，把你的课程写进技能文件夹。在它之上构建之前检查第一节课程落在哪里，并在一开始时明确命名目录，而不是依靠"当前目录"被理解。

**我留在一个会话里，还是每节课程开始一个新的？**

三种方法都有效——留在同一个会话里、在一个新会话中重新调用 `/teach`、或在同一个文件夹中打开一个新会话。每节课程是它自己的调用。文件夹是连续性，不是对话。常见做法是在工作区中打开一个新会话说 `/teach next lesson for <topic>`。

**我怎么知道它没在教我它编造的东西？**

你无法，只凭技能的话。你读首要来源。`teach` 不够可靠到可以不检查就信任，而没有一个建立在 LLM 上的技能是。打底机制——`RESOURCES.md`、每节课程中的引用、每节课程一个推荐的首要来源——存在是为了让验证便宜，不是去掉它的需要。失败不是假设的：一个用户学 2x2 魔方被给了编造的、解不开的转动序列。对那种情况的诊断清单是模型、harness、努力——以及来源是什么。风险在带精确记号的程序性领域最高，在输出立即可验证的地方最低，比如你能运行的代码。

**正确的测验答案总是第一个选项。**

被几个人确认，在 Sonnet、Opus 和 GLM 上，仍然未修复。`SKILL.md` 现在要求每个答案字数相同，那杀掉一个不同的信号——正确的答案过去是唯一一个完整推理的——但对位置什么都没说。一个贡献者测试了一个针对位置的指令级修复，报告正确的答案仍然在九节课程中 33/33 次落在 A 槽（[#335](https://github.com/mattpocock/skills/issues/335)），它指向 `assets/` 中一个打乱的测验组件作为真正的修复，而不是更好的措辞。在那发布之前，把答案位置当作无意义的。你的 `assets/` 目录是你的，所以要求一个在渲染时打乱的组件是一个合法的本地修复。

**它假设我已经知道事情，用了它从不定义的术语。**

最常见的实质性抱怨。没有评估步骤：`teach` 从使命和学习记录推断你的水平，而在会话一里没有学习记录。一个在 wayfinder 管道内运行它的用户平白地说——"它从不做访谈来建立我的起点，所以它对我已经知道什么做了很多假设。"另一个报告课程依赖未定义的行话，还有一节针对他们硬件的课程，覆盖了硬件能做什么，却从不说什么不能。两件事有帮助：在第一条消息中陈述你的先验知识和你的缺口，并在课程没击中时大声纠正水平，因为纠正变成一个学习记录并引导下一节。一个显式的知识评估步骤是一个常设的功能请求（[#725](https://github.com/mattpocock/skills/issues/725)），不是已发布的行为。

**它做间隔重复吗，它知道什么时候停止教吗？**

第一个不，第二个不可靠地不。间隔和交错是课程被设计对其的原理，但没有什么安排一次复习，也没有 Anki 或日历集成——两者都是反复出现的请求。相关的缺口是退出标准：正如一个用户说的，`teach`"善于做下一节课程，但不那么善于知道什么时候停下、切换到复习或真实练习。"如果你想要复习或操练而不是新材料，要求它；技能不会自行提议那个切换。

**它只对代码有用吗？**

不，而非编码的用途是记录中较大的部分：韩语、日语正式语域、钢琴、吉他、桌游设计、OpenSCAD、电影情节、Azure 和 CCNA 认证、大学考试，以及八九岁的孩子得到关于逃生房和火蜥蜴的可打印书。技能中没有任何东西是编程特有的——使命、资源、最近发展区和操练在任何领域都以同样的方式工作。在代码内部，被报告最强的用途不是从零学一门语言，而是在一个陌生的代码库或一个新团队的栈中找方向。

**我应该用哪个模型运行它？**

没有规范答案，而报告差异很大。更高[推理努力](https://www.aihero.dev/ai-coding-dictionary/effort)被报告产生明显优于中等设置的课程。一个用户用 Codex 通过 Copilot CLI 运行同一个技能，得到一个 30 行 HTML 卡片，而 Claude Code 产生了一节完整课程。它在 Claude Cowork 中原样运行，受限于你的组织是否允许在那里添加技能。如果课程出来很薄，在重写你的提示之前换模型、[harness](https://www.aihero.dev/ai-coding-dictionary/harness)或努力。

## 正常工作的标志

- 它在一个空目录里做的第一件事是访谈你关于你为什么想要这个，而不是产出一节课程。
- `RESOURCES.md` 在课程之前被填满，而每节课程点名一个值得自己读的首要来源。
- 课程中的断言带链接出来。没有引用的课程是技能凭记忆在教。
- 一节课程花一口气，让你能做一件以前不能做的事。
- 在文件夹中打开一个新会话说"next lesson"会继续课程而不是重启它。
- `learning-records/` 增长，而课程停止重教你已经证明过的东西。
- 课程看起来像一门课——它们链接 `assets/` 中的样式表，而不是每个自带一个。
- 一个需要判断的问题让你被指向一个论坛、subreddit 或班级，而不只是一个答案。

## 在流程中的位置

`teach` 是一个**随时可取的独立项**。它不是构建链中的一步，与工程流程不共享工件；它拥有它的目录，在主题持续的时长里住在那里。

它唯一真正的邻居是 [handoff](https://aihero.dev/skills-handoff)，通过 Matt 命名为"如果我被访谈关于我不理解的东西怎么办？"答案的组配：不要停下访谈去学——`/handoff` 到一个教学工作空间，在那里用 `/teach` 学它，然后回去从停下的地方继续。附近的替代是 [research](https://aihero.dev/skills-research)，用于当你想要的是带引用的文档而不是课程和保留时。当你不确定哪个技能或流程合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 在整套之上为你路由。
