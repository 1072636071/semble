# CONTEXT.md 格式

## 结构

```md
# {上下文名称}

{一两句话描述这个上下文是什么以及为什么存在。}

## 语言

**订单（Order）**:
{一两句话描述该术语}
_避免_: Purchase, transaction

**发票（Invoice）**:
交付后发送给客户的付款请求。
_避免_: Bill, payment request

**客户（Customer）**:
下单的个人或组织。
_避免_: Client, buyer, account
```

### 术语分组

当术语自然形成内聚集群时，用子标题分组。如果所有术语属于一个内聚领域，平铺列表即可。

```md
## 语言

### 交易

**订单（Order）**:
客户发起的购买请求。
_避免_: Purchase, transaction

**退款（Refund）**:
对已支付订单的金额返还。
_避免_: Return, payback

### 参与者

**客户（Customer）**:
下单的个人或组织。
_避免_: Client, buyer, account

**商户（Merchant）**:
提供商品或服务的供应商。
_避免_: Seller, vendor
```

## 规则

- **要有主见。** 当同一概念存在多个词时，选最好的一个，将其他列在 `_避免_` 下。
- **保持定义紧凑。** 最多一两句话。定义它是什么，不是它做什么。
- **只包含此项目上下文特有的术语。** 通用编程概念（超时、错误类型、工具模式）不属于，即使项目大量使用它们。添加术语前问：这是此上下文独有的概念，还是通用编程概念？只有前者属于。

- **术语变更时保留痕迹。** 如果术语定义发生实质性变更，在术语旁用 blockquote 标注旧定义。变更流程见 SKILL.md「术语演化」。

  ```md
  **会员（Member）**:
  拥有特定权益的用户（含付费和邀请获得）。
  _避免_: VIP, subscriber

  > 变更自：付费用户 — 扩展为包含邀请获得的用户
  ```

## 单上下文 vs 多上下文仓库

**单上下文（大多数仓库）：** 仓库根目录一个 `CONTEXT.md`。

**多上下文：** 仓库根目录的 `CONTEXT-MAP.md` 列出上下文、它们的位置和彼此的关系：

```md
# 上下文映射

## 上下文

- [订购](./src/ordering/CONTEXT.md) — 接收和跟踪客户订单
- [计费](./src/billing/CONTEXT.md) — 生成发票和处理付款
- [履约](./src/fulfillment/CONTEXT.md) — 管理仓库拣货和发货

## 关系

- **订购 → 履约**: 订购发出 `OrderPlaced` 事件；履约消费它们开始拣货
- **履约 → 计费**: 履约发出 `ShipmentDispatched` 事件；计费消费它们生成发票
- **订购 ↔ 计费**: 共享 `CustomerId` 和 `Money` 类型
```

### 关系模式

上下文间关系使用以下模式描述：

| 模式      | 符号            | 含义                              |
| --------- | --------------- | --------------------------------- |
| 上游/下游 | `A → B`         | A 发出事件/数据，B 消费           |
| 双向依赖  | `A ↔ B`         | A 和 B 共享类型或同步调用         |
| 共享内核  | `A ⇔ B via X`   | A 和 B 共享显式定义的内核 X       |
| 防腐层    | `A →\| B`       | A 通过防腐层访问 B，隔离 B 的模型 |

示例：

```md
## 关系

- **订购 → 履约**: 订购发出 `OrderPlaced` 事件；履约消费它们开始拣货
- **履约 → 计费**: 履约发出 `ShipmentDispatched` 事件；计费消费它们生成发票
- **订购 ⇔ 计费 via Money**: 共享 `CustomerId` 和 `Money` 值对象
- **计费 →| 支付网关**: 计费通过防腐层访问外部支付网关，隔离其模型
```

技能推断适用哪种结构：

- 如果 `CONTEXT-MAP.md` 存在，读取它来查找上下文
- 如果只有根 `CONTEXT.md` 存在，单上下文
- 如果都不存在，在第一个术语被确定时惰性创建根 `CONTEXT.md`

当存在多个上下文时，推断当前话题与哪个相关。如果不清楚，询问。
