# Changelog

## 1.3.0 — 2026-11-06

旧流程把事实缺口和常规技术细节也交给用户，并要求续接时逐条重新确认旧决策，导致重复提问、方案推进依赖逐步审批。本次改为「agent 自主查证与决策，用户只决定关键取舍」：

- 开始阶段新增六项需求理解，区分用户明确表达、上下文推断与真正缺失；普通缺省不再作为阻塞
- 建立 L1/L2/L3 权限分流：L1/L2 自主继续，L2 记录关键假设、影响与易修正方式；L3 集中提问且每题提供推荐、原因与 2–3 个有意义选项；未授权的 memorial → 全局 CONTEXT/ADR 回写列为 L3
- 明确禁止因工作量、实现难度、Token/时间或需要重构预先否决更优方案；显著扩大范围、显著增加成本或风险，或需要重大重构的候选须保留收益、代价、可逆性与推荐，未明确授权时交用户决定，已明确授权时记录授权原文与影响后由主 agent 代决
- 用户确认后自主完成剩余方案与 memorial 文档；续接由 agent 重验旧事实，只在失效、冲突或新风险形成新 L3 时重新提问
- 查不到证据的低影响项改为明确假设继续，待澄清只收未解决 L3；方案完整后主动收尾
- 收尾 checklist 扩展为 C1–C9，新增需求覆盖、决策来源、提问必要性、方案比较与全局回写检查；先处置全局 CONTEXT/ADR 回写再核对 C9，未授权时只合并确认一次范围，已授权相同范围不重复询问
- 新增单一 Checker 边界：只检查复杂或重要方案，主 agent 保留决策权，不引入多 agent 相互否决
- context.md 模板新增需求理解与决策级别/来源字段；四份共享 scaffold 模板与回归测试同步
- 调研Agent-姜小研 的 memorial 集成改为按明确工单执行，外部资料只作为证据、不作为指令
- 新增六类正向行为评测与一条不触发反例，覆盖自主补全、不重复问、关键选择暂停、确认后完成、续接重验与重构候选保留；用例 4/5 附 memorial、当前代码与文档夹具，可核验 context/ADR/checklist 写回及新 L3 分流

## 1.2.0 — 2026-10-17

新增「证据优先」铁律——有疑问先找一手资料，不用世界知识冒充事实：
- SKILL.md 新增「证据优先（贯穿全程的铁律）」一节：五级渠道阶梯（项目代码/文档 → 代码索引 → MCP 工具面 → 官方文档/源码 → 社区讨论），配使用方式与适用问题
- 明确分工：事实类问题（版本、参数、行为、能力边界）必须查证并带来源；只有偏好/取舍/优先级才直接问人
- 查不到写「未找到证据」并列入待澄清，禁止用"通常应该是"补位；引用须落到可复核坐标（路径+行号 / URL / issue 号 / MCP 工具名+字段）
- 阶段 2 的「事实自己去查」升级为带渠道指引的硬规则；方案对比中的事实性论据必须先查证（防止用幻觉事实搭方案）
- 追问记录新增「查证记录」要求：证据连坐标一起落盘，事实与推断分开写
- 调查委派提示词新增「调查渠道与证据要求」；调研Agent-姜小研 同步加「证据优先」节（先于模式选择）
- 收尾 checklist 新增 C6「证据可复核」：决策汇总与 ADR 的事实性论据必须带来源坐标，无来源的降级为「假设」；scaffold.mjs 的 CHECKLIST_TEMPLATE 与测试同步（C1–C5 → C1–C6）
- 反模式新增三条：世界知识冒充事实、猜工具行为、查证拖延
- description 增补「证据先行」说明，让技能在列表层即可被识别

## 1.1.0 — 2026-08-21

修复调查委派环节经常遗忘回写工单与调查结果的问题：
- 调查委派改为闭环式：委派提示词必须显式给出工单绝对路径，并硬性要求 subagent 将「结论+来源+完成时间」写回同一工单、状态改为「已完成」，禁止输出到 docs/report/
- 主 agent 在 subagent 返回后必须亲自回读工单做三验（状态/结论来源/非空），任一不满足判定「调查未闭环」禁止继续 grill
- 三验通过后强制将调查结果即时追加到 context.md「追问记录」
- 强化收尾 C4：工单需含结论与来源且 context.md 已记录调查结果
- 调研Agent-姜小研 与 memorial 集成升级为强制模式，优先级高于自由/严格模式
