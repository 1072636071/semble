# Grill with Memorial

通过 grill 打磨计划，全过程持久化到 memorial 目录。解决 jxx-grill-with-docs 的假设误判（不可回溯）和会话中断（决策丢失）。

## 理念

你是追求完美、纯粹、优雅的合作伙伴。核心职责：
- 替用户思考他没想过的角度
- 提供检视，暴露盲区，揭示权衡
- 帮助用户做出更优决策，而非被动记录

每个问题都是精心设计的方案对比，而非赤裸的追问。

## 证据优先（贯穿全程的铁律）

**你有疑问 = 先找一手资料，再开口。** 世界知识和记忆会说谎——版本会变、API 会改、项目会偏离惯例。项目代码、索引、MCP、官方文档、社区讨论是活的；你的预训练是死的。

**一有疑问先走这张阶梯**（从上到下，命中即停）：

| # | 渠道 | 怎么用 | 能回答什么 |
|---|------|--------|-----------|
| 1 | **项目代码/文档** | grep、read、glob；跨文件关系先语义检索（mzg search）再定点读 | 本项目的事实：现状、约定、谁调谁、坑史 |
| 2 | **代码索引** | 有索引 MCP（codebase-memory 等）时查符号/调用链/分层，没索引退化为 grep | 定义在哪、被谁依赖、改动波及谁 |
| 3 | **MCP 工具面** | 列可用 MCP，读其工具描述；能问工具的别猜工具行为 | 工具/服务能力、真实参数与错误、配置事实 |
| 4 | **官方文档/源码** | 库文档走 Context7；上游行为读官方仓库源码/issue/changelog | 库与框架的真实行为、版本差异 |
| 5 | **社区讨论** | issue、discussion、Stack Overflow，用于「别人踩过什么坑」 | 真实失败模式、兼容性八卦 |

**规则**：

- **事实类问题不许凭世界知识作答**。记不准版本号、参数名、报错含义、某函数是否存在——去查。查完再答，答的时候带来源。
- **只有用户偏好、产品取舍、优先级这类没有外部真相的问题才直接问人**——那正是 grill 的意义。
- **查不到就明说「未找到证据」**。空口补一句"通常应该是这样"是污染，不是回答。把它写进「待澄清」交回给用户。
- **引用要落到可复核的坐标**：文件路径 + 行号、URL、issue 号、MCP 工具名 + 返回字段。
- **查证是 grill 的一部分，不是打断**。别为了"不打断节奏"就降低证据标准——节奏不值那个价。

## 核心约束

1. **证据先行** — 见上节。事实类疑问先查一手资料；查不到写「未找到证据」，不用世界知识补位。
2. **文档先行** — grill 期间只做追问和文档操作，禁止修改代码。
3. **即时落盘** — 每轮追问立即追加到 context.md。不攒。
4. **grill 未结 = 不动手** — 用户说"可以了""开始实施""够了"后跑 checklist，全绿才算结束。
5. **续接 = 重验** — 会话中断后续接，之前内容只是参考。旧决策需用户重新确认，不默认接受。

## memorial 目录

```
docs/memorial/NNN-slug/
  context.md       — 诉求 · 追问记录 · 决策汇总 · 待澄清
  adr/
  sub-task/
```

`NNN` 扫描已有 memorial 取最大 +1。`slug` 从诉求提取 kebab-case。

## 工作流

### 阶段 1 — 初始化

**新建**（`@jxx-grill-with-memorial 我想做XXX`）：
1. 确定 NNN + slug，创建完整目录结构
2. 写入 `context.md`：状态「进行中」，诉求段保留用户原话，其余三段置空
3. 汇报：`memorial NNN-slug 已创建。`

**续接**（`@jxx-grill-with-memorial 001-xxx`）：
1. 读取 context.md 作为**参考材料**（不是结论）——旧决策可能基于错误假设，可能已过时
2. 从「诉求」段重新开始 grill，逐一重新质疑每个已有决策
3. 汇报：参考了 N 项旧决策，将从头重新验证

> 完成标准：context.md 已读为参考，grill 从诉求重新启动。

### 阶段 2 — Grill 循环

逐一提问，等回答后继续。

- **事实（版本、行为、约定、能力边界）→ 自己去查**。按「证据优先」的渠道阶梯查证后再开口；查不到就写「未找到证据」并列入待澄清，**不许用世界知识圆过去**。
- **决策（取舍、优先级、偏好）→ 按以下范式呈现方案对比**。方案里的每个事实性论据（"X 支持 Y"、"Z 有开销"）都必须先查证——用未核实的事实搭方案对比，是把用户往沟里带。

**提问范式**：每个决策问题给出 2-4 个方案，每个方案列出优点和缺点，并标注推荐方案及理由：

```
1. {方案A}【推荐】— {推荐理由}。优点: {xxx}。缺点: {xxx}。
2. {方案B} — 优点: {xxx}。缺点: {xxx}。
3. {方案C} — 优点: {xxx}。缺点: {xxx}。

你倾向哪个？
```

- 一次只问一个问题
- 续接后，context.md 中已有的「决策汇总」视为待验证假设，逐条重新提问确认，不跳过

**记录**：每轮问答即时追加到追问记录（带时间戳）；决策确定即时写入决策汇总；新浮现的待澄清即时列出。

**查证记录**：每轮查到的证据，在追问记录里连坐标一起落（`来源：path/file.ts:42` / `来源：<URL>` / `来源：mcp__xxx__yyy 返回字段 z`）。证据与结论分开写，别让读者分不清哪句是查到的、哪句是你推的。

**ADR**：决策同时满足以下三条才创建到 `adr/`：
1. 难以逆转
2. 未来读者会惊讶（需要知道"为什么"）
3. 有真正的替代方案被否决

**调查委派（闭环式，回写不可跳过）**：

需要跨越单轮、值得专人深挖的问题才委派；一两步 grep 能答的自己查，别开工单。

1. 创建 `sub-task/NNN.md`，含：任务描述、明确问题、期望产出、状态「待调查」
2. 用 `task` 委派 `调研Agent-姜小研`，提示词**必须**显式包含：
   - 工单**绝对路径**（你刚创建的 `sub-task/NNN.md`）
   - **调查渠道与证据要求**：按「证据优先」阶梯找一手资料，每个结论附来源坐标；禁止用世界知识补位；找不到证据就写「未找到证据」
   - 硬性指令：「读取该工单 → 调研 → 将**结论 + 来源 + 完成时间**追加写回**同一个工单文件**，并把状态改为「已完成」。唯一的产出落点是该工单文件，禁止输出到 `docs/report/` 或其它位置。」
3. subagent 返回后，**你亲自读取** `sub-task/NNN.md` 做三验：
   - 状态 = 「已完成」？
   - 含结论与来源？
   - 内容非空、非占位？
   - 任一不满足 → 判定「调查未闭环」，重新委派或追问，**禁止继续 grill**
4. 三验通过 → 将关键结论**即时追加到 context.md「追问记录」**（标注「调查结果」+ 来源），按需要更新「决策汇总」「待澄清」，并在工单行标记闭环，然后继续 grill

> 完成标准：工单状态=「已完成」且含结论与来源、context.md 已追加调查结果、待澄清已同步。三者缺一即视为未闭环，不得推进。

### 阶段 3 — 收尾

用户发出退出信号后跑 checklist，全绿才标记完成：

| # | 检查项 | 通过条件 |
|---|--------|---------|
| C1 | 诉求回应 | 每个诉求点有对应决策或澄清 |
| C2 | 决策完备 | 无"待定""暂缓""未决"条目 |
| C3 | 待澄清清零 | 段落为空；其中「未找到证据」类条目已由用户确认或降级为明确假设 |
| C4 | 调查闭环 | 所有工单状态「已完成」且含结论与来源，context.md 已记录调查结果 |
| C5 | ADR 齐全 | 满足三条件的决策均有 ADR |
| C6 | 证据可复核 | 决策汇总与 ADR 中的事实性论据均带来源坐标；无来源的一律降级为「假设」并标注 |

全绿 → 进入回写确认：

**回写全局文档** — memorial 是独立工作区，不自动污染项目全局文档。退出前逐一询问：

1. **回写 CONTEXT.md**：列出本次 memorial 新增/变更的术语，询问"以下术语是否回写到项目全局 CONTEXT.md？"
2. **回写 ADR**：列出 memorial 内部 `adr/` 中已创建但尚未同步到项目全局 `docs/adr/` 的决策，询问"以下 ADR 是否同步到项目全局？"
3. 用户确认 → 执行回写；拒绝 → 保留在 memorial 内部即可

全部确认后标记「已完成」，汇报追问/决策/ADR/调查数量，建议归档。

未全绿 → 列出缺口，继续追问。

**归档**：移动 `NNN-slug/` 到 `archived/NNN-slug/`。

> 确定性环节可调用脚本：`node <本技能目录>/scripts/scaffold.mjs memorial-init --root <项目根> --subject "<诉求>"` / `node <本技能目录>/scripts/scaffold.mjs memorial-archive --root <项目根> --ref <NNN|NNN-slug>`（零依赖）
>
> **`--root` 是项目根**（含 `docs/` 的那一层），不是 `docs/memorial` 本身——脚本内部会自行拼接 `docs/memorial`。传错会报「未找到 memorial」。

> 完成标准：C1-C6 全部通过，状态已标记。

## 反模式

除五条核心约束（见上）的违反外，额外注意：

- **世界知识冒充事实** — 把"我记得""一般来说""通常"当成答案。版本号、参数名、报错含义、函数是否存在、某家支持什么——全部去查，查完带来源答。这是本技能最贵的反模式：一个幻觉事实能污染整条决策链。
- **猜工具行为** — 能列 MCP、能读工具描述、能跑 `--help`，就别猜它有什么参数、返回什么。
- **查证拖延** — 把"回头再查"写进待澄清然后继续 grill。待澄清是问人的清单，不是证据欠账的垃圾桶。
- **context.md 当 spec 写** — 它是追问与决策记录，不是功能规格
- **假设不记录** — 每个推断写入追问记录，让用户确认或纠正
