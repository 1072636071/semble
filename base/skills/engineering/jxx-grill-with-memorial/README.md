# jxx-grill-with-memorial

通过 grill 把用户的真实目标转成有证据、可验收的完整方案，并将需求理解、分析、决策与调查持久化到 memorial。主 agent 自主查证和完成具体设计，只把 L3 关键取舍交给用户。

**核心约束：证据先行，文档先行，grill 期间不改业务代码。** 每轮立即更新 memorial；用户确认后不再重复询问，方案完整且无未解决 L3 时主动收尾。

## 何时使用

当用户想讨论方案、梳理需求、澄清设计或做技术决策时使用。适合需要完整追溯和断点续接的复杂设计讨论。

触发词：memorial、奏报、grill 方案、讨论设计、梳理需求、分析需求。

## 工作流

1. **初始化与需求理解** — 创建 memorial，填写核心目标、使用场景、明确要求、约束、明确偏好与验收标准；区分用户明确表达、上下文推断和真正缺失。续接时由 agent 重验旧事实，不逐条重新确认旧决策。
2. **查证、决策与文档** — L1 常规细节与 L2 易修正事项由 agent 自主决定；L3 关键事项合并提问，每题给推荐、原因与 2–3 个选项。确认后自主完成剩余方案与 memorial 文档。
3. **主动收尾** — 先处置全局回写，再按 C1–C9 检查需求覆盖、决策分流、提问必要性、方案比较、证据、调查与 ADR。确有全局 CONTEXT/ADR 回写内容且未授权时只合并确认一次范围；已授权相同范围时记录授权原文与影响后直接回写，不重复询问；没有内容不询问。

不得因工作量、实现难度、Token/时间或需要重构预先否决更优方案。更优但显著扩大范围、显著增加成本或风险，或需要重大重构的方案保留比较，记录收益、代价、可逆性与推荐；未明确授权时作为 L3 交用户决定，已明确授权时记录授权原文与影响后由主 agent 代决。已授权的小重构仍自主处理。

复杂调查使用 sub-task 工单闭环回写。复杂或重要方案至多使用一个 Checker，主 agent 保留决策权，Checker 不直接问用户。

完整判据见 [SKILL.md](SKILL.md)。
