# criterion 基准与收敛判定

基准不可信，后面所有轮次都是噪声上的折腾。这份文档只回答两件事：怎么让 Rust 的基准数字可信，什么时候该停。

## 工具

| 工具 | 用途 | 注意 |
|---|---|---|
| `criterion` | 主基准。跨轮次对比、自带统计判定 | 默认工具，所有优化轮都用它 |
| `cargo bench -- --save-baseline <名>` / `--baseline <名>` | 固化并对比基线 | 每轮存一个 baseline，名字带轮次 |
| `iai-callgrind` | 指令数基准（确定性，不受噪声影响） | 适合 CI；与 criterion 结论互补 |
| `hyperfine` | 端到端 CLI 耗时 | 只用于整程序/CLI 场景，不替代库内基准 |
| `cargo flamegraph` / `perf` | 定位热点 | 只用来找方向，不用来度量 |

不要手搓计时器。自造 `Instant::now()` 循环既没有预热也没有统计判定，是作弊的温床，也难审计。

## criterion 使用要点

- **预热与采样**：默认配置通常够用；一旦动了 `sample_size` / `warm_up_time` / `measurement_time`，把它写进基线记录——下一轮的对比必须同参数。
- **`black_box`**：输入和输出都要过 `std::hint::black_box`，否则编译器会把整个循环优化掉，数字会「快得离谱」。这也是判「34,500 倍」这类异常值的第一个检查点。
- **输入生成**：固定随机种子；数据生成写在 benchmark 里，不要依赖外部文件，否则换机器就不可复现。
- **分组**：用 `criterion_group!` 按「规模 × 复杂度」分组，组名就是报告里的行名。
- **独立**：某条基准开了缓存，下一条就吃到了不属于它的收益。共享状态要么每轮重建，要么显式禁用。

## 矩阵

至少两维：**规模**（小 / 大）× **复杂度**（简单 / 复杂）。小数据集的优化不一定适用于大数据集，反之亦然。原文的初始提示就是这么定的。进阶要求：让模型自己设计多样、反常、对抗性的输入，而不是笼统的「最大 100000×768」。

## 环境

- 串行跑。并行跑出来的数字一律作废（`cargo bench` 默认会并行跑多个 benchmark，必要时 `-- --test` 之类的手段不合适，直接按 group 单个跑）。
- 同机、同负载、同 `RUSTFLAGS`、同 `[profile.release]`。几个「同」缺一个，跨轮比较就失效。
- 记录 CPU 型号、核数、是否超线程、内存、`rustc -V`，写进报告。
- 关掉后台负载：浏览器、索引进程、同步盘。

## 噪声

同代码两次跑差异超过 10% ⇒ 先解决噪声，再谈优化（`ERR_BENCH_UNSTABLE`）。常用手段：

1. 固定 CPU 亲和（`taskset` / `start /affinity`）。
2. 关超线程，或至少固定到物理核。
3. 拉长单次测量时间，减少计时器相对误差。
4. 用 `iai-callgrind` 复核：指令数不受频率和调度影响，能直接判定「是真快还是噪声」。
5. 检查后台：杀浏览器、杀索引进程。

## convergence

什么时候停：

- 连续两轮提升小于 **3–5%**，且这个幅度在统计上不显著（criterion 会在输出里标 `Change within noise threshold`）。
- 同时代码净增明显不成比例——为了 3% 加了两千行，收益不抵维护成本。
- 再往下不是「优化」而是「换算法」了，那算新一轮任务，不是这一轮迭代。

收敛后仍然可以做的两件事：`breakthrough` 轮（要求根本性重写）与 `refactor` 轮（砍 SLoC，常带来意外提速）。两者都要重新过基准与质量闸。

## 质量闸

速度与质量在机器学习这类领域是硬权衡。原文的顺序是**先做快、再做对**：先拿到速度，再拿已知正确的实现做对照，把质量修回来，同时给速度损失设上限（默认 5%）。

对照物怎么选：

- 有权威实现（`umap-learn`、`xgboost`、`umap-rs`）→ 直接比拼数值与质量指标。
- 没有 → 用上一版 crate 或黄金样本，逐样本比输出。
- 对外发布的 crate → 把质量对比写进 `examples/` 或 notebook，作为可复跑的凭证。

## 报告模板

```
baseline: cargo bench -- --save-baseline base @ <机器>, rustc <版本>  中位 <x> ms
result:   cargo bench -- --baseline base                         中位 <y> ms   → <x/y>× 加速

| benchmark | baseline | result | multiple | verdict |
|-----------|----------|--------|----------|---------|
| small-1k  | 2.1 ms   | 1.4 ms | 1.50×    | kept    |
| large-1M  | 812 ms   | 790 ms | 1.03×    | noise   |

cheat-audit: passed（benches/ 与 tests/ 的 diff 为空）
quality:     <指标> 与参考实现差 <z>%，速度损失 <5%
```
