# 改善代码库架构

发现架构摩擦并提出**深化机会**——将浅模块变为深模块的重构。目标是可测试性和 AI 可导航性。

此命令以项目的领域模型为依据，建立在共享设计词汇之上：

- 运行 `/jxx-codebase-design` 技能获取架构词汇（**模块**、**接口**、**深度**、**接缝**、**适配器**、**杠杆**、**局部性**）及其原则（删除检验、"接口是测试面"、"一个适配器 = 假想接缝，两个 = 真正接缝"）。在每个建议中精确使用这些术语——不要漂移到"组件"、"服务"、"API"或"边界"。
- `CONTEXT.md` 中的领域语言为好的接缝（seam）命名；`docs/adr/` 中的 ADR 记录此命令不应重新争论的决策。

## 流程

### 1. 探索

先阅读项目的领域词汇表（`CONTEXT.md`）和你涉及区域的任何 ADR。

然后派发一个子 agent 遍历代码库——如果你的 harness 有只读探索 agent，就用它。不要遵循死板的启发式——有机地探索并注意你体验到的摩擦：

- 理解一个概念是否需要在许多小模块之间来回跳转？
- 模块在哪里是**浅的** — 接口几乎和实现一样复杂？
- 纯函数是否仅仅为了可测试性被提取，但真正的 bug 隐藏在它们如何被调用中（没有**局部性（locality）**）？
- 紧耦合的模块在哪里跨接缝泄漏？
- 代码库的哪些部分未测试，或难以通过当前接口测试？

对你怀疑是浅的任何东西应用**删除检验（deletion test）**：删除它会集中复杂性，还是只是移动它？"是的，集中"就是你要的信号。

### 2. 以 HTML 报告呈现候选者

> 确定性环节可调用脚本：`node base/scripts/report-flow.mjs report-html --cards '<json>' --temp`（零依赖）

将自包含的 HTML 文件写入操作系统临时目录，使仓库中不留下任何东西。从 `$TMPDIR` 解析临时目录，回退到 `/tmp`（或 Windows 上的 `%TEMP%`），写入 `<tmpdir>/architecture-review-<timestamp>.html` 使每次运行获得新文件。为用户打开——Linux 上 `xdg-open <path>`，macOS 上 `open <path>`，Windows 上 `start <path>`——并告诉他们绝对路径。

报告使用 **Tailwind via CDN** 进行布局和样式，**Mermaid via CDN** 用于图表（当图形/流程/序列可靠传达结构时）。Mermaid 与手工 CSS/SVG 视觉混用——当关系是图形状的（调用图、依赖、序列）时用 Mermaid，当你想要更具表现力的东西（体量图、截面、折叠动画）时用手工 div/SVG。每个候选者有一个**前后可视化**。要视觉化。

对于每个候选者，渲染一张卡片：

- **文件** — 涉及哪些文件/模块
- **问题** — 当前架构为什么造成摩擦
- **方案**——会改变什么的通俗描述
- **收益** — 用局部性和杠杆效应解释，以及测试如何改善
- **前后图**——并排，自定义绘制，展示浅和深
- **推荐强度** — `强烈`、`值得探索`、`试探性` 之一，渲染为徽章

报告末尾有**首要推荐**部分：你会先处理哪个候选者以及为什么。

**用 CONTEXT.md 词汇表达领域，用 `/jxx-codebase-design` 词汇表达架构。** 如果 `CONTEXT.md` 定义了"订单"，说"订单接收模块"——而不是"FooBarHandler"，也不是"订单服务"。

**ADR 冲突**：如果候选者与现有 ADR 矛盾，仅当摩擦足够真实值得重新审视 ADR 时才提出。在卡片中清楚标记（如警告标注：_"与 ADR-0007 矛盾——但值得重新审议因为…"_）。不要列出 ADR 禁止的每个理论性重构。

见 [HTML-REPORT.md](HTML-REPORT.md) 获取完整 HTML 脚手架、图表模式和样式指导。

先不要提出接口。文件写入后，问用户："你想探索哪一个？"

### 3. grill 循环

用户选择候选者后，运行 `/jxx-grilling` 技能与他们一起遍历设计树——约束、依赖、深化模块的形状、接缝后面是什么、哪些测试存活。

附带操作在决策成型时内联发生——运行 `/jxx-domain-modeling` 技能保持领域模型最新：

- **用不在 `CONTEXT.md` 中的概念命名深化模块？** 将术语添加到 `CONTEXT.md`。如果文件不存在则惰性创建。
- **在对话中锐化模糊术语？** 立即更新 `CONTEXT.md`。
- **用户以支撑性理由拒绝候选者？** 提供 ADR，措辞为：_"要我将其记录为 ADR，使未来的架构 review 不再重新建议它吗？"_ 仅当理由确实会被未来探索者需要以避免重新建议相同东西时才提供——跳过短暂的理由（"现在不值得"）和显而易见的理由。
- **想为深化模块探索替代接口？** 运行 `/jxx-codebase-design` 技能并使用其设计两次并行子 agent 模式。
