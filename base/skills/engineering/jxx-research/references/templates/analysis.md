# analysis — 分析报告

用于架构评估、代码质量分析、性能分析、安全审查。

## 标准节

| 节 | 必填 | 内容 |
| -- | ---- | ---- |
| **摘要** | 是 | 分析对象、分析方法、主要结论、风险等级 |
| **实证快照** | 是 | 按 [strict-mode](../strict-mode.md) 记录日期、commit、实际分析的模块/文件/服务与环境 |
| **当前状态** | 是 | 架构/代码的现状描述（事实，非评价） |
| **关键发现** | 是 | 逐条列出发现：问题位置、严重程度、影响面 |
| **验证记录** | 是 | 只列实际执行命令及 cwd、退出码、实际输出/产物；无命令则写明 |
| **未验证边界** | 是 | 未检查的模块、平台、场景与假设 |
| **未验证建议** | 是 | 未执行的命令逐条标「未执行」并写明预期用途；不得编造退出码、输出或性能数字 |
| **风险评估** | 否 | 按严重程度分级的风险清单，含触发条件和影响 |
| **改进建议** | 是 | 具体可执行的改进方案，按优先级排列 |
| **参考来源** | 是 | 代码文件、配置、文档及其来源角色与支撑的结论 |

## 示例场景

- "分析当前项目的架构是否支持多租户"
- "审查 src/api/ 目录的代码质量"
- "评估首页加载性能瓶颈"
