# Changelog

## 1.6.0 — 2026-10-23

**工单「后续修订」改指 ticket-flow**：状态 / 标题 / 标签 / 认领用写腿（`--set status=… --set title=… --set labels=a,b`）、打卡与评论附 `--comment`，一条命令完成「改本地 md + 推服务器」；验收点/正文段落修订改完 md 后跑只读腿 `--file <单条工单md>` 收敛。写腿不 create，新建工单仍走批量 `ticket-uplink` / `jxx_ticket_push` / `create`（ticket_no + id + version 留痕口径不变）；项目无该 CLI 时回退 MCP 双写（`get` 最新 `version` → `update`），批量 push 的 id 核对纪律不变。

## 1.5.0 — 2026-10-23

**覆盖闸：生成后自检是否完全覆盖「用户诉求 / 决策 / PRD」**（防少做、防降低标准）：

- 权威规范新增 §八「覆盖闸」：三源分开枚举（用户原话诉求 / 决策与明确不做 / PRD 逐条），每条一个判定且只有四种（`covered` / `gap→已补` / `rejected` 须用户确认原话 / `defer` 须有去向）；「独立关闭」口径——只相关、只主路径、只前置条件一律判 gap；落 `map.md` 的 `## 覆盖闸` 表（PRD 源复用 §一 覆盖矩阵，不写第二份）。
- 反作弊条款（§8.4）：两条诉求并进一条 AC、改弱措辞再判 covered、用「不适用」顶替覆盖判定、靠改判消除缺口、零 `gap→已补` 而初检记录缺失——出现即不合格。
- 本技能新增第 4b 步「覆盖闸（发布前硬闸，不可跳）」：定稿后落盘前自检，gap 归零后把清单并入第 4 步询问给用户过目（`rejected` 只能由用户给），补过工单回第 5 步重跑 `--strict`。
- 第 4 步询问清单的「覆盖矩阵空洞」条改为「覆盖闸空洞」，覆盖诉求 / 决策 / PRD 三源。
- 机械校验同步：`ac-audit.mjs --strict` 查 `## 覆盖闸` 节存在、判定取值合法、未处置 gap 为 0（§七 与 §八 同批）。

## 1.4.1 — 2026-10-21

文档侧收敛：`<ac-closure-rules>` 删掉覆盖清单与禁词的逐条复述，只留动作句（整块 6 行）；写死的「12 类」全部改成「覆盖清单（14 类，见规范 §一）」。原因：判据正文只在权威规范存在一份，复制必漂移。

生成器侧同步（复审高危项「生成即违规」）：`scripts/issue-flow.mjs` 的 `to-tickets` 缺省验收段从 `- [ ] 验收标准 1 / 2` 改为与 `<local-issue-file-template>` 逐字一致的 4 条示例行（主路径 / 错误路径 / 回归 / 负向，带 `AC-<n>`、`[类别]` 与 `验证:机器 <用例名|命令>` 载荷），并补 `**AC 覆盖声明：**` / `**处理步骤：**` 两行（验收标准之后、`## 评论` 之前）；`to-spec` 的 PRD 骨架补 `## 验收点（AC）` 节与 4 条草案行，`Status:` 行改粗体 `**Status:** ready-for-agent`；生成动作后打印 `下一步自检：node <脚本目录>/scripts/ac-audit.mjs <功能目录> --strict`。实测新生成工单跑 `ac-audit` 退出码 0，三份副本 0 漂移，`issue-flow.test.mjs` + `copies-parity.test.mjs` 32/32 通过。

## 1.4.0 — 2026-10-21

**验收点闭包：工单必须覆盖全部验收点（防漏实现 + 防劣化）**：

- 新增权威规范 `references/acceptance-criteria.md`（唯一源，随技能分发）：覆盖清单（14 类）、单条 AC 格式与禁词、覆盖矩阵、劣化门禁 5 条、审查逐条判定口径（met / partial / missing）、反模式速查。本技能与其他工单技能一律 pointer 引用，不复制正文。
- 第 3 步「起草垂直切片」加 `<ac-closure-rules>`：每张工单单独立 AC 闭包；改代码的工单必须有 `[回归]` 与 `[负向]` AC；PRD 每条用户故事映射 ≥1 条 AC，矩阵落 `map.md` 的 `## AC 覆盖矩阵`。
- 工单模板改为带编号 AC：`- [ ] AC-n [类别] 当 … 时，… 则 … —— 验证:机器/人工 …`，并新增 `**AC 覆盖声明：**` 与 `**处理步骤：**` 两行。
- 第 4 步询问清单加两条：抽 2–3 条 AC 反问「这样写，桩能过吗」；检查覆盖矩阵空洞。
- 第 5 步发布前新增形式硬闸 `scripts/ac-audit.mjs --strict`（编号连续唯一 / 验证方式标注 / 禁词 / 类别覆盖 / 回归或负向 / 覆盖矩阵），退出码非 0 不得发布。
