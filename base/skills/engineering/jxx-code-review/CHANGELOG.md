# Changelog

## 1.3.1 — 2026-10-21

文档侧收敛：0c 加「先跑 ac-audit 机械闸」并把硬问题计入发现项；劣化门禁表收敛为「项 | 命令」（公共符号与行为基线各给可执行命令），判据指向规范 §四；置 `done` 前置补「AC 覆盖表非空且无未审」，`done` 由执行者置、审查者只报告。原因：判据正文只在权威规范存在一份。

## 1.3.0 — 2026-10-21

审查从「找问题」补上「对验收点」：新增步骤 0c 逐条 AC 判定与劣化门禁，两条执行模式共用、不可跳过。起因是执行侧少做 / 假做 / 劣化三类失效在审查端没有机械出口——审查能说「代码不错」，却答不出「AC-5 到底做了没有」。

- **新增步骤 0c「验收点逐条判定」**（置于 0b 之后，两模式共用）：定位 AC 源（commit 引用 → 用户给定路径 → `.scratch/` 匹配），逐条输出 `met` / `partial` / `missing` + 审查者**自己取的证据**，严禁引用执行者的勾选与自述（宪章一、三）；`partial` / `missing` 一律发现项，功能缺失 High；「AC 勾了但代码是桩 / 硬编码 / `TODO` / 空实现」单列 High；无 AC 可核对时明报「未审：无验收点可核对」并指出属生产侧缺陷，不得静默通过（宪章二）。
- **0c 内附劣化门禁五条**（回归全量绿 / 公共符号无未声明删除与签名变更 / diff 无新增 `skip`·`todo`·`only`·`as any`·`!`·放宽阈值 / lock 文件无未授权依赖 / 行为基线一致），每项给判据 + 取证命令；判据正文 pointer 到 `../jxx-to-tickets/references/acceptance-criteria.md` §四，**不复制规范**（复制必漂移）。
- **委托模式 D4 与内置模式步骤 4 同步**：spec 维度 / spec 子 agent 提示均要求输出逐 AC 判定表（AC 编号 / 类别 / 判定 / 证据），spec 维度不再以「看起来实现了」结案。
- **报告格式**：`## AC 覆盖` 小节排在 `## 标准` / `## spec` / `## 规则` **之前**（表格列 = AC 编号 | 类别 | 判定 | 证据坐标，表下 `met N · partial N · missing N`），两条模式都出。
- **步骤 6 置 `done` 加前置**：AC 覆盖表无 `partial` / `missing`；`missing` 属功能缺失，不许用「用户认可」跳过。

## 1.1.3 — 2026-09-29

新增**步骤 0b「外部契约取证」固定动作**（置于模式分流之前，委托/内置两模式共用）：变更消费了不在本仓的契约（HTTP/RPC 接口、字段名、路由、DB schema、消息格式，真源常在另一仓或另一分支，如 fork 仓的 `fork/<卡id>`）时，必须到真源只读取证并写出取证坐标（仓 + 分支 + SHA + `文件:行`），禁止凭本仓命名/注释/测试桩/PRD 表格反推契约；取不到真源按 spec 维度 Medium 以上发现项报告，不得默认通过。

- 起因：双仓交付（前端/MCP 面在主仓、服务端在 fork 仓分支）的审查里反复出现「断言后端返回某字段却没证」，以及把 MCP 工具名当 REST 路径的误名事故。
- 委托模式 D4 的 spec 维度与内置模式步骤 4 的 spec 子 agent 提示各加一条**回指 0b**（要求把取证坐标随提示下发、逐条核对「本仓断言 ↔ 对方真源实现」）。
- 与工单卡模板新增的「外部契约」节配对：卡面留空而实现明显消费外部接口 ⇒ 报「契约坐标缺失」；两处判据同一份措辞，防漂移。

## 1.1.2 — 2026-09-17

模式探测改为**直接运行二进制自证存在**，彻底规避 shell 写法陷阱：

- 步骤 0 的探测统一为 `ocr --version`（bash 与 PowerShell 语法一致），不再依赖 `which` / `command -v` / `where`，也不含 stderr 重定向。
- 修掉曾导致误降级的混写陷阱 `where ocr 2>$null; command -v ocr 2>$null` —— bash 下 `$null` 展开为空触发 `ambiguous redirect` 致整条命令不执行；PowerShell 下 `where` 是 `Where-Object` 别名、`command -v` 不存在 —— 两者都零输出，被误判为「未检测到 ocr」而错误降级为内置模式。
- 全量同步修复到所有厂商安装目录（8 处），清除遗留的 v1.1.0 旧副本。

- 步骤 0 探测从 `which ocr || command -v ocr || where ocr` 改为 POSIX 优先 + 运行时验证，并补充 PowerShell 变体与 shell 陷阱警示。（1.1.2 进一步简化为 `ocr --version`。）

## 1.1.0 — 2026-09-17

新增**委托模式**（Delegation Mode）作为内置执行模式之一：

- 流程新增「步骤 0：选择执行模式」——按环境是否安装 `ocr` CLI 自动选择。
- **委托模式**（检测到 `ocr` 时启用）：**3 维度审查** —— 标准 + spec + **规则**。OCR 负责确定性工程（文件筛选、规则解析、范围判定），宿主 Agent 用自身 LLM 执行实际审查，OCR 端无需配置 LLM。流程为 `ocr delegate preview` → `ocr delegate rule` → git 取 diff → 逐文件 3 维度审查 → 按 Critical/High/Medium/Low 分级报告。
- **内置模式**（未检测到 `ocr` 时降级）：**2 维度审查** —— 沿用原有双轴（标准 / spec）并行子 agent 流程，无「规则」维度。
- 「规则」维度是 OCR 的工程产出，没有 `ocr` 时该维度不存在，故降级为 2 维度。
