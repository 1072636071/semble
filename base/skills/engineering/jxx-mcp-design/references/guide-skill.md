# MCP 配套引导技能（披露式）

每个 MCP 必须有一个引导技能：教 Agent 怎么用这个 MCP。**详细介绍，但分层披露。**

## 命名与定位

- 技能名 = MCP 名（kebab-case，不加 `-mcp` / `-tool` 等噪音后缀）。
- `description` 必须写明「引导使用 X」+ 覆盖用户口语说法（中英均可）。
- **不是**工具说明书：不罗列参数表，而是约束"先做什么、再做什么、出错怎么办"。

## 目录结构

```
<mcp-guide>/
├── SKILL.md                      ≤ 80 行：何时用 + 最小可用路径 + 指针
└── references/
    ├── capability-map.md         全量工具清单 + 分层 + 入口工具（含 outputSchema 要点）
    ├── workflows.md              典型链路：真实调用序列与参数
    ├── pitfalls.md               陷阱、限流、失败恢复
    └── ui.md                     UI 路径（静态档 / Apps 档）与何时打开
```

## 披露规则

| 层级 | 放什么 | 不放什么 |
|------|--------|----------|
| SKILL.md | 触发场景、3–5 步最小可用路径、每篇 reference 的**何时读** | 参数表、完整工具列表、长示例 |
| references | 全量细节，按需读取 | 与 SKILL.md 重复的内容 |

**写法要求**：每个 reference 指针必须带触发条件，而不是单纯列文件名。

```
- 能力地图 — 见 references/capability-map.md：当用户要"看看有什么能力"或需要选工具时读。
```

## 内容清单（缺一不可）

1. **能力地图** — 工具按工作流分层，标出入口工具与初始暴露集
2. **典型工作流** — 3–5 条真实链路（含具体工具名、参数、返回值要点）
3. **参数契约** — 必填/选填、默认值、易错取值
4. **失败恢复** — 常见错误 → 下一步动作；错误文案本身要带可行动的恢复指引（缺什么、有效取值、下一步调什么）
5. **UI 指针** — 静态档绝对路径 + 何时用 `present_files` 打开；Apps 档说明哪些工具带 `_meta.ui.resourceUri`
6. **安全边界** — 破坏性操作清单与前置确认要求

## 与 UI 的分工

| | 引导技能 | UI（静态档 / Apps） |
|---|---------|---------------------|
| 读者 | Agent | 人类 |
| 职责 | 约束行为序列 | 可视化能力地图/管理面板/交互部件 |
| 触发 | 用户意图命中 description | 被显式打开 / host 渲染 |

两者内容必须**同源**（工具名、链路、错误码一致），避免双份维护漂移。

## 与 host 的按需连接

SKILL.md 里声明本技能依赖哪些 MCP server。host 侧可只在技能被触发时才连接对应 server，任务结束断开，进一步省上下文——这是渐进披露从"工具级"上升到"server 级"的用法。

## 反模式

- SKILL.md 一次讲完 —— 上下文污染，违背渐进披露
- 只有 SKILL.md 没有 references —— 要么太浅要么太长
- 只写"有哪些工具"不写"先调哪个" —— LLM 仍会乱选
- 把 MCP 的 README 直接当技能 —— 面向人类 ≠ 面向 Agent
