# 规范契约：MCP 2026-07-28

写或审任何 MCP 工具前读这份。来源全部是官方文档与 spec 正文，版本 = 当前 spec `2026-07-28`。

## 版本机制

- 版本号是日期 `YYYY-MM-DD`，只在**向后不兼容**变更时递增；向后兼容的增订不换号。
- 修订状态：Draft / Current / Final。当前 Current = `2026-07-28`。
- 每个请求在 `_meta` 里带 `io.modelcontextprotocol/protocolVersion`；Streamable HTTP 另在 `MCP-Protocol-Version` 头带一份。客户端可先 `server/discover`（mandatory RPC，一次返回支持的版本、能力、身份）。

## 三种原语与控制方

| 原语 | 控制方 | 说明 |
|------|--------|------|
| tools | 模型 | schema 定义的动作，模型自己决定何时调用 |
| resources | 应用（host） | 只读数据，URI 唯一，MIME 标注；host 决定何时进上下文 |
| prompts | 用户 | 参数化模板，显式调用；支持参数补全 |

选型：模型要"做" → tool；host 要"供上下文" → resource；人要"复用套路" → prompt。

## 工具定义字段（[规范]）

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | 是 | 1–128 字符；仅 `A-Za-z0-9_-.\u3000`；server 内唯一；大小写敏感 |
| `title` | 否 | 人类可读标题，host 显示用 |
| `description` | 是 | 给模型的说明——写"何时用、返回什么、边界在哪" |
| `inputSchema` | 是 | JSON Schema，缺省 2020-12；无参数工具用 `{"type":"object","additionalProperties":false}` |
| `outputSchema` | 否 | JSON Schema；给了就 MUST 产出符合的结构化结果 |
| `annotations` | 否 | 行为标注，见下 |
| `icons` | 否 | host UI 图标数组 |

- `tools/list` **SHOULD 确定性排序**（同一工具集多次请求顺序一致）——客户端缓存与 prompt cache 命中都依赖它。
- `tools/list` 集合 MUST NOT 随连接变化或作为其他请求的副作用变化；**MAY** 按请求携带的授权范围变化。
- 参数可加 `x-mcp-header`（Streamable HTTP）把原始类型参数镜像成 HTTP 头；敏感参数（口令、密钥、令牌、PII）SHOULD NOT 打这个标记。
- 跨 server 聚合时客户端 SHOULD 做消歧（如加 server 前缀）——`serverInfo.name` 不保证唯一，不能拿来消歧。

## Annotations（[规范]）

可选属性，描述工具行为（`readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint` 一类）。**客户端 MUST 把 annotations 视为不可信，除非来自受信 server。** 用途是提示，不是安全边界；破坏性操作的确认必须走 elicitation 或客户端自己的确认流。

## 输出与错误（[规范]）

- 结果两种：**非结构化**（`content` 数组：text / image / audio / resource_link / embedded resource）与**结构化**（`structuredContent`）。
- 返回结构化内容时 SHOULD 同时在 text block 里序列化一份 JSON（向后兼容）。
- `outputSchema` 给了：server MUST 产出符合 schema 的结果；client SHOULD 校验。
- 错误分两层：
  1. **协议错误**（JSON-RPC error：未知工具、畸形请求、server 错误）——模型较难自愈，客户端 MAY 透传给模型。
  2. **执行错误**（`isError: true` + 内容）——输入校验失败、API 失败、业务错误。客户端 SHOULD 给模型，模型据此自纠。**错误文案必须带可行动的恢复指引**（缺什么、有效取值、下一步调什么），别只给错误码或 traceback。

## 无协议级会话：显式 handle（[规范]）

MCP 无协议级 session，server 不能靠隐式连接状态关联两次调用。要跨调用保持状态（购物车、事务、浏览器上下文），就**创建工具返回 handle，后续工具把它当参数传**：

- **opaque** — 别在 handle 里编码内部结构。
- **寿命** — 在创建工具的 description 里写清保留策略（如"24 小时无活动过期"），让模型建状态时看得见。
- **授权** — 有认证的 server：handle 是名字不是能力，每次调用都要校验调用方授权；无认证 server：handle 即 bearer token，用足熵（UUIDv4）且有界寿命。
- **过期错误** — 对过期/未知 handle 返回明确的执行错误，让模型能自己重建。

## 按需收集输入：elicitation（[规范]）

工具处理中缺输入时，返回 `InputRequiredResult`（`inputRequests` 里带 `elicitation/create`），客户端收集后带 `inputResponses` + `requestState` 重试同一请求（新 JSON-RPC id）。

| mode | 用途 | 禁忌 |
|------|------|------|
| `form` | 带 JSON Schema 校验的结构化收集 | MUST NOT 收集口令、API key、令牌、支付凭证 |
| `url` | 跳外部 URL 完成敏感交互 | 数据不流经客户端与模型上下文；客户端只回报用户是否同意 |

## 其他协议机制（[规范]）

| 机制 | 要点 |
|------|------|
| 分页 | 不透明 `cursor`（非页码）；page size 由 server 定；响应带 `nextCursor`、`ttlMs`、`cacheScope` |
| 缓存 | 列表/read 结果带 `ttlMs` + `cacheScope`；收到 `list_changed` 即视为过期，不等 TTL 到期 |
| 取消 | `notifications/cancelled`，server 可中止对应操作 |
| 进度 | 请求带 `progressToken` 时 server MAY 发 `notifications/progress`（可含 total），完成 MUST 停发 |
| 补全 | `completion/complete` 为 prompt / 资源模板参数提供补全，支持 `hasMore` |
| listChanged | 工具集变化时发 `notifications/tools/list_changed`（需订阅流） |

## 弃用清单（2026-07-28，别在新设计里用）

| 特性 | 迁移路径 |
|------|----------|
| Roots | 用工具参数、资源 URI 或 server 配置传目录/文件 |
| Sampling | 直接对接 LLM 厂商 API |
| Logging（客户端推送） | stdio 走 `stderr`；可观测性用 OpenTelemetry |
| Dynamic Client Registration | Client ID Metadata Documents |
| HTTP+SSE 传输 | Streamable HTTP |

最早移除 = 2027-07-28 起的修订版。

## 安全（[规范] 的 MUST/SHOULD）

- 工具始终应保留**人能否决**的能力：host SHOULD 展示"哪个 server 暴露哪些工具"、调用时给视觉指示、危险操作给确认提示。
- Server MUST：校验所有输入、实现访问控制、限流、净化输出。
- Client SHOULD：敏感操作前确认；调用前把工具输入展示给用户（防数据外泄）；校验结果再给模型；给工具调用设超时；审计日志。
- Elicitation form mode 禁收敏感凭证（见上）。
- 做 OAuth 代理时防 confused deputy：per-client 同意、redirect_uri 精确匹配、state 单次使用且过期短、禁 token passthrough。

## stdio server 的两条铁律

1. **绝不写 stdout** —— 会污染 JSON-RPC 帧，直接搞坏 server。
2. 日志走 `stderr`（HTTP server 无此约束，可 stdout）。
