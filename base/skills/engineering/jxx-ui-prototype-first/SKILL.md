# UI 原型先行（jxx-ui-prototype-first）

界面改动**先在原型库出 demo，人确认后再动产品代码**。这条流程的价值不在 demo 好看，而在于：需求在便宜的地方被看见、被否决，而不是在 merge 之后。

## 什么时候走

要走：页面、区块、组件、布局、样式的任何可见改动——包括「只换展示形式」。

不用走：改文案错别字、改配置常量、修一个已在别处确认过的样式变量。判断口径只有一条——**改动会不会影响人看到的形态**。

项目可能有更细的口径（比如颜色变量微调免原型），以项目子技能为准。

## 两段式：原型停下 → 确认后落地

**阶段 A · 出原型并停下**：在原型库里建 `<slug>/draft/`（或既定版本号），拿真实素材与真实数据做 demo。只回答一个问题：这版形态对不对。做完就**通知用户看，然后停**——不写实施代码、不跑落地门禁、不合并、不登记生产侧文档。

**阶段 B · 确认后落地**：用户逐项看，反馈只改对应组件块，不重画整页。确认合格 ⇒ `draft/` 升格为 `v<N>/` 冻结 ⇒ 才进入实施；代码以**最新冻结版 `vN` 为准**，实现中发现形态要变，**回原型再出一版**，不在代码里悄悄改设计。

### 阶段 A 的边界（这条最容易被破）

原型阶段**只做**原型本体、可用性自测（各断点无横向滚动、无外链、按钮不发请求）、截图与实测尺寸表。

原型阶段**不做**：`build`、行为回归 harness、产物统计、文档门禁、SEO / llms 等生产侧登记、看板终审流转、merge、push。这些只对 `src/` 有意义，对 `docs/` 下的静态原型零信息量——提前做一遍，落地时还要再做一遍。

### 只有这四类值得升级给用户

1. 信息架构：区块 / 组件的去留与顺序。
2. 商业口径：价格展示、按钮与 CTA 文案、是否保留某条转化路径。
3. 列数与尺寸上限：各断点的列数、`max-width`。
4. 外部依赖：能否引外链资源、用哪张素材。

字号、行高、间距、图标、微交互、命名由执行者自决，写进原型的说明段即可。**同一口径不要问第二遍**——先翻原型台账与既有裁决记录。

## 原型库

默认根目录 `docs/prototypes/`（没有则 `prototypes/`，或用 `--root`）：

```
docs/prototypes/
  README.md              库的说明与索引（可空）
  <slug>/
    manifest.md          版本台账 + 组件清单
    draft/               进行中（未确认）
    v1/  v2/  ...        已确认冻结（只增不改）
```

**manifest.md 是台账**：版本表（版本 / 日期 / 状态 / 改了什么 / 落地 commit 或工单）＋组件清单（id、位置、职责）。状态三档：`draft` 进行中 · `confirmed` 已确认待实现 · `shipped` 已上线。

**版本规则**：`vN` 一经确认即冻结，**只增不改**；新改动从最新 `vN` 拷到 `draft/` 改。这条是硬约束——改 `vN` 等于篡改双方确认过的基准，实施方与审查方都失去参照。

## 组件级迭代

原型要在能拆的地方拆开，让反馈能落到局部。给每个区块/组件在 HTML 里加注释标记：

```html
<!-- component:card -->
<section class="...">...</section>
<!-- /component:card -->
```

改反馈时**只动目标组件的标记块与它的 CSS**，其余原样带过。这样一次迭代的影响面是可说清的，也方便下一版 diff 出到底改了什么。组件清单同步写进 manifest。

## 写 demo 的硬要求

- 单文件自包含：双击就能开，不依赖构建、不依赖本地服务。
- 真实素材、真实文案、真实数据（能取真数据就取，不许拿 Lorem 顶）。
- 语言跟随项目面向的读者；多语言项目默认出主读者那版。
- 页面别出横向滚动条；长内容允许纵向自然长高，但要测过三档宽度（窄屏 / 平板 / 桌面）。

具体阈值（宽高比、字号、间距、色值）由项目子技能给——本技能不替你定设计值。

## 脚手架

```bash
node scripts/prototype.mjs new <slug>        # 建 slug 与 draft/ 骨架
node scripts/prototype.mjs freeze <slug>     # draft/ 升格为 v<N> 并写台账行
node scripts/prototype.mjs list              # 列出现有原型与版本
```

根目录自动探测；也可 `--root <仓库根>` 显式指定。

## 实施阶段的约束

- 实施以最新 `vN` 为准；实现与原型不一致的地方，要么改代码，要么回原型改设计并出新版——**不许只在代码里改**。
- 原型随项目一起进 git；已确认版本是基准，不是临时产物。
- 上线后把 manifest 的状态改为 `shipped`，补 commit 或工单号。

## 项目子技能

每个项目有自己的一套细则（原型根目录、语言、素材深度、与现有站点的门禁如何衔接）。**通用流程放本技能，项目细则放项目技能**，冲突时项目细则优先。

照 [references/project-skill-template.md](references/project-skill-template.md) 起项目子技能，它列了必须回答的七个问题。
