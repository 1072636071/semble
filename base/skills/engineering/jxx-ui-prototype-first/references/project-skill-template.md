# 项目子技能模板（复制改名）

项目子技能只写**本项目特有**的细则；通用流程由全局技能 `jxx-ui-prototype-first` 承担，不要复制过来（复制必漂移）。

建法：在项目技能目录下建 `<项目技能名>/SKILL.md`，frontmatter 写 `name` 与 `description`（description 要写清「什么时候加载」），然后在项目规范文件里加一行指针。

七个必答问题：

1. **原型库放哪、叫什么**：根目录路径、slug 命名规则（例：`docs/prototypes/<页面>-<改动>/ `）。
2. **语言与读者**：demo 出哪种语言、给谁看（内部评审 / 客户 / 采购）。
3. **素材从哪来**：图片/数据的唯一来源目录；新增素材要不要入库（KB / 图床）与命名规则。
4. **哪些改动免原型**：写清豁免口径（例：颜色变量、间距微调、文案错别字），别留「看情况」。
5. **确认与冻结怎么走**：谁来确认；冻结后放哪；台账文件叫什么、记哪几列。
6. **两段门禁**：分开写。**阶段 A（原型）**：只过哪些轻量检查（例：lint、行尾），并写明**豁免**哪些（例：build、行为回归、产物统计、SEO / llms 登记、看板流转）。**阶段 B（落地）**：一次过哪几道闸（例：事实核对、双语硬分叉、lint + build、行为回归、文档回写、SEO 登记、看板收口）。逐条可执行，别留「必要时」。
   另写一条：**升级给用户的四类问题**（信息架构 / 商业口径 / 列数与尺寸上限 / 外部依赖），其余由执行者自决。
7. **偏离怎么处理**：实现时发现形态要变，回哪份文件记决策、要不要出新版原型。

写法要点：

- 一句话一条规则，不解释「为什么」（理由放项目规范或决策记录）。
- 能给命令就给命令，能给路径就给路径；别写「按需」「适当」。
- 与全局技能冲突时以本技能为准——在开头写一句声明这句话。
