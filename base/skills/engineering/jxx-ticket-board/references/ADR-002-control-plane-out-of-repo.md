# ADR-002：协调层独立于仓库——工单正文留 .scratch/，全局状态卡放顶层 control/（一单一文件，不入 git）

- 状态：已接受（2026-09-21）
- 关联：memorial 001 D3

## 背景

多工单并行后，工单正文分布在各自分支的 `.scratch/`（规范要求工单随仓库版本化），但"谁在开发哪张卡、worktree 租约、审查状态"这类协调状态必须全局可见。若把总账板写进仓库，多分支各自更新同一聚合文件必然合并冲突，且历史教训（共享树重跑聚合生成物会把他人未提交状态烤进提交）证明聚合文件在工作区内不可靠。

## 决策

1. **真源不动**：工单正文（PRD、验收标准、交付记录）仍留仓库 `.scratch/`，随分支与 main 版本化。
2. **协调层外置**：`E:\work\ai-sp\TDB-AM\control\`（顶层，非 git 仓库）每工单一张状态卡（`NNN-slug.md`）：状态机（backlog → developing → in-review → changes-requested → merged / blocked）、branch 与 worktree 租约、审查报告指针。
3. **一单一文件**：不存在聚合总账文件，全局视图由扫描 control/ 目录即时生成，避免聚合物污染。
4. 卡与分支可能漂移，需一个校验脚本（卡声明的状态 vs 分支/worktree 实际状态）辅助。

## 后果

- 正面：agent 冷启动只需读卡即可接管；无跨分支合并冲突；真源与协调各司其职。
- 负面：两处存放需指针互链；状态卡是"影子状态"，可能失真，需校验脚本与定期核对。
- 替代方案（被否）：① 工单整体迁出仓库——违背工单随仓库版本化规范，正文与代码 review 分家；② 全留仓库内约定——未合并分支的协调状态互相不可见，全局视图需跨分支扫描。
