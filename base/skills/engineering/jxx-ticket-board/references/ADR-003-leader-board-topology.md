# ADR-003：领导者-领取制公告板拓扑（领导者只分解，工人自发领取并回写）

- 状态：已接受（2026-09-21）
- 关联：memorial 001 D4；ADR-002（control/ 目录为握手媒介）

## 背景

多工单并行需要确定 agent 之间的组织形态。候选：中心协调者逐单派遣（协调者 spawn 并驱动每条开发会话）、对等自治认领、守护脚本全自动流水线。用户的实际工作方式是人同时拉起多个 agent，且不希望领导者成为开发过程的瓶颈或 micromanager。

## 决策

1. **领导者会话**：只负责三件事——把需求分解成任务卡写入指定目录、维护卡片状态流转、汇总验收。不参与也不干预"怎么开发、怎么审查"。
2. **开发小组（worker agent）**：由用户拉起，自发到任务目录领取任务，在各自隔离工作区（ADR-001 的 worktree+分支）内完成开发与组内审查，完成后回写任务状态。
3. **握手媒介 = 任务目录**（control/），所有跨 agent 通信通过卡片文件完成，不依赖任何 agent 的内存状态。
4. agent 之间的自治治理（冲突仲裁、依赖协调、自动重派）明确**推迟**为后续议题。

## 后果

- 正面：领导者可随时被杀死重建（状态全在卡片里）；开发组内部流程可自由演化（jxx 技能各组自便）；横向扩容 = 多拉一个 worker。
- 负面：领取环节的互斥、回写格式的一致性需要文件协议保证（后续决策）；"组内自行审查"是否满足 jxx"开发完必审"的纯净度要求，取决于 ADR-001 的 diff 隔离，领导者无法兜底。
- 替代方案（被否）：① 中心协调者派遣制——领导者变成所有开发细节的瓶颈；② 守护脚本流水线——工程量过大，异常分支兜不住，属过度设计。
