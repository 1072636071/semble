# ADR-004：任务卡采用"目录即状态机"，状态流转 = 文件原子 move

- 状态：已接受（2026-09-21）；决策 1 的目录集合与决策 3 的 move 目标经 **ADR-008** 修订（2026-09-30）——目录改为生命周期三态 `open/done/archived`，执行态移到文件名后缀。**本 ADR 的核心不变量「领取 = 一次原子 move/rename，由文件系统兜底防抢」原样成立**，这也是 ADR-008 拒绝「执行态写进 frontmatter 标签」的理由。
- 关联：memorial 001 D5；ADR-002、ADR-003、ADR-008

## 背景

领导者-领取制下多个 worker 并发访问任务目录，"领取"必须互斥，"回写"必须可信。平铺目录 + 卡内字段方案在读-改-写路径上没有原子性，两个 worker 可同时"成功"领取同一张卡；领导者中心分配与"worker 由用户随时拉起、自发领取"矛盾。

## 决策

1. `control/cards/` 下按状态分目录：`inbox/ → claimed/ → review/ → done/ | blocked/`。
2. **领取 = 把卡从 inbox/ 原子 move 到 claimed/**，文件系统排他性天然防抢；move 成功后在卡内追加领取者、worktree 路径、分支名。
3. **回写 = 再次 move + 卡内追加**（自审报告、交付说明）；返工 = move 回 claimed/，历史段落保留在卡内成审计轨迹。
4. 领导者扫目录即得全局视图，不设聚合总账文件。
5. 约束：目录必须与卡文件同盘（跨盘 move 非原子）；卡内状态字段与所在目录需一致性校验脚本辅助。

## 后果

- 正面：互斥由 OS 兜底不靠纪律；状态物理可见；卡片自身即审计日志。
- 负面：状态集变更需迁移目录；agent 必须遵守"先 move 成功后才动卡内容"的顺序（协议文档需写明）。
- 替代方案（被否）：① 平铺 + frontmatter 租约字段——读改写无原子性，与历史上"共享树互相卷入"同型风险；② 领导者中心分配——worker 启动即需领导者在场，违背公告板模型。
