# ADR-006：卡片粒度 = 工单粒度（薄卡，卡↔工单↔分支一一对应）

- 状态：已接受（2026-09-21）
- 关联：memorial 001 D7；ADR-001、ADR-002、ADR-005

## 背景

D2 确立"审查 diff = 分支 diff"后，卡片粒度必须与分支粒度一致，否则多卡共享分支会使 diff 不再等于单卡成果、审查纯净性失效。候选：一单拆 N 卡每卡一分支（并行粒度细但工单成果散落多分支、状态语义翻倍、侵入 jxx 一单一分支交付假设）、厚卡内联全文（与 .scratch/ 双源漂移）。

## 决策

1. 一张卡 = 一个 `.scratch/` 工单 = 一个 `ticket/NNN` 分支，严格一一对应。
2. 卡是"薄"的：工单号、PRD 指针、一句话目标、依赖列表、可合并判定标记、状态流转追加段（领取记录/交付记录/审查报告指针）。
3. 大工单**不在卡片层拆分**；开发组在分支内按 jxx 技能自行分步提交，粒度自治。
4. 合并卡（ADR-005）同样一卡一分支，命名 `merge-NNN-slug.md` 以示类别。

## 后果

- 正面：卡↔分支↔工单三者映射唯一，diff 即成果，审查语义最干净；目录扫描协议最简。
- 负面：大工单在飞期间看板粒度粗，"并行度"表面数字偏低——接受，用分支内提交节奏补足可见性。
- 替代方案（被否）：① 一单拆 N 卡——破坏 1:1 映射，工单完成判定复杂化；② 厚卡——双源漂移。
