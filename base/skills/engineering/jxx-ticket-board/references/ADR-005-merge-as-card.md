# ADR-005：合并作为特殊任务卡由专职合并 agent 执行，工作成果一律以 git 分支承载

- 状态：已接受（2026-09-21）
- 关联：memorial 001 D6；ADR-003、ADR-004

## 背景

领导者-领取制下，多张工单分支并行开发完成后都需要合入 main。候选：领导者收口串行合并、worker 自助合并（有基线漂移竞态）、人工逐单合并（吞吐瓶颈）。用户选择把合并本身也纳入公告板协议。

## 决策

1. **合并 = 一类特殊任务卡**：领导者判定某分支"审过且可合"后向 `inbox/` 投一张 `merge: ticket/NNN` 卡；专职"合并专员" agent 领取，执行 rebase 到最新 main + merge + 推 remote，回写 done。
2. **一切工作成果以 git 分支承载**：代码、`.scratch/` 工单文档增量、审查报告指针都在 `ticket/NNN` 分支上；control/ 卡片只做协调指针，不承载成果。
3. 合并顺序由领导者在下卡时指定（后一单等前一单合完），并发合并被协议禁止——同一时刻合并专员只处理一张 merge 卡。

## 后果

- 正面：合并纳入统一协议，无特权通道；main 前进有单一执行者，基线竞态消灭；合并专员可被多个实例轮值（治理期再议）。
- 负面：合并专员 rebase 时若遇冲突，**解决冲突会产生新 diff，严格意义上使原审查失效**——协议需规定：冲突超出机械可解范围时打回 review/ 复审，禁止合并专员发明行为（参照 jxx-resolving-merge-conflicts 原则）。
- 替代方案（被否）：① 领导者亲自合并——领导者职责膨胀回 micromanager；② worker 自助合并——N 分支并发推 main 的竞态把污染搬进 main 历史。
