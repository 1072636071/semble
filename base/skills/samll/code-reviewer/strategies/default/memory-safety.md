# 通用内存安全分析指导文档

## 能力目标

基于编程语言的内存管理模型和运行时特性，识别真实的内存安全风险，避免基于表面模式的误报。

---

## 前置判断

获取以下关键信息：
- **内存管理模型**：手动管理/自动垃圾回收/引用计数/所有权系统
- **类型系统**：静态类型/动态类型/类型安全程度
- **运行时检查**：边界检查/空值检查/类型检查
- **并发模型**：共享内存/消息传递/数据竞争保护
- **输入来源**：用户输入/网络数据/文件/可信数据源

---

## 分析流程

### Step 1 — 识别内存相关操作
定位语言中的内存操作模式：
- **分配**：对象创建、集合初始化、动态分配
- **释放**：显式释放、作用域结束、垃圾回收触发
- **复制**：赋值操作、深拷贝、浅拷贝
- **访问**：索引访问、属性访问、间接引用

### Step 2 — 验证边界与容量
- 检查集合/数组访问是否有边界验证
- 验证缓冲区/容器容量是否足够
- 确认字符串/序列操作的长度限制

### Step 3 — 检查输入约束
- 外部输入是否经过验证和清理
- 大小/长度/范围参数是否受信任
- 是否存在可被外部控制的内存相关参数

### Step 4 — 分析引用生命周期
- 引用/指针的有效性范围
- 对象销毁后的引用使用
- 跨作用域的引用传递
- 空值/未定义值的解引用风险

---

## 风险模式分类

### CAT-M001 内存分配失败未处理
内存分配操作失败时缺乏适当的错误处理。

**触发条件**：
- 分配操作返回空值/错误但未检查
- 大对象分配可能耗尽内存
- 循环中的累积分配未限制
- 资源受限环境下的分配

**分析要点**：
检查分配操作的返回值处理，验证错误路径的完整性，确认资源耗尽场景的处理逻辑。

**通用示例**：
```
// 问题：未检查分配结果
buffer = allocate_memory(size)
buffer.write(data)  // 如果分配失败，这里会崩溃

// 改进：检查分配结果
buffer = allocate_memory(size)
if buffer is null:
    handle_error()
    return
buffer.write(data)
```

---

### CAT-M002 集合/数组越界访问
使用超出有效范围的索引访问集合元素。

**触发条件**：
- 负数索引（在不支持负索引的语言中）
- 索引值大于等于集合大小
- 循环边界条件错误
- 未验证的外部输入索引
- 空集合的访问操作

**分析要点**：
验证索引来源的可控性，检查边界条件的正确性，确认集合大小的动态变化是否被考虑。

**通用示例**：
```
// 问题：未验证索引范围
index = get_user_input()
value = array[index]  // 可能越界

// 改进：验证索引范围
index = get_user_input()
if index < 0 or index >= array.length:
    handle_error()
    return
value = array[index]
```

---

### CAT-M003 空引用/空指针解引用
访问值为空/未定义/未初始化的引用。

**触发条件**：
- 可能返回空值的操作未检查
- 未初始化的变量直接使用
- 条件分支导致引用为空
- 查找/搜索操作未找到结果时的处理
- 可选类型未进行存在性检查

**分析要点**：
追踪引用的赋值路径，验证所有可能为空的情况，检查使用前的验证逻辑。

**通用示例**：
```
// 问题：未检查空值
result = find_item(key)
process(result.data)  // result可能为空

// 改进：检查空值
result = find_item(key)
if result is null:
    handle_not_found()
    return
process(result.data)
```

---

### CAT-M004 引用失效后使用
使用指向已销毁/释放对象的引用。

**触发条件**：
- 对象销毁后继续持有引用
- 集合修改导致迭代器/引用失效
- 跨线程的对象生命周期不一致
- 闭包捕获的引用超出作用域
- 弱引用未检查有效性

**分析要点**：
分析对象生命周期与引用使用的时序关系，验证集合修改对引用的影响，检查异步场景下的引用有效性。

**通用示例**：
```
// 问题：迭代时修改集合
for item in collection:
    if should_remove(item):
        collection.remove(item)  // 迭代器可能失效

// 改进：收集后删除
to_remove = []
for item in collection:
    if should_remove(item):
        to_remove.append(item)
for item in to_remove:
    collection.remove(item)
```

---

### CAT-M005 资源泄漏
分配的资源未被正确释放或回收。

**触发条件**：
- 异常/错误路径缺少资源清理
- 循环引用阻止垃圾回收
- 长生命周期对象持有临时资源
- 显式管理的资源未释放
- 事件监听器/回调未注销

**分析要点**：
追踪所有代码路径的资源释放，检查异常处理的完整性，识别可能的循环引用模式。

**通用示例**：
```
// 问题：错误路径未释放资源
resource = acquire_resource()
if operation_fails():
    return  // 资源泄漏

// 改进：使用try-finally或RAII模式
resource = acquire_resource()
try:
    perform_operation()
finally:
    release_resource(resource)
```

---

### CAT-M006 缓冲区/容器溢出
向固定大小的缓冲区或容器写入超出容量的数据。

**触发条件**：
- 写入长度超过缓冲区大小
- 字符串拼接未检查总长度
- 序列化操作超出目标容量
- 累积追加操作未限制大小
- 未验证的外部数据长度

**分析要点**：
验证写入操作的长度参数，检查缓冲区容量的静态与动态限制，确认外部数据的长度验证。

**通用示例**：
```
// 问题：未验证数据长度
fixed_buffer = create_buffer(MAX_SIZE)
data = get_network_data()
fixed_buffer.write(data)  // data可能超过MAX_SIZE

// 改进：验证并截断
fixed_buffer = create_buffer(MAX_SIZE)
data = get_network_data()
if data.length > MAX_SIZE:
    data = data.substring(0, MAX_SIZE)
fixed_buffer.write(data)
```

### CAT-M007 整数溢出影响内存操作
整数运算溢出导致内存分配或访问错误。

**触发条件**：
- 乘法计算内存大小时溢出
- 加法累积索引值时溢出
- 类型转换导致值截断
- 用户可控的数值参数未范围检查
- 有符号/无符号混用导致的异常

**分析要点**：
检查用于内存操作的数值计算，验证整数类型的范围限制，确认外部数值输入的验证。

**通用示例**：
```
// 问题：乘法溢出
count = get_user_input()
size = count * ITEM_SIZE  // 可能溢出
buffer = allocate(size)

// 改进：检查溢出
count = get_user_input()
if count > MAX_SAFE_COUNT:
    handle_error()
    return
size = count * ITEM_SIZE
buffer = allocate(size)
```

### CAT-M008 类型混淆/不安全类型转换
不安全的类型转换导致内存解释错误。

**触发条件**：
- 强制类型转换绕过类型检查
- 反射/动态类型操作未验证
- 序列化/反序列化类型不匹配
- 泛型/模板类型假设错误
- 外部数据的类型信任

**分析要点**：
验证类型转换的安全性，检查动态类型操作的验证逻辑，确认序列化边界的类型一致性。

**通用示例**：
```
// 问题：未验证类型转换
obj = deserialize(data)
result = obj as SpecificType  // 类型可能不匹配
result.specific_method()

// 改进：验证类型
obj = deserialize(data)
if not isinstance(obj, SpecificType):
    handle_type_error()
    return
result = obj as SpecificType
result.specific_method()
```

---

### CAT-M009 并发访问冲突
多线程/并发环境下的不安全内存访问。

**触发条件**：
- 共享数据无同步保护
- 检查-使用（TOCTOU）竞态条件
- 非线程安全集合的并发修改
- 对象在一个线程销毁，另一个线程访问
- 原子性假设错误

**分析要点**：
识别共享内存访问模式，验证同步机制的完整性，检查线程安全性保证。

**通用示例**：
```
// 问题：无同步保护
// 线程1
if cache.contains(key):
    value = cache.get(key)  // 可能已被其他线程删除

// 改进：原子操作
value = cache.get_or_null(key)
if value is null:
    handle_miss()
```

---

### CAT-M010 未验证的外部数据操作
使用未经验证的外部数据进行内存相关操作。

**触发条件**：
- 用户输入直接用作索引/偏移
- 网络数据中的长度字段未验证
- 文件解析中的大小参数直接使用
- 反序列化数据中的指针/引用
- API响应中的数量/范围参数

**分析要点**：
追踪外部数据的流向，验证所有外部输入的验证逻辑，确认使用前的范围和合法性检查。

**通用示例**：
```
// 问题：未验证外部数据
packet = receive_network_packet()
length = packet.read_length_field()
buffer = allocate(length)  // length可能是恶意值

// 改进：验证范围
packet = receive_network_packet()
length = packet.read_length_field()
if length <= 0 or length > MAX_PACKET_SIZE:
    handle_invalid_packet()
    return
buffer = allocate(length)
```

## 代码分析视角

### 1. 数据流分析
追踪数据从输入源到内存操作的完整路径，验证每个转换点的约束条件。

### 2. 控制流分析
检查所有代码路径（包括异常、错误处理）的内存操作一致性。

### 3. 生命周期分析
验证对象/资源从创建到销毁的完整生命周期，识别引用的有效性范围。

### 4. 并发分析
识别共享状态访问模式，验证同步机制的正确性和完整性。

## 语言特性考量

不同编程语言的内存安全保障差异：

| 特性 | 高安全语言 | 中等安全语言 | 低安全语言 |
|------|----------|------------|----------|
| 边界检查 | 运行时强制 | 部分检查 | 无检查 |
| 空值安全 | 类型系统保证 | 运行时检查 | 手动检查 |
| 内存管理 | 自动GC | 引用计数/混合 | 手动管理 |
| 类型安全 | 静态强类型 | 动态类型 | 弱类型 |

**分析策略**：根据语言特性调整关注重点，高安全语言关注逻辑错误，低安全语言关注底层内存操作。

---

## 典型误报场景

以下情况不应报告为内存安全问题：
- 语言运行时已提供边界检查保护
- 使用了语言推荐的安全API
- 输入数据已经过充分验证
- 编译器/解释器静态分析已排除的场景
- 内部受控环境中的可信数据操作
- 框架/库已提供的安全抽象
