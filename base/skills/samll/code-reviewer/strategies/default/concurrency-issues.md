# 通用并发问题分析指导文档

## 能力目标

基于并发编程的通用原则，识别跨语言的线程安全风险，判断真实的竞态条件和同步问题，区分并发安全和误报场景。

---

## 前置判断

### 识别并发上下文

获取以下信息：
- **并发模型**: 多线程、多进程、异步任务、协程、事件循环、Actor模型
- **执行单元**: 线程、进程、任务、协程、工作单元
- **共享资源**: 全局变量、静态变量、堆对象、共享内存、文件、数据库连接
- **同步机制**: 
  - 互斥锁（mutex/lock）
  - 读写锁（reader-writer lock）
  - 信号量（semaphore）
  - 条件变量（condition variable）
  - 原子操作（atomic operations）
  - 消息传递（message passing）
  - 事件通知（event notification）
- **内存可见性**: 内存模型、缓存一致性、指令重排序

## 通用分析流程

### Step 1 — 识别并发执行点

定位可能并发执行的代码段：

**并发执行的标志**:
- 显式创建执行单元（线程/进程/任务）
- 异步调用或延迟执行
- 事件处理器或回调函数
- 并行循环或批处理
- 定时器或调度器
- 消息队列的消费者

**示例特征**（语言无关）:
```
// 伪代码示例
创建线程(函数)
异步执行(函数)
并行循环(集合, 函数)
事件监听器(事件, 处理器)
定时器(延迟, 函数)
工作队列.提交(任务)
```

### Step 2 — 追踪共享资源访问

#### 2.1 识别共享状态

**共享资源类型**:
- **全局变量**: 程序范围内可访问
- **静态变量**: 类或模块级别共享
- **堆对象**: 通过引用传递
- **单例对象**: 全局唯一实例
- **缓存结构**: 共享的查找表或映射
- **集合容器**: 数组、列表、映射、集合
- **外部资源**: 文件、数据库连接、网络套接字

#### 2.2 分析访问模式

**访问类型**:
- **读-读**: 通常安全（无修改）
- **读-写**: 数据竞争（读到不一致状态）
- **写-写**: 数据竞争（更新丢失）
- **复合操作**: 非原子的多步操作

**复合操作示例**:
```
// 伪代码
计数器++                    // 读-修改-写
列表.添加(元素)            // 检查-修改
映射[键] = 值              // 查找-插入/更新
if (余额 >= 金额) { 
    余额 -= 金额           // 检查-操作（TOCTOU）
}
```

### Step 3 — 验证同步机制

#### 3.1 同步覆盖检查

验证同步机制是否覆盖所有共享资源访问：

**检查点**:
- 所有读操作是否受保护
- 所有写操作是否受保护
- 锁的作用域是否完整
- 是否存在未保护的访问路径

**同步模式**（概念层面）:
```
// 伪代码：互斥锁保护
获取锁(互斥锁)
try {
    // 临界区：访问共享资源
    共享数据.修改()
} finally {
    释放锁(互斥锁)
}

// 伪代码：原子操作
原子变量.原子递增()

// 伪代码：读写锁
获取读锁(读写锁)
try {
    // 读操作
    读取(共享数据)
} finally {
    释放读锁(读写锁)
}
```

#### 3.2 同步机制有效性

验证同步机制的正确性：
- 锁粒度是否适当
- 是否存在锁顺序问题
- 内存可见性是否保证
- 原子性是否满足

### Step 4 — 检测竞态条件

#### 4.1 常见竞态模式

**时间窗口竞争**:
- 检查-操作（Check-Then-Act）
- 读-修改-写（Read-Modify-Write）
- 双重检查（Double-Checked Pattern）

**执行顺序依赖**:
- 初始化顺序
- 依赖特定执行时序
- 未同步的状态转换

**示例场景**:
```
// 场景1：检查-操作竞态
if (资源.可用()) {          // 检查
    // 时间窗口：其他线程可能获取资源
    资源.使用()             // 操作 - 可能失败
}

// 场景2：非原子复合操作
当前值 = 计数器.读取()
新值 = 当前值 + 1
计数器.写入(新值)           // 丢失更新

// 场景3：双重检查
if (实例 == null) {         // 第一次检查
    获取锁()
    if (实例 == null) {     // 第二次检查
        实例 = 创建对象()   // 可能的可见性问题
    }
    释放锁()
}
```

## 风险模式分类

### CAT-0051 竞争条件 (Race Condition)

**定义**: 程序的执行行为依赖于不可控的线程执行时序，导致不可预测的结果。

**触发条件**:
- 检查-操作模式未原子化
- 复合操作缺少同步保护
- 懒加载或单例模式未正确同步
- 状态依赖操作未原子执行

**通用案例：账户余额检查**

```
// 危险模式（伪代码）
类 账户 {
    余额 = 0
    
    方法 取款(金额) {
        if (余额 >= 金额) {      // 检查
            // 时间窗口：另一线程可能同时通过检查
            余额 = 余额 - 金额    // 操作
            返回 成功
        }
        返回 失败
    }
}

// 竞态场景：
// 初始余额：100
// 线程1：取款(100) -> 检查通过（100 >= 100）
// 线程2：取款(100) -> 检查通过（100 >= 100）
// 线程1：余额 = 0
// 线程2：余额 = -100  // 错误！透支
```

**安全模式**:
```
// 安全实现（伪代码）
类 账户 {
    余额 = 0
    互斥锁 = 创建锁()
    
    方法 取款(金额) {
        获取锁(互斥锁)
        try {
            if (余额 >= 金额) {
                余额 = 余额 - 金额
                返回 成功
            }
            返回 失败
        } finally {
            释放锁(互斥锁)
        }
    }
}
```

**通用案例：懒加载单例**

```
// 危险模式（伪代码）
全局变量 实例 = null

函数 获取实例() {
    if (实例 == null) {        // 检查
        实例 = 创建对象()      // 操作 - 多线程可能同时创建
    }
    返回 实例
}

// 竞态场景：
// 线程1：检查实例为null
// 线程2：检查实例为null
// 线程1：创建对象A，实例 = A
// 线程2：创建对象B，实例 = B  // 覆盖，对象A丢失
```

**安全模式**:
```
// 安全实现（伪代码）
全局变量 实例 = null
全局变量 锁 = 创建锁()

函数 获取实例() {
    获取锁(锁)
    try {
        if (实例 == null) {
            实例 = 创建对象()
        }
        返回 实例
    } finally {
        释放锁(锁)
    }
}
```

### CAT-0052 锁定不当 (Improper Locking)

**定义**: 锁的使用方式导致死锁、活锁、性能问题或保护不足。

**触发条件**:
- 多个锁的获取顺序不一致
- 锁粒度不当（过大或过小）
- 持锁时调用外部代码或阻塞操作
- 嵌套锁导致的循环依赖

**通用案例：死锁场景**

```
// 危险模式（伪代码）
全局变量 锁A = 创建锁()
全局变量 锁B = 创建锁()

// 线程1
函数 操作1() {
    获取锁(锁A)
    // 执行某些操作
    获取锁(锁B)      // AB顺序
    // 临界区
    释放锁(锁B)
    释放锁(锁A)
}

// 线程2
函数 操作2() {
    获取锁(锁B)
    // 执行某些操作
    获取锁(锁A)      // BA顺序 - 死锁风险！
    // 临界区
    释放锁(锁A)
    释放锁(锁B)
}

// 死锁场景：
// 时刻1：线程1获取锁A
// 时刻2：线程2获取锁B
// 时刻3：线程1尝试获取锁B（被线程2持有）- 阻塞
// 时刻4：线程2尝试获取锁A（被线程1持有）- 阻塞
// 结果：两个线程互相等待，死锁
```

**安全模式**:
```
// 安全实现：统一锁顺序（伪代码）
函数 操作1() {
    获取锁(锁A)
    获取锁(锁B)      // 统一AB顺序
    // 临界区
    释放锁(锁B)
    释放锁(锁A)
}

函数 操作2() {
    获取锁(锁A)      // 统一AB顺序
    获取锁(锁B)
    // 临界区
    释放锁(锁B)
    释放锁(锁A)
}
```

**通用案例：锁粒度过大**

```
// 危险模式（伪代码）
类 数据处理器 {
    锁 = 创建锁()
    数据集 = []
    
    方法 处理全部() {
        获取锁(锁)
        // 锁持有时间过长
        对于 数据集 中的 每个数据 {
            执行耗时计算(数据)    // CPU密集
        }
        执行网络请求()            // IO阻塞
        释放锁(锁)
        // 问题：阻塞其他所有线程访问数据集
    }
}
```

**安全模式**:
```
// 安全实现：缩小锁范围（伪代码）
类 数据处理器 {
    锁 = 创建锁()
    数据集 = []
    
    方法 处理全部() {
        本地副本 = []
        获取锁(锁)
        本地副本 = 复制(数据集)   // 快速复制
        释放锁(锁)
        
        // 无锁执行耗时操作
        对于 本地副本 中的 每个数据 {
            执行耗时计算(数据)
        }
        执行网络请求()
    }
}
```

### CWD-1130 缺少同步 (Missing Synchronization)

**定义**: 对共享资源的并发访问缺少必要的同步机制，导致数据竞争。

**触发条件**:
- 共享变量的读写操作未保护
- 集合容器的并发修改未同步
- 懒加载未使用适当的同步
- 误以为某些操作是原子的

**通用案例：共享计数器**

```
// 危险模式（伪代码）
全局变量 计数器 = 0

函数 递增() {
    计数器 = 计数器 + 1    // 数据竞争
}

函数 获取() {
    返回 计数器            // 数据竞争
}

// 问题分析：
// "计数器++" 实际包含三个操作：
// 1. 读取计数器当前值
// 2. 计算新值（+1）
// 3. 写入新值

// 竞态场景（初始值=0）：
// 线程1：读取=0
// 线程2：读取=0
// 线程1：计算=1，写入=1
// 线程2：计算=1，写入=1
// 结果：两次递增后计数器=1（应该是2）
```

**安全模式**:
```
// 方案1：使用互斥锁（伪代码）
全局变量 计数器 = 0
全局变量 锁 = 创建锁()

函数 递增() {
    获取锁(锁)
    计数器 = 计数器 + 1
    释放锁(锁)
}

函数 获取() {
    获取锁(锁)
    值 = 计数器
    释放锁(锁)
    返回 值
}

// 方案2：使用原子操作（伪代码）
全局变量 计数器 = 创建原子整数(0)

函数 递增() {
    计数器.原子递增()
}

函数 获取() {
    返回 计数器.原子读取()
}
```

**通用案例：集合并发修改**

```
// 危险模式（伪代码）
全局变量 共享列表 = []

函数 线程1() {
    共享列表.添加(元素1)    // 数据竞争
}

函数 线程2() {
    共享列表.添加(元素2)    // 数据竞争
}

// 问题：
// - 列表内部状态损坏
// - 元素丢失
// - 程序崩溃
```

**安全模式**:
```
// 安全实现（伪代码）
全局变量 共享列表 = []
全局变量 列表锁 = 创建锁()

函数 线程函数(元素) {
    获取锁(列表锁)
    共享列表.添加(元素)
    释放锁(列表锁)
}
```

### CWD-1132 在多线程上下文中对共享数据的非同步访问

**定义**: 在多线程环境中访问共享数据结构时缺少完整的同步保护。

**触发条件**:
- 集合容器的迭代与修改并发
- 复杂数据结构的部分保护
- 对象生命周期管理问题
- 迭代器或游标失效

**通用案例：迭代器失效**

```
// 危险模式（伪代码）
全局变量 共享列表 = [1, 2, 3, 4, 5]

// 线程1：迭代
函数 读取线程() {
    对于 共享列表 中的 每个元素 {
        处理(元素)    // 迭代过程中列表可能被修改
    }
}

// 线程2：修改
函数 写入线程() {
    共享列表.添加(6)          // 可能导致内部重新分配
    共享列表.删除(第一个元素)  // 迭代器失效
}

// 问题：
// - 迭代器失效导致崩溃
// - 读到不一致状态
// - 跳过或重复处理元素
```

**安全模式**:
```
// 安全实现（伪代码）
全局变量 共享列表 = []
全局变量 锁 = 创建锁()

函数 读取线程() {
    获取锁(锁)
    对于 共享列表 中的 每个元素 {
        处理(元素)
    }
    释放锁(锁)
}

函数 写入线程() {
    获取锁(锁)
    共享列表.添加(元素)
    释放锁(锁)
}
```

**通用案例：生产者-消费者**

```
// 危险模式（伪代码）
全局变量 队列 = []

函数 生产者() {
    任务 = 创建任务()
    队列.添加(任务)        // 数据竞争
}

函数 消费者() {
    if (队列.非空()) {     // 检查
        任务 = 队列.取出()  // 操作 - TOCTOU竞态
        处理(任务)
    }
}

// 竞态场景：
// 消费者1：检查队列非空（有1个元素）
// 消费者2：检查队列非空（有1个元素）
// 消费者1：取出任务（队列变空）
// 消费者2：尝试取出 - 错误！队列已空
```

**安全模式**:
```
// 安全实现（伪代码）
全局变量 队列 = []
全局变量 锁 = 创建锁()
全局变量 条件变量 = 创建条件变量()

函数 生产者() {
    任务 = 创建任务()
    获取锁(锁)
    队列.添加(任务)
    通知(条件变量)       // 唤醒等待的消费者
    释放锁(锁)
}

函数 消费者() {
    获取锁(锁)
    while (队列.为空()) {
        等待(条件变量, 锁)  // 释放锁并等待
    }
    任务 = 队列.取出()
    释放锁(锁)
    
    处理(任务)
}
```

### CWD-1134 同步不正确 (Incorrect Synchronization)

**定义**: 虽然使用了同步机制，但使用方式不正确，仍然无法保证线程安全。

**触发条件**:
- 锁的作用域不完整
- 临界区保护范围错误
- 同步粒度不匹配
- 原子操作使用错误

**通用案例：锁作用域过小**

```
// 危险模式（伪代码）
类 银行账户 {
    余额 = 0
    锁 = 创建锁()
    
    方法 转账(目标账户, 金额) {
        // 第一步：扣款
        获取锁(this.锁)
        this.余额 -= 金额
        释放锁(this.锁)
        
        // 中间状态：钱已扣但未存入
        // 如果此时程序崩溃，金额丢失
        
        // 第二步：存款
        获取锁(目标账户.锁)
        目标账户.余额 += 金额
        释放锁(目标账户.锁)
        
        // 问题：转账不是原子操作
    }
}
```

**安全模式**:
```
// 安全实现（伪代码）
类 银行账户 {
    余额 = 0
    锁 = 创建锁()
    
    方法 转账(目标账户, 金额) {
        // 同时锁定两个账户
        获取锁(this.锁)
        获取锁(目标账户.锁)
        
        if (this.余额 >= 金额) {
            this.余额 -= 金额
            目标账户.余额 += 金额
        }
        
        释放锁(目标账户.锁)
        释放锁(this.锁)
    }
}
```

**通用案例：原子操作误用**

```
// 危险模式（伪代码）
全局变量 原子计数器 = 创建原子整数(0)

函数 条件递增() {
    当前值 = 原子计数器.读取()        // 原子读
    if (当前值 < 100) {
        新值 = 当前值 + 1
        原子计数器.写入(新值)          // 原子写
    }
    // 问题：读和写之间存在时间窗口
}

// 竞态场景：
// 当前值=99
// 线程1：读取=99
// 线程2：读取=99
// 线程1：检查<100，写入100
// 线程2：检查<100，写入100
// 结果：计数器可能超过限制
```

**安全模式**:
```
// 安全实现：使用比较并交换（伪代码）
全局变量 原子计数器 = 创建原子整数(0)

函数 条件递增() {
    while (true) {
        当前值 = 原子计数器.读取()
        if (当前值 >= 100) {
            break
        }
        新值 = 当前值 + 1
        // 原子操作：仅当计数器仍为当前值时更新
        if (原子计数器.比较并交换(当前值, 新值)) {
            break    // 成功
        }
        // 失败则重试
    }
}
```

### CWD-1135 在同步访问远程资源时未设置超时时间

**定义**: 在执行可能阻塞的同步操作时未设置超时，导致线程可能永久阻塞。

**触发条件**:
- 锁获取无超时限制
- 条件变量等待无超时
- 网络IO操作无超时
- 外部资源访问无超时

**通用案例：无超时的锁等待**

```
// 危险模式（伪代码）
全局变量 锁 = 创建锁()

函数 处理任务() {
    获取锁(锁)              // 可能永久阻塞
    // 临界区
    释放锁(锁)
}

// 问题场景：
// 如果持锁线程崩溃或死锁，
// 其他线程将永久等待
```

**安全模式**:
```
// 安全实现：使用超时（伪代码）
全局变量 锁 = 创建锁()

函数 处理任务() {
    if (尝试获取锁(锁, 超时=30秒)) {
        try {
            // 临界区
        } finally {
            释放锁(锁)
        }
    } else {
        // 处理超时
        记录错误("获取锁超时")
        返回 失败
    }
}
```

**通用案例：无超时的条件等待**

```
// 危险模式（伪代码）
全局变量 队列 = []
全局变量 锁 = 创建锁()
全局变量 条件 = 创建条件变量()

函数 工作线程() {
    while (true) {
        获取锁(锁)
        while (队列.为空()) {
            等待(条件, 锁)      // 可能永久等待
        }
        任务 = 队列.取出()
        释放锁(锁)
        
        处理(任务)
    }
}

// 问题：如果永远没有任务，线程永久阻塞
```

**安全模式**:
```
// 安全实现（伪代码）
函数 工作线程() {
    while (未停止) {
        获取锁(锁)
        
        超时 = false
        while (队列.为空() and 未停止) {
            if (不 等待超时(条件, 锁, 超时=60秒)) {
                超时 = true
                break
            }
        }
        
        if (未停止 and 不 超时) {
            任务 = 队列.取出()
            释放锁(锁)
            处理(任务)
        } else {
            释放锁(锁)
            if (超时) {
                执行心跳或清理()
            }
        }
    }
}
```

### CWD-1137 在并发上下文中使用不可重入函数

**定义**: 在信号处理器、中断处理器或异步回调中调用不可重入函数，可能导致数据损坏或死锁。

**触发条件**:
- 信号/中断处理器中调用非重入安全函数
- 异步回调中修改共享状态
- 处理器中使用锁或分配内存
- 处理器中调用复杂库函数

**通用概念**:

**可重入函数特征**:
- 不使用静态或全局变量
- 不修改共享状态
- 不调用非重入安全函数
- 所有状态通过参数传递

**通用案例：信号处理器中的危险操作**

```
// 危险模式（伪代码）
全局变量 日志缓冲 = []
全局变量 锁 = 创建锁()

函数 信号处理器(信号) {
    // 危险操作1：使用锁
    获取锁(锁)                  // 可能死锁
    日志缓冲.添加("收到信号")
    释放锁(锁)
    
    // 危险操作2：内存分配
    新对象 = 分配内存()         // 非重入安全
    
    // 危险操作3：复杂输出
    打印("处理信号")           // 通常非重入安全
}

// 问题场景：
// 主程序：获取锁
// 此时收到信号，中断主程序
// 信号处理器：尝试获取锁 - 死锁！
```

**安全模式**:
```
// 安全实现：只设置标志（伪代码）
全局变量 信号接收标志 = 0

函数 信号处理器(信号) {
    // 仅设置原子标志或简单变量
    信号接收标志 = 1
    // 不做其他操作
}

函数 主循环() {
    while (true) {
        if (信号接收标志 == 1) {
            信号接收标志 = 0
            // 在主线程安全处理
            处理信号()
        }
        
        // 正常工作
        执行任务()
    }
}
```

## 通用并发原则

### 1. Happens-Before 关系

**概念**: 操作A happens-before 操作B，意味着A的结果对B可见。

**建立方式**:
- 同一线程内的程序顺序
- 锁的释放 happens-before 后续获取
- 原子写操作 happens-before 原子读操作（使用适当的内存序）
- 线程启动 happens-before 该线程的所有操作
- 线程的所有操作 happens-before 线程结束检测

### 2. 内存可见性

**问题**: 一个线程的修改可能对其他线程不可见。

**原因**:
- CPU缓存
- 编译器优化
- 指令重排序

**解决方案**:
- 使用同步机制（锁、原子操作）
- 使用内存屏障或适当的内存序
- 避免依赖未同步的共享状态

### 3. 原子性

**定义**: 操作作为一个不可分割的整体执行，要么全部完成，要么全部不执行。

**非原子操作示例**:
- 复合赋值：`x++`、`x += 1`
- 64位值在32位系统上的读写
- 对象的多字段更新
- 集合的检查-修改操作

**保证原子性**:
- 使用锁保护整个操作序列
- 使用语言提供的原子类型
- 使用不可变数据结构

### 4. 可见性

**定义**: 一个线程对共享变量的修改，对其他线程的可见时机。

**问题场景**:
```
// 伪代码
全局变量 标志 = false
全局变量 数据 = 0

// 线程1
函数 写入者() {
    数据 = 42
    标志 = true    // 可能被重排序到数据=42之前
}

// 线程2
函数 读取者() {
    if (标志) {
        使用(数据)  // 可能读到数据=0
    }
}
```

**解决方案**: 使用适当的同步机制建立happens-before关系。

## 典型触发条件总结

| 并发问题类型 | 高频触发条件 |
|------------|------------|
| 竞争条件 | 检查-操作、读-修改-写、懒加载、单例模式 |
| 锁定不当 | 锁顺序不一致、锁粒度不当、持锁调用外部代码 |
| 缺少同步 | 共享变量未保护、集合并发访问、懒加载未同步 |
| 非同步访问 | 迭代器失效、生产者-消费者、生命周期问题 |
| 同步不正确 | 锁范围错误、原子操作误用、临界区不完整 |
| 未设置超时 | 锁等待、条件等待、IO操作、外部资源访问 |
| 不可重入 | 信号处理器、中断处理、异步回调中的复杂操作 |

## 典型误报场景

**不应报告为问题**:
- 正确使用同步机制保护的共享资源
- 使用不可变对象或值类型
- 线程局部存储或线程私有数据
- 单线程上下文中的代码
- 使用原子操作正确保护的变量
- 使用消息传递而非共享内存的并发模型
- 正确使用读写锁的读多写少场景
- 使用线程安全的数据结构或库

**常见的非问题场景**:
```
// 场景1：不可变对象（伪代码）
类 不可变配置 {
    只读属性 值1
    只读属性 值2
    
    构造器(v1, v2) {
        值1 = v1
        值2 = v2
    }
}
// 多线程共享不可变对象是安全的

// 场景2：线程局部存储（伪代码）
线程局部变量 缓冲区 = []
// 每个线程有独立的缓冲区副本

// 场景3：函数局部变量（伪代码）
函数 处理() {
    局部变量 temp = 0    // 栈上分配，线程私有
    temp = 计算()
    返回 temp
}
```
