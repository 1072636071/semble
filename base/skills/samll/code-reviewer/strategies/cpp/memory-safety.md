## 能力目标

基于内存访问模式和语言特性,判断真实内存安全风险,避免模式匹配式误报。

---

## 前置判断

获取:
- 语言特性:C 依赖手动管理,C++ 有 RAII/智能指针
- 是否使用安全函数(`memcpy_s`/`strncpy` 替代 `memcpy`/`strcpy`)
- 内存分配方式:堆/栈/静态内存
- 多线程环境下的并发访问
- 输入来源:用户输入/网络数据/可信数据

---

## 分析流程

### Step 1 — 识别内存操作点
定位内存相关操作:
- 分配:`malloc`、`calloc`、`alloca`、`new`
- 释放:`free`、`delete`
- 复制:`memcpy`、`strcpy`、`sprintf`、`operator=`
- 访问:数组下标、指针算术、解引用

### Step 2 — 验证边界完整性
- 检查缓冲区大小是否足够容纳输入
- 验证循环边界条件
- 确认字符串以 null 结尾

### Step 3 — 检查输入约束
- 外部输入是否有长度/范围验证
- 是否信任输入的合法性
- 是否存在可被外部控制的内存大小参数

### Step 4 — 分析指针生命周期
- 悬垂指针风险
- 返回指向栈内存的指针
- 释放后的引用检查
- 尝试访问或操作一个值为 `null` 或 `undefined` 的对象引用

## 风险模式分类

### CAT-0044 未正确分配内存
内存分配大小不足或分配失败导致的问题。

**触发**:
- `malloc`/`calloc` 分配大小为 0 或负值
- 乘法运算导致大小溢出: `malloc(n * m)` 当 n*m 超出 `size_t` 范围
- 未处理内存分配失败返回 NULL 的情况
- 分配大小与实际需求不匹配

**分析**:
追踪大小计算表达式,验证乘法是否可能溢出,检查分配失败的处理逻辑,确认分配大小覆盖所有使用场景。

---

### CAT-0045 依赖错误的内存布局
假设内存按特定方式对齐或排列,但实际布局与假设不符。

**触发**:
- 对齐假设(如假设 `int*` 是 4 字节对齐)
- 结构体填充和跨平台兼容性问题
- 不同平台 `sizeof` 结果不一致
- 序列化/反序列化时假设内存布局一致

**分析**:
验证对齐约束,检查结构体定义的跨平台兼容性,确认序列化/反序列化使用明确的字节序而非内存复制。

---

### CWD-1009 未受认可的内存安全函数
使用已知的危险函数而非安全替代函数。

**触发**:
- `strcpy`、`strcat`、`sprintf` 等不检查边界
- `gets` 不限制输入长度
- `scanf` 未指定字段宽度
- `memcpy` 未验证源和目标大小

**分析**:
识别所有字符串和内存操作函数,检查是否使用带大小限制的版本,确认参数正确验证缓冲区大小。

**安全替代对照**:
| 不安全函数 | 安全替代 |
|-----------|---------|
| `strcpy` | `strcpy_s` / `strncpy` |
| `strcat` | `strcat_s` / `strncat` |
| `sprintf` | `snprintf` / `sprintf_s` |
| `memcpy` | `memcpy_s` |
| `gets` | `fgets` |

---

### CAT-0046 内存访问长度不正确
读写操作的长度与分配内存或预期不符。

**触发**:
- `memcpy`/`memset` 长度参数超过目标缓冲区大小
- 数组访问使用错误的大小(如 `sizeof(指针)` 而非 `sizeof(数组)`)
- 循环边界错误导致多一次或少一次迭代
- 字符串操作未考虑终止符的额外字节

**分析**:
验证所有长度参数与对应缓冲区的关系,检查数组/指针类型是否导致大小计算错误,确认循环边界覆盖所有元素但不越界。

---

### CWD-1017 内存拷贝重叠
源和目标缓冲区重叠时执行内存复制操作。

**触发**:
- 使用 `memcpy` 而非 `memmove` 处理重叠区域
- 同一缓冲区内进行自我拷贝
- 指针偏移后与原地址范围重叠
- 缓冲区片段移动操作

**分析**:
检查 `memcpy` 调用,确认源和目标内存区域是否重叠,验证指针偏移范围。

---

### CAT-0047 栈变量地址传递到其作用域外
返回或传递已失效的栈变量指针。

**触发**:
- 函数返回局部变量的地址或引用
- 将栈变量地址存储到全局变量或堆数据结构
- 线程传递栈变量地址到其他线程
- 异步回调中使用局部变量指针

**分析**:
追踪指针指向的内存区域(栈/堆/静态),验证指针的生命周期,检查返回值和回调的后续使用。

---

### CAT-0048 释放无效内存
释放非动态分配内存或未正确处理的内存。

**触发**:
- `free` 栈变量或静态变量
- 释放已经释放的内存(Double-Free)
- 释放非 `malloc`/`calloc` 分配的指针
- 释放部分分配内存(如指向结构体字段的指针)
- 野指针释放

**分析**:
追踪指针来源,验证是否来自堆分配函数,检查是否存在多处释放同一内存的代码路径。

---

### CAT-0049 过期指针解引用
使用指向已释放内存的指针。

**触发**:
- Use-After-Free: 释放后继续访问内存
- 悬垂指针:返回指向已释放栈变量的指针
- 多线程竞态:一个线程释放内存,另一个线程访问
- 释放后未置 NULL 继续使用

**分析**:
验证释放后的控制流,检查指针是否清理为 NULL,是否存在释放后继续访问内存问题，确认多线程访问保护机制。

---

### CWD-1027 内存在有效生命周期后未释放(内存泄漏)
分配的内存未被释放,导致资源耗尽。

**触发**:
- 所有执行路径缺少 `free`/`delete`
- 异常处理路径未释放已分配内存
- 循环中重复分配未释放
- 智能指针循环引用(C++)
- 长期运行的程序中临时对象泄漏

**分析**:
追踪所有分配路径,验证每个分支的释放逻辑,检查异常和错误处理,确认长期持有的数据结构清理。

---

### CWD-1028 数组索引越界
使用越界索引访问数组元素。

**触发**:
- 负数索引访问
- 索引超过数组大小
- 循环边界错误: `i <= n` 而非 `i < n`
- 用户输入控制的索引未验证
- 忘记数组空位

**分析**:
验证数组访问的边界条件,检查索引来源是否可控,确认循环和迭代器正确性。

---

### CWD-1029 指针偏移量超出范围
指针算术运算导致指针指向有效分配区域之外。

**触发**:
- 指针加减访问超出分配范围
- 指针与不同数组之间的计算
- 多次偏移未验证中间边界
- 指针与 `NULL` 或无效指针算术运算

**分析**:
追踪指针起始位置和偏移量,验证最终指针是否仍在原分配范围内,检查指针类型匹配。

---

### CWD-1030 访问未初始化的指针
使用未初始化或未赋有效值的指针。

**触发**:
- 指针变量声明未赋予初值且直接使用
- `malloc` 分配的内存未初始化内容
- 局部指针变量未指向有效内存
- 结构体中指针字段未初始化
- 指针变量、表示资源描述符的变量、BOOL变量声明必须显式赋予初值

**分析**:
验证所有指针声明和赋值,检查 `malloc` 后的初始化逻辑,确认使用前指针已指向有效内存。指针变量、表示资源描述符的变量、BOOL变量声明必须显式赋予初值。

---

### CWD-1031 空指针解引用
解引用值为 NULL 的指针。

**触发**:
- 未检查 `malloc`/`calloc` 返回 NULL 就使用
- 未验证输入参数是否为 NULL
- 函数可能返回 NULL 但调用者未检查
- 数据流中指针被置 NULL 但后续仍使用
- 逻辑误判导致指针保持 NULL

**分析**:
追踪指针是否检查 NULL,验证所有解引用前的非断言检查,确认可能返回 NULL 的函数调用后检查。

---

### CWD-1034 不受信任的指针解引用
解引用来自不可信来源的指针或索引。

**触发**:

- 用户输入作为数组索引或指针偏移
- 网络数据包含指针值或地址
- 文件解析中的偏移量直接使用
- 反序列化数据中的原始指针
- 未验证的共享内存内容

**分析**:
追踪指针/索引来源,进行外部输入的参数进行合法性检查，确认在使用前的进行范围和有效性验证。

---

### CAT-0050 指针类型转换错误
不安全的指针类型强制转换。

**触发**:
- 不同大小类型之间转换(如 `int*` 转为 `char*`)
- 通过类型转换绕过类型检查
- 将数据强制解释为其他类型
- 联合体不安全使用实现类型混淆
- `void*` 泛型指针误用

**分析**:
追踪指针类型转换链,验证内存布局兼容性,检查序列化/反序列化边界,确认转换语义正确性。

---

### CWD-1040 不正确的null结束符
字符串未正确以 null 字节终止。

**触发**:
- `malloc` 分配但忘记写入终止符
- `memcpy` 复制字符串未包含终止符
- 字符串操作超出缓冲区导致截断
- 字符串拼接未检查剩余空间
- 二进制数据错误当作字符串处理

**分析**:
确认分配大小包含终止符空间,验证字符串操作的边界,追踪字符串传递后的使用。

---

### CWD-1042 未受控的格式化字符串
使用用户输入或不可信数据作为格式化字符串。

**触发**:
- `printf`/`sprintf` 使用外部输入作为格式字符串
- `syslog` 直接包含用户数据
- 错误消息包含用户内容未转义
- 格式字符串攻击漏洞

**分析**:
检查所有格式化函数调用,验证格式字符串参数是否为固定字符串,确认外部输入使用 `%s` 而非直接嵌入。

---

### CWD-1043 容器访问越界
访问容器(STL容器、数组等)超出有效范围。

**触发**:
- STL容器 `operator[]` 未检查边界
- `std::vector::at` 异常未捕获
- 迭代器失效后继续使用
- 容器操作(插入/删除)导致迭代器/引用失效
- 容器大小假设错误

**分析**:
验证容器访问方式,检查迭代器失效模式,确认容器修改后的引用有效性。  

---

## 代码分析视角

### 1. 数据流分析
追踪数据从输入到内存操作的传递链,验证每个转换点的安全约束。

### 2. 整数范围分析
检查大小计算、数组下标、循环边界是否防止溢出。

### 3. 控制流分析
验证错误路径、异常情况下的内存操作一致性。

### 4. 指针分析
追踪指针的指向、生命周期、所有权和别名关系。

## 典型触发条件

| 风险模式 | 高频触发条件 |
|---------|-------------|
| 缓冲区溢出 | `strcpy`/`sprintf`、用户输入长度未验证 |
| 越界读取 | 数组下标未检查、字符串未 null 结尾 |
| 栈溢出 | 自动变量缓冲区、递归过深 |
| 堆溢出 | `malloc` 大小溢出、写入边界越界 |
| 悬垂指针 | 返回局部指针、释放栈地址 |
| Use-After-Free | 释放后未置 NULL、多线程竞态 |
| Double-Free | 错误路径重复释放、所有权不清 |
| 未初始化内存 | `malloc` 后未清零、局部变量未初始化 |
| 整数溢出 | `malloc(n*m)` 乘法溢出、用户可控 size |
| 类型混淆 | 强制指针转换、联合体误用 |

## 典型误报场景

不应报告:
- 使用安全函数(`memcpy_s`/`strcpy_s`)且有正确参数验证
- 循环边界显式检查且不可溢出
- 经过验证的输入数据(如配置文件格式正确)
- `malloc(0)` 或其他规范允许的边界情况
- 内部函数调用,输入已预验证
- 编译器静态分析已排除的场景

---

## 安全函数对照表

| 不安全函数 | 安全替代 | 注意事项 |
|-----------|---------|---------|
| `strcpy` | `strcpy_s` / `strncpy` | 需指定缓冲区大小且验证 |
| `sprintf` | `snprintf` / `sprintf_s` | 需指定缓冲区大小 |
| `strcat` | `strcat_s` / `strncat` | 需检查剩余空间 |
| `memcpy` | `memcpy_s` | 需检查源和目标大小 |
| `gets` | `fgets` | 永远不要用 `gets` |
| `scanf` | `fscanf` + 长度限制 | 格式字符串安全检查 |
