# 学习记录格式

学习记录存放在 `./learning-records/` 中，使用顺序编号：`0001-slug.md`、`0002-slug.md` 等。延迟创建目录——仅在写入第一条记录时才创建。

它们是教学版的 ADR：记录非显而易见的教训、关键洞察和已声明的先验知识，这些将引导后续会话。用于计算最近发展区。

## 模板

```md
# {所学或所确立内容的简短标题}

{1-3 句话：学到了什么（或确立了什么先验知识），以及为什么它对后续会话重要。}
```

这就是全部格式。一条学习记录可以只是一段话。其价值在于记录*这*现在是已知的，以及*为什么*它改变了下一步该教什么——而非填满各个章节。

## 可选部分

仅在它们增加真正价值时才包含。大多数记录不需要。

- **Status** frontmatter（`active | superseded by LR-NNNN`）——当早期理解被证明有误并被替换时有用。
- **Evidence** ——用户如何展示该理解（回答的问题、完成的练习、引用的先前经验）。当该论断可能被重新审视时有用。
- **Implications** ——这为后续会话解锁了什么或排除了什么。在非显而易见时值得记录。

## 编号

扫描 `./learning-records/` 找到最高现有编号，然后加一。

## 何时写学习记录

以下任一情况为真时写一条：

1. **用户展示了对非平凡内容的真正理解** ——不仅是接触，而是能正确使用该概念的证据。这为下一步该教什么设定了新的下限。
2. **用户披露了先验知识** ——"我已经知道 X"。记录它以免后续会话重复教学。同时记录所声称的*深度*。
3. **纠正了一个误解** ——用户之前相信了错误的东西，现在明白了为什么。这些是高价值的：它们预测相关主题的未来绊脚石。
4. **使命因学习而转移** ——用户发现他们关心的是与最初不同的东西。交叉链接到 [[MISSION.md]] 并更新它。

### 什么*不*符合条件

- 仅仅覆盖过的内容。覆盖不是学习。等待证据。
- 已在 [[GLOSSARY.md]] 中作为术语定义简洁捕获的任何内容。不要重复。
- 逐会话的活动日志。学习记录不是日记——它们是决策级别的洞察。

## 取代

当后续记录与早期记录矛盾时（用户的理解深化或纠正了），将旧记录标记为 `Status: superseded by LR-NNNN` 而非删除它。理解如何演变的历史本身也是有用的信号。
