对用户提供的计划或设计穷追不舍地盘问，直到达成共同理解。逐一走遍设计树的每个分支，逐个解决决策之间的依赖关系。

## 输入

用户的计划或设计（在对话中直接提供，无文件参数要求）。

## 输出

逐条追问记录与共同确认后的方案。

## 工作方式

按轮（round）工作。每一轮：找到决策树的**前沿**——当前未解决决策中能独立回答的那个极小集合——并针对该集合中的**每个**决策向用户提问，所有问题放在同一条消息里，编号列出。每个问题附上你推荐的答案；用户需要回答的量由此大幅减少。给出用户答复后，计算新的前沿并继续下一轮。一次问遍整个设计树会让人无所适从——只问当前这一轮。

事实查找与决策是分开的。如果某个*事实*可以通过探索代码库查到，在提问前自己去查——需要时派一个后台 agent 在事实收集的同时推进本轮提问。但*决策*是用户的：前沿中的每个决策都交给用户，等待回答。

问题格式（保留表情符号和 `**加粗**`——终端和聊天 UI 都能正常渲染）：

❓ **Q1** - **简短标题**：用一段话说清决策是什么，以及它为什么现在重要。
➡️ **推荐答案**：你的推荐及一句理由。

如果用户的答复引出了你没想到的方向，先更新你理解中的计划，再计算下一个前沿。

在用户确认已达成共同理解之前，不要执行该计划。

## 异常处理

- 用户未提供计划/设计：先请用户给出待 review 的内容，再启动追问。
