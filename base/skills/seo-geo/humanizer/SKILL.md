# Humanizer · 去 AI 味

去掉文本里的 AI 写作痕迹，让它像人写的。中英双语，一个流程：**扫描 → 改写 → 评分验收**。

## 铁律

- **不改事实**——数据、来源、人名、时间、核心论点一律保留
- **不改语气基调**——除非用户明确要求换风格
- 只删填充性修辞，**不删有信息量的内容**
- 禁止用新的 AI 模式替换旧的（别用新三段式换掉旧三段式）
- 已经自然流畅的段落**不改写**
- **未评分不交付**

| 用户说 | 走哪一步 |

用户没给原文 → 问一句"把要改的文字发我"，别自己编。

## 1. 扫描

### 1a. 脚本扫描（自动，先跑）

```bash
python3 scripts/scan_ai_flavor.py <file>          # Markdown 报告
python3 scripts/scan_ai_flavor.py --json <file>   # JSON
python3 scripts/scan_ai_flavor.py <file> -o r.md  # 写文件
cat a.md | python3 scripts/scan_ai_flavor.py -    # 管道
```

纯 stdlib，中英词库都扫。输出：总分、命中位置（类别/行号/严重度/扣分）、Top 3 建议。
粘贴文本 → 先落临时文件再扫。Word/PDF → 转 txt 再扫。

### 1b. 模型语义扫描（脚本扫不到的）

脚本只认词面。这些必须你读一遍判断，扣分别漏：

- **B1 句式单一** — 连续 5 段以上句式雷同 / 每段都以短句机械收尾
- **B2 段落对称** — 每段都是"观点+论证+例子+总结"四件套
- **B3 标题层级滥用** — 一段一标题、标题带 emoji、标题全粗体加冒号
- **B4 总结段放之四海而皆准** — 结尾无具体数字/事实
- **B5 缺乏具体细节** — 全文无数字、无名字、无时间、无版本号
- **B6 缺乏个性化声音** — 无"我/我们"视角、无不确定性表达、无口语断句
- **B7 标点滥用** — 破折号「——」成灾、连续感叹号、排比反问

中文词库与改写对照：**`references/patterns-zh.md`**
英文词库与改写对照：**`references/patterns-en.md`**
评分算法与等级：**`references/scoring.md`**
完整对照范例：**`assets/examples.md`**

## 2. 改写

按扣分从高到低改，只改 Top 3 类通常够。

### 核心规则

1. **砍填充** — 去掉开场白和强调性拐杖词
2. **破公式** — 拆掉二元对比、戏剧性分段、修辞性设问
3. **变节奏** — 长短句交错。两项优于三项。段落结尾别都一样
4. **信读者** — 直接陈述，跳过软化、辩解、手把手引导。不解释自己的比喻
5. **删金句** — 一句话听起来像可引用的格言，重写它
6. **具体化** — 用数字、人名、时间、产品名替换形容词。删掉"XX 的体现/象征"

### 注入声音（删完套话 ≠ 有人味）

删光 AI 套话但依然没声音的文章 = 从"AI 体"变成"新闻通稿"，同样没人味。改完对照这五条自检：

- 有"我"/"我们"的具体视角
- 有具体数字、时间、人名、产品名
- 有不确定性表达（"其实""不过""还在想""我不太确定"）
- 有节奏变化（不是每句都 18 个字）
- 允许一点不完美——短句、糙句、口语、半成型的想法

**别过度**：正式报告不需要段子，技术文档不需要吐槽。声音要匹配文本的原始用途。

## 3. 评分验收

脚本给**词面基线分**，模型叠加 1b 的 B 类结构扣分，得终分。

| 分值 | 等级 | 动作 |
|---|---|---|
| 85-100 | 🟢 人话 | 直接交付 |
| 70-84 | 🟡 微 AI 味 | 局部优化后交付 |
| 50-69 | 🟠 中度 | 大改 1-2 段 |
| 30-49 | 🔴 重度 | 重写 |
| 0-29 | ⚫ 完全 AI 体 | 整段重写 |

**< 70 分必须回到第 2 步重改**，重点处理 Top 3。改完重跑脚本复评，分数必须上涨；没涨说明改错地方了。

## 输出模板

```markdown
## AI 味检测报告

**总分：** XX / 100  🟠 中度 AI 味

### Top 3 命中
| # | 类别 | 命中 | 位置 | 扣分 |
|---|---|---|---|---|
| 1 | A4 结尾升华 | `让我们共同…` | 第 N 段 | -X |

### 改写后（可直接替换原文）
> ……

### 变更摘要
- 删掉"作为……的证明"（模式 1 夸大意义）
- "赋能" → "帮"（A6 营销黑话）

### 复评
重跑脚本：XX → XX 分
```

用户只要改写稿时，省略报告表，但**分数和变更摘要不能省**。

## 适用范围

**适用**：公众号/小红书/知乎长文、产品文案、工作汇报、技术博客、新闻稿、邮件、代码注释里的说明文字。

**不适用**：文学创作（保留作者风格优先）、学术论文（术语有规范）、法律文书（用词需严谨）、翻译稿（保留原文结构优先）。

---

## 错误处理

| 情况 | 处理 |
|---|---|
| 输入为空 | 要求用户给文本 |
| 非中英文 | 提示本技能针对中英优化 |
| 原文已 ≥ 85 分 | 告知 AI 痕迹极少，只列可选优化点 |
| 改完仍 < 70 | 第二轮，只攻剩余 Top 3 |
| 改写丢了核心信息 | 回退该段，保留原文并标注需人工处理 |
