# 技能安装指南

本仓库技能通过单一入口 `base/scripts/ship.mjs` 分发到各平台技能目录（配置驱动于 `base/scripts/vendors.json`，零硬编码）。

## 源目录

| 源目录 | 路径 |
|--------|------|
| engineering | `base/skills/engineering` |
| productivity | `base/skills/productivity` |
| seo-geo | `base/skills/seo-geo` |

## ship 子命令一览

| 子命令 | 作用 |
|--------|------|
| `ship`（零参数） | 全流程：扫描 → 双模式派生/复制 → 安装 → SHA256 验证 → 残留清理 |
| `ship init` | 生成 `SKILL.src.md` / `AGENT.src.md` 骨架（`--type skill\|agent --name <x>`） |
| `ship derive` | 把含 `SKILL.src.md` / `AGENT.src.md` 的技能/Agent 派生到 `.generated/<vendor>/` |
| `ship install` | 安装到各平台目录；`--project` 装到当前项目工作区 |
| `ship check` | 预检（配置合法性、CodeArts 门禁、各派生版最小校验） |

### 常用选项

| 选项 | 作用 |
|------|------|
| `--project` | 项目级安装（装进当前项目 `.codebuddy/skills` 等） |
| `--user-home <dir>` | 重定向用户级根目录（测试 seam，配合 `--config` 注入 fixture） |
| `--dry-run` | 预演，不落盘 |

## 安装模式：用户级 vs 项目级

本仓库技能分两种安装目标：

- **用户级**（`ship install`，默认）：技能装进各平台用户主目录下（如 `~/.codebuddy/skills`），全局可用。
- **项目级**（`ship install --project`）：技能装进当前项目的工作区目录下（如 `.codebuddy/skills`），仅该项目可用，不同项目间版本与参数互不干扰。

### `x-install` frontmatter 取值

技能的 `SKILL.md` / `SKILL.src.md` frontmatter 可用 `x-install` 声明安装目标：

| 取值 | 含义 |
|------|------|
| `true` 或缺省 | 用户级 + 项目级都装（默认） |
| `false` | 不装（仅作派生源；`derive` 同样跳过） |
| `project` | **仅项目级装**，用户级跳过 |

### 双模式（dual-mode）

技能目录含 `SKILL.src.md` 时走**单源派生**（按 `vendors.json` 中各厂商派生规则产出适配版）；不含时走**原样复制 fallback**。`SKILL.src.md` 的存在与否即派生开关，Agent 同理（`AGENT.src.md`）。

### seo-geo 族：仅项目级分发

`seo-geo/` 桶下的技能族（审查模板、写作模板、五件套、`seo-router`）整体声明 `x-install: project`——**不会装进用户级目录**，只能通过 `ship install --project` 装进具体项目。这是 ADR 0005 的设计：营销域技能按项目参数生成子技能，不同项目间互不干扰。

```powershell
# 在目标项目根目录下执行（如 official-domestic-website）
node E:\work\sp\JwikisSkills\base\scripts\ship.mjs install --project
```

首次安装后，项目内的 `seo-router` 兼任安装器，负责后续的参数化生成、升级、缺失修复（详见 ADR 0005）。

## 目标目录

平台与目录全部外置于 `base/scripts/vendors.json`。以 `~` 开头的路径指各平台用户主目录下的相对路径：

| 平台 | 用户级 skills | 项目级 skills |
|------|---------------|---------------|
| OpenCode | `~/.agents/skills` | `.opencode/skills` |
| CodeBuddy | `~/.codebuddy/skills` | `.codebuddy/skills` |
| 码道（CodeArts） | `~/.codeartsdoer/skills` | `.codeartsdoer/skills` |
| Trae | `~/.trae-cn/skills` | `.trae/skills` |
| Qoder | `~/.qoder-cn/skills` | `.qoder/skills` |
| WorkBuddy | `~/.workbuddy/skills` | `.workbuddy/skills` |

> 以 `base/scripts/vendors.json` 实际声明为准；新增平台或调整目录只改该配置，不改脚本。

## 安装与验证

```powershell
# 全流程（零参数 = 扫描 + 派生 + 安装 + 验证 + 清理）
node E:\work\sp\JwikisSkills\base\scripts\ship.mjs

# 分步
node E:\work\sp\JwikisSkills\base\scripts\ship.mjs derive    # 派生 src 技能/Agent
node E:\work\sp\JwikisSkills\base\scripts\ship.mjs install   # 安装 + SHA256 验证 + 残留清理
node E:\work\sp\JwikisSkills\base\scripts\ship.mjs check     # 预检

# 项目级安装（seo-geo 族）
node E:\work\sp\JwikisSkills\base\scripts\ship.mjs install --project
```

- 安装输出对每个已装技能给出 **OK / MISMATCH / MISSING** 三态 SHA256 验证结果。
- 残留清理只动 `vendors.json` 中 `managedPrefixes` 声明的前缀（默认 `jxx-`、`huawei-cloud-`、`seo-`），不匹配前缀的目录绝不动。
- `x-install: false` 的技能（如 `jxx-teach`、`jxx-wait-what`、`skill-creator`、`skill-reviewer`、`skill-tester`）默认不安装，也不派生。

## 注意

- 不要复制 `README.md` 和 `正常的工作流.md`（非技能目录）
- 安装后重启各平台或重新加载技能列表
- 源目录中的 `.md`、`.json`、`.txt`、`.py`、`.sh` 等附属文件一并复制，技能可能依赖
- 每次修改技能源文件后，执行安装 + 验证，确保所有平台同步
- 若某技能已从源删除，安装脚本会清理目标中的残留目录；如需保留旧版，手动从目标移出
