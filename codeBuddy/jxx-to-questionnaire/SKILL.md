# To Questionnaire

将未决决策转化为别人能填写的文档。

你一直在和 A 来回沟通，但真正持有答案的是 B——客户、经理、安全团队、其他部门。A 不该背下你的问题再靠记忆带回答案。写一份问卷。

## 问卷是写给人读的，不是给 agent

文档的读者是要回答问题的人。问题措辞面向他们，不是面向你和 A 的讨论。扔掉 agent 词汇（"seam"、"ticket"、"red-green"），用回答者自己的词汇——业务语言、他们的产品名、他们的顾虑。

保持中立。你写给 A 的推荐、立场和倾向会污染答案。问卷问的是 B 的想法，不是确认你已经认定的东西。

## 流程

1. **收集未决决策。** 对话中每个悬而未决的问题——或 grill 揭示的、需要 B 输入的分支。每个成为问卷中的一节。
2. **按 B 的心智模型分组，而不是按你的。** 相关的问题放在一起，让 B 能在同一上下文中作答。节标题用他们认得的名字。
3. **写清每个问题需要怎样的答案。** 一句话说明你在找什么——"是/否加一句理由"、"一个数字"、"哪个选项、为什么"——让 B 知道怎样才算答完。
4. **留出作答空间。** 每节下留白行或 `**答：**`，让 B 直接在文档里写。问卷随作答一起返回——一来一回，不落东西。
5. **交给 A。** 一个文件、一条消息、一次转发。不要散装问题列表，不要聊天刷屏。

## 模板

```markdown
# 关于<主题>的问题

<一句话：这是什么、为什么需要你的输入。>

## <按 B 词汇命名的分组>

### <问题，以 B 能独立理解的方式表述>

<期待什么样的答案——格式、详细程度、截止时间（如有）。>

**答：**

## <下一个分组>

...
```

## 问卷回来之后

通读答案。哪条决策被解决了——去更新计划。哪个答案又引出新的分支——那是下一轮 `/jxx-grilling`，或一份跟进问卷，别两者混着来。带答案的问卷成为这个决策的记录：放进仓库，链接进 issue，或附加到 plan 之后。

## 反模式

- **用 agent 词汇写问题** — 问卷读者是要回答的人。扔掉"seam""ticket""red-green"，用他们的业务语言。
- **夹带倾向** — 把推荐、立场、倾向写进问卷。问卷问的是 B 的想法，不是确认你已认定的东西。
- **按你的心智模型分组** — 应该按 B 的心智模型分组，让 B 在同一上下文中作答。
- **散装问题列表** — 一个文件、一条消息、一次转发。不要聊天刷屏。
- **不写清期望答案** — 每个问题要说明"是/否加理由""一个数字""哪个选项"，让 B 知道怎样算答完。

## 异常处理

| 场景 | 处理方式 |
|------|---------|
| 答案又引出新分支 | 进入下一轮 grill 或跟进问卷，不混在同一份问卷里 |
| 持有答案的人不明确 | 先与当前对话的人确认 B 是谁 |
| 问题无有效答案 | 标注为开放项，不在问卷中强填 |
