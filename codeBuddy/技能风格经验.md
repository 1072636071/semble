# CodeBuddy 技能风格经验文档

> 本仓库 `codeBuddy/` 下 31 个 `jxx-*` 技能统一遵循的风格规范与写作经验。
> 撰写本仓库技能（新增或改造）时，以此文档为基准；评审时对照此清单逐项检查。

## 一、核心原则

CodeBuddy 技能的核心是：**描述（description）是唯一常驻触发面，正文（body）只在触发后加载。**

- `description` 写给**人**和**模型**——决定技能何时被触发，必须自带触发词与使用场景。
- `SKILL.md` 正文写给 **agent**——触发后才加载，可以详尽，但要简洁（skill-creator 建议 <500 行）。
- 详细的模板、示例、配置放 `references/`，按需加载，避免正文臃肿。

**三级渐进披露（progressive disclosure）：**

| 层级 | 内容 | 何时加载 |
|------|------|---------|
| 1 | `name` + `description`（约 100 词） | 始终在上下文 |
| 2 | `SKILL.md` 正文（<5k 词） | 技能被触发时 |
| 3 | `references/`、`assets/`、`scripts/` | agent 按需读取 |

## 二、Frontmatter 规范

统一采用以下字段顺序（`description` 是触发面，紧随其后放调用开关，最后是 `metadata`）：

```yaml
---
name: jxx-skill-name
description: >
  功能一句话 + 触发词 + 使用场景。
  description 过长时用 `>` 折叠多行。
disable-model-invocation: true
metadata:
  version: 1.0.0
---
```

### 字段细则

- **`name`**：kebab-case，小写英文字母 + 数字 + 连字符，≤64 字符，与目录名一致，不加语义噪音词（agent/tool/assistant）。
- **`description`**：
  - ≤1024 字符，非空。
  - 必须含 **功能**（做什么）+ **触发词/触发场景**（何时用）。
  - 面向人写"何时调用"，面向模型写"能做什么"。
  - 长描述用 YAML `>` 折叠多行（如 `jxx-goal-contract`、`jxx-goal-mode`）。
- **`disable-model-invocation`**：
  - `true` = **用户调用**（user-invoked）：只能人输入名字触发，剥离模型触达面，description 写面向人的一行摘要。适用于启动型/路由器型技能（如 `jxx-ask-matt`、`jxx-implement`、`jxx-goal-mode`、`jxx-grill-with-docs`、`jxx-handoff`）。
  - 省略 = **模型调用**（model-invoked）：agent 可自主触发。适用于共享词汇层/参考型技能（如 `jxx-codebase-design`、`jxx-domain-modeling`、`jxx-grilling`、`jxx-research`）。
- **`metadata.version`**：语义化版本号。大改内容升主版本，小修升次版本。改动后同步更新 `CHANGELOG.md`。
- **`argument-hint`**：可选，技能需要参数时给出提示（如 `jxx-handoff`、`jxx-loop-me`）。
- 其余字段（license、compatibility 等）本仓库一般不用，除非确实需要。

## 三、SKILL.md 正文结构

正文组织顺序建议（按需取用，不强制全有）：

```
# 标题                          # 中文标题，与技能职责对应

<开篇 1-2 句>                   # 一句话说明核心职责 / 核心判停依据
                                # 用 --- 与下一节分隔

## 何时使用                     # 适用场景；启动型技能必写
## 核心约束                     # 纪律性硬约束（文档先行、即时记录等）
## 工作流 / 流程                # 分步骤（第 1 步…第 N 步）
## 模式选择                     # 有分支时用表格列出"特征 → 模式 → 理由"
## 异常处理                     # 表格：场景 → 处置
## 反模式                       # 明确"不要做什么"，比正例更有约束力
## 相关技能 / 参考资源          # 上下游依赖、references/ 文件索引
```

### 写作要点

- **命令式祈使句**：直接写"先读 CONTEXT.md""运行 X 命令"，不要"你应该考虑……"。
- **模块间用 `---` 分隔**：一级模块（`##`）之间用 `---` 划开（见 `jxx-research`、`jxx-agent-generator`）。
- **表格辅助**：模式选择、异常处理、验收标准、依赖关系多用表格，一目了然。
- **代码块引用产物**：文件结构、模板、格式用 ``` 代码块包裹；**注意不要写成 `\````（反斜杠 + 三个反引号），那是格式 bug**。
- **反模式必备**：每个技能都应有一节"不要做什么"。反模式通常比正例更能约束 agent 行为。
- **异常处理必备**：表格列出常见异常场景与处置方式（来源不可用、文件缺失、越界、矛盾信息等）。

## 四、配套文档

skill-creator 规范要求每个技能目录包含三件套（给用户看的）：

| 文件 | 内容 | 必需 |
|------|------|------|
| `SKILL.md` | 技能定义与规范 | ✅ |
| `README.md` | 用户指南：简介 + 何时使用 + 相关技能 | ✅ |
| `CHANGELOG.md` | 版本变更记录 | ✅ |
| `LICENSE.txt` / `LICENSE.md` | 许可证 | ✅ |

### README.md 风格

精简，三到四节即可：

```markdown
# jxx-skill-name

<一句话功能简介>

## 何时使用

<使用场景>

## 相关技能

- `/jxx-xxx` — 关系说明
```

### CHANGELOG.md 风格

```markdown
# Changelog

## 1.0.0 — 2026-08-11

初始版本 / 做了什么改动。
```

日期用 `YYYY-MM-DD`。改动后必须同步：`SKILL.md` 的 `metadata.version`、`CHANGELOG.md` 的记录、`README.md` 的描述三处一致。

## 五、命名与调用规范

### 技能名（kebab-case）

本仓库统一前缀 `jxx-`，后接功能动词。功能性命名，`[Action]-[Object]` 结构：

- `jxx-code-review`（审查代码）
- `jxx-to-spec`（转成规格）
- `jxx-grill-with-memorial`（带奏报的追问）

### 调用开关与分工

| 类型 | `disable-model-invocation` | 触发方式 | 典型技能 |
|------|---------------------------|---------|---------|
| 模型调用（词汇/参考层） | 省略 | agent 自主 | codebase-design、domain-modeling、grilling、research |
| 用户调用（启动/路由/封装） | `true` | 人输名字 | ask-matt、implement、goal-mode、handoff、triage |

## 六、经验教训（本仓库踩过的坑）

1. **代码块转义**：`jxx-goal-execute` 曾出现 `\``` 写成 `\`````（反斜杠 + 反引号），导致嵌套代码块无法渲染。写代码块时用三个反引号即可，不要加反斜杠。
2. **frontmatter 字段顺序**：`disable-model-invocation` 与 `metadata` 顺序曾混用（有的在前、有的在后）。统一为 `description` → `disable-model-invocation` → `metadata`。
3. **配套文档缺失**：8 个技能曾缺 `README.md`/`CHANGELOG.md`（jxx-agent-generator、jxx-plan-review、jxx-triage、jxx-wizard 等）。新增技能必须三件套齐全。
4. **description 太长**：把"何时使用"写进了正文而非 description。`description` 是唯一触发面，"when to use"信息必须放在这里，正文只在触发后加载。
5. **`metadata.version` 缺失**：个别技能（如 `jxx-improve-codebase-architecture`）无 `metadata`，无法版本追踪。所有技能应带 `metadata.version`。
6. **反模式缺失**：翻译自 mattpocock 的部分技能缺「反模式」「异常处理」节。统一风格下应补齐。

## 七、自查清单（写/改技能后对照）

- [ ] `name` 与目录名一致，kebab-case，≤64 字符
- [ ] `description` ≤1024 字符，含功能 + 触发词，写给人与模型
- [ ] `disable-model-invocation` 位置与调用类型一致
- [ ] `metadata.version` 存在
- [ ] 正文命令式，含反模式与异常处理
- [ ] `README.md`、`CHANGELOG.md`、`LICENSE.txt` 齐全
- [ ] `SKILL.md` 版本号、`CHANGELOG.md` 记录、`README.md` 描述三者一致
- [ ] 无 `\````` 等代码块转义 bug
