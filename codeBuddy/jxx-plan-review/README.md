# jxx-plan-review

语义方案审查（门下省封驳）——在 goal-contract 和 goal-execute 之间独立审阅 GOAL.md 契约，检查方案可行性、覆盖完整性、风险盲区，输出**准奏 / 封驳 / 附条件准奏**。

## 何时使用

- `.goals/{name}/GOAL.md` 已固化后、进入执行循环前。
- goal-execute 启动前验证审查已通过（准奏 / 附条件准奏）。

## 审查维度

| 维度 | 审什么 |
|------|--------|
| D1 覆盖完整性 | 契约是否覆盖目标所有关键维度、有无遗漏边界场景或无声明假设 |
| D2 可行性 | 方案技术是否可行、切片依赖顺序是否正确、有无循环依赖 |
| D3 约束一致性 | Constraints 内部是否互斥、是否与 Goal 冲突、Budget 是否匹配 |
| D4 审计就绪性 | 验证命令是否可执行、输出是否可判定、Pause Conditions 是否合理 |
| D5 可恢复性 | 目标命名是否稳定、切片粒度是否足够细、有无最小可交付 |

## 综合判定

- 全部 ✅ → **准奏**
- 有 ⚠️ 无 ❌ → **附条件准奏**（进入执行但 PROGRESS.md 记录警告）
- 有 ❌ → **封驳**（列修正方向，打回 goal-contract）

## 相关技能

- `jxx-goal-contract` — 上游：契约固化 + 否决门（语法层）
- `jxx-goal-mode` — 上游：路由器
- `jxx-goal-execute` — 下游：准奏后启动执行循环
