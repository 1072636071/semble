# 调研与报告生成

收到请求后，先判断使用哪种模式。

## 模式选择

| 用户说 | 模式 |
| ------ | ---- |
| "调研 X""研究一下 Y""帮我查查 Z""了解下 W" | **自由模式**（默认） |
| "生成报告""写报告""严格模式""按模板""输出报告" | **严格模式** → [references/strict-mode.md](references/strict-mode.md) |

自由模式是默认。当前模型很强大 —— 给目标、不规定流程，有时效果更好。严格模式用于需要正式存档、汇报给他人的场景，详细工作流、模板选择、完成标准见严格模式定义文件。

---

# 自由模式

不规定流程。agent 自主决定：
- 从哪里收集信息（本地代码、文档、网络）
- 如何组织发现
- 输出什么格式、放在哪里

唯一硬要求：**每个论断可追溯到来源**（文件路径、URL、用户输入）。

---

## 通用护栏

以下约束两种模式均适用：

- **不编造结论。** 所有论断来自调研结果；找不到证据时写"未找到相关证据"，禁止凭空推断。
- **来源可追溯。** 每个关键结论标注出处。读者应能独立验证。

## 通用反模式

- **来源不可追溯。** 结论像凭空产生，读者无法验证 —— 这是报告最致命的缺陷。
- **信息过载。** 堆砌所有找到的信息，缺乏筛选和组织。信息整理是提炼，不是转储。

## 异常处理

以下场景两种模式均可能遇到：

| 场景 | 处理方式 |
| ---- | -------- |
| 信息源不可用（网络搜索失败、链接失效） | 尝试替代来源；所有来源耗尽后标注"无法验证"并告知用户 |
| 模板文件缺失（严格模式） | 以 general 模板为兜底，提示用户模板缺失 |
| 输出目录不可创建（严格模式） | 降级到工作区根目录输出，并告知用户原因 |
| 用户请求超出 skill 能力范围 | 明确告知边界，建议切换到更合适的 skill |
| 结论相互矛盾 | 列出矛盾来源，标注置信度，让读者自行判断 |
