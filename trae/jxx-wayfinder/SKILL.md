一个松散的想法到来了——大到单个 agent 会话无法承载，且笼罩在迷雾中：从这里到**目的地**的路径尚不可见。寻路就是找到那条路径，而不是冲向目的地。此技能将路径绘制为 repo issue tracker 上的**共享地图**，然后逐一处理其工单，直到路径清晰。

目的地因工作而异，命名目的地是寻路的第一步——它塑造每个工单。它可能是一份交出去迭代的规格文档、一个在规划开始前锁定的决策、或一个就地完成的变更（如数据结构迁移）。地图是领域无关的——工程工作、课程内容，任何符合此形态的皆可。

## 规划，而非执行

Wayfinder 默认是**规划**：每个工单解决一个决策，地图在路径清晰时完成——在有人去做那件事之前，没有剩下需要决定的。想要直接动手的冲动通常是你到达地图边缘的信号，是时候交接了。一项工作可以在其**备注**中覆盖此默认——将执行带入地图本身——否则，产出决策，而非交付物。

## 按名称引用

每个地图和工单都是一个 issue，所以它有一个**名称**——它的标题。在人阅读的所有内容中——叙述、地图的"决策进展"——用名称引用，绝不用裸 id、编号或 slug。满屏的 `#42, #43, #44` 是不可读的；名称一目了然。id 和 URL 并不会消失——名称包裹着它的链接——但它们嵌在名称*之内*，从不替代名称。

## 地图

地图是 repo issue tracker 上的单个 issue，标记为 `wayfinder:map`——标准工件。其工单是地图的子 issue。

地图是一个**索引**，不是存储。它列出已做出的决策并指向持有其详情的工单；一个决策只存在于一个地方——它的工单——所以地图从不复述它，只做摘要并链接。

**地图、其子工单、阻塞关系和前沿查询的物理存放位置取决于 tracker。** issue tracker 应已提供——如果没有，运行 `/jxx-setup-matt-pocock-skills`。查阅 tracker 文档的"寻路操作"节，了解*此* repo 如何表达它们。如果没有提供 tracker，默认使用本地 markdown tracker。

### 地图正文

整个地图的低分辨率视图，每次会话加载一次。开放工单**不**列出——它们是开放子 issue，通过查询发现。

```markdown
## 目的地

<到达此地图终点意味着什么——此工作要寻找的路径所指向的规格文档、决策或变更。一两行；每次会话在选择工单前先对齐于此。>

## 备注

<领域；每次会话应查阅的技能；此工作的固定偏好>

## 决策进展

- [<已关闭工单标题>](链接) — <答案一行摘要>

## 尚未明确

<!-- 见"战争迷雾"：范围内你还无法开工单的迷雾；随前沿推进而毕业 -->

## 超出范围

<!-- 见"超出范围"：被排除在目的地之外的工作；已关闭，永不毕业 -->
```

### 工单

每个工单是地图的**子 issue**；tracker 的 issue id 是其身份。其正文是问题，大小适合一个 100K token 的 agent 会话：

```markdown
## 问题

<此工单解决的决策或调查>
```

每个工单带一个 `wayfinder:<type>` 标签——`research`、`prototype`、`grilling`、`task` 之一（参见[工单类型](#工单类型)）。

一个会话通过将工单分配给驱动地图的开发者来**认领**它，**首先**，在任何工作之前，这样并发会话会跳过它。被分配者*就是*认领：一个开放的、未分配的工单是未被认领的。

阻塞使用 tracker 的**原生**依赖关系——这很关键，因为它在 tracker 自己的 UI 中*可视化*地渲染前沿，所以人不打开地图就能看到什么可做。只有缺少原生阻塞的 tracker 才回退到正文约定。一个工单在阻塞它的每个工单都关闭时**解除阻塞**；**前沿**是开放的、解除阻塞的、未认领的子工单——已知世界的边缘。

答案不是正文的一部分——它在解决时记录（参见[处理地图](#处理地图)）。解决工单时创建的资产从 issue 链接，不粘贴进去。

## 工单类型

每个工单要么是 **HITL**——人在回路中，与人*一起*工作，由人代表自己发言——要么是 **AFK**，由 agent 单独驱动。HITL 工单只能通过实时交流解决；agent 绝不代替人的那一方（一个自我回答问题的追问 agent 已经破坏了 HITL）。

- **Research**（AFK）：阅读文档、第三方 API 或本地资源如知识库。创建一个 markdown 摘要作为链接资产。当需要当前工作目录之外的知识时使用。
- **Prototype**（HITL）：通过制作廉价、粗糙、具体的可反应工件来提高讨论的保真度——大纲、粗略尝试、桩代码，或通过 /jxx-prototype 技能的 UI/逻辑代码。链接 prototype 作为资产。当"它应该长什么样"或"它应该怎么表现"是关键问题时使用。
- **Grilling**（HITL）：通过 /jxx-grilling 和 /jxx-domain-modeling 技能进行的对话，一次问一个问题。默认情况。
- **Task**（HITL 或 AFK）：必须在*决策*可以做出之前完成的手动工作——不涉及决策、prototype 或研究，但讨论被阻塞直到完成。注册服务以便评判其 API、配置访问权限、移动数据以便查看其形状。这是唯一*做*而非*决定*的类型——它存在的理由是解除决策的阻塞，而非交付目的地。agent 在可能时单独驱动（AFK）；否则给人类一个精确的检查清单（HITL）。在工作完成时解决；答案记录做了什么以及后续工单依赖的任何结果事实（凭据位置、新 URL、行数）。

## 战争迷雾

地图是*刻意*不完整的：不要绘制你还看不到的东西。活跃工单之外是**战争迷雾**——你能感觉到即将到来但还无法精确定位的决策和调查的模糊视图，因为它们依赖于仍然开放的问题。解决一个工单会清除它前方的迷雾，将现在可 spec 化的内容**毕业**为新的工单——一次一个，直到通往目的地的路径清晰且没有工单剩余。

地图的**尚未明确**节是记录那个模糊视图的地方：疑似问题、稍后要重访的区域。它是朝向**目的地**的未发现前沿——这里的一切都在范围内，只是还不够清晰到可以开工单。写得松散或充分都可以，取决于视图允许的程度；它同时作为协作者阅读工作方向的路标。

**迷雾还是工单？** 测试标准是你现在能否精确陈述问题——*不是*你现在能否回答它。

- **工单**当问题已经明确——即使它被阻塞且你还不能对其采取行动。
- **尚未明确**当你还不能那么精确地表述它。不要预先将迷雾切成工单大小的片段：它比工单更粗，一块迷雾可能毕业为多个工单，或者当前沿到达时一个也不毕业。

**尚未明确**排除已决定的内容（决策进展）、已是活跃工单的内容、以及超出范围的内容（下一节）。

## 超出范围

迷雾只朝向**目的地**聚集。目的地固定范围，所以目的地之外的工作是**超出范围**的——它不是迷雾，也不属于**尚未明确**。它在地图上有自己的**超出范围**节：你有意识地排除在*此*努力之外的工作。范围，而非清晰度，将它放在这里。

超出范围的工作永不毕业——前沿止于目的地——所以它只在目的地被重新绘制时返回，且作为新的工作，而非延续。

将某事排除在范围之外是范围界定行为，不是路径上的步骤。当一个已存在的工单发现位于目的地之外——规划时范围错误，或被解决方案暴露——**关闭它**（关闭的工单明确不在前沿），并在**超出范围**节留一行：摘要加上为什么超出范围，链接已关闭工单。它不属于**决策进展**，后者记录实际走过的路径——范围边界不是路径上的步骤。

## 调用

两种模式。无论哪种，**每次会话绝不超过一个工单。**

### 绘制地图

用户用一个松散的想法调用。

1. **命名目的地。** 运行 `/jxx-grilling` 和 `/jxx-domain-modeling` 会话以确定此地图在寻找什么路径——规格文档、决策或变更。目的地固定范围，所以首先确定它。
2. **映射前沿。** 再次追问，这次**广度优先**：横跨整个空间展开而非深入任何一条线，浮现开放决策和现在可采取的第一步。**如果这没有浮现迷雾**——通往目的地的路径已经清晰，整个旅程小到可以在一个会话中完成——你不需要地图。停下来询问用户想如何继续。
3. **创建地图**（标签 `wayfinder:map`）：目的地和备注填入，决策进展为空，迷雾草拟到**尚未明确**。
4. **创建你现在能 spec 化的工单**作为地图的子 issue——然后在**第二轮**连接阻塞边（issue 需要 id 才能互相引用）。连接将它们排序为前沿和被阻塞的；你尚无法 spec 化的所有内容留在迷雾中——**尚未明确**节。
5. 停下——绘制地图是一个会话的工作；不要同时解决工单。

### 处理地图

用户用一个地图（URL 或编号）调用。工单是**可选的**——没有的话，你选择下一个决策，而非由用户选。

1. 加载**地图**——低分辨率视图，不是每个工单正文。
2. 选择工单。如果用户指定了一个，使用它。否则按顺序取第一个前沿工单。**认领它**：在任何工作之前分配给自己。
3. 解决它——**按需缩放**：按需获取任何相关或已关闭工单的完整正文；调用 `## 备注` 块中命名的技能。如果不确定，使用 `/jxx-grilling` 和 `/jxx-domain-modeling`。
4. 记录解决方案：将答案作为**解决评论**发布，**关闭** issue，并向地图的决策进展**追加上下文指针**。
5. 添加新浮现的工单（创建后连接）；毕业答案已使其可 spec 化的任何迷雾，从**尚未明确**中清除每个已毕业的迷雾块使其只作为新工单存在。如果答案揭示一个工单——此工单或另一个——位于目的地之外，**将其排除在范围之外**而非在路径上解决它。如果决策使地图其他部分失效，更新或删除那些工单。

用户可能并行运行未阻塞的工单，所以预期其他会话会并发编辑 tracker。
