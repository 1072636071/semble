## 配置 ocr 的 LLM provider（OpenRouter）
- OCR 无内置 openrouter，用**自定义 provider** 接入（OpenRouter 兼容 OpenAI 协议）：
  `ocr config set provider openrouter` + `custom_providers.openrouter.url=https://openrouter.ai/api/v1` + `protocol=openai` + `providers.openrouter.api_key=<key>`（实际落盘在 `custom_providers.openrouter.api_key`）+ `model=nex-agi/nex-n2.5-pro:free`。
- 配置落盘：`~/.opencodereview/config.json`。`ocr config set model` 会把 model 写进当前 provider 的 `custom_providers.<name>.model`。
- 验证：`ocr llm test` → ✓ successful（Go 二进制不经 Windows schannel 吊销检查，能直连 openrouter，不受 curl 的 cert 问题影响）。
- 注意：`provider=openrouter` 的 api_key 设值时命令用 `providers.openrouter.api_key`，但二进制定向存到 `custom_providers.openrouter.api_key`，无需手动指定 custom_ 前缀。

## jxx-code-review 新增委托模式（v1.1.0）
- 位置：`base/skills/engineering/jxx-code-review/`（SKILL.md / CHANGELOG.md / README.md）。
- 需求：ocr 装了 → 委托模式 **3 维度**审查；没装 → 降级为原 **2 维度**。
- 实现：流程新增「步骤 0：选择执行模式」（`which ocr || command -v ocr || where ocr`，只检测一次，可 `--mode delegate|builtin` 覆盖）。
  - 委托模式 D1–D5：`ocr delegate preview` → `ocr delegate rule <path...>` → 按 mode 用 git 取 diff（range=`git diff <merge_base>..<to> -- <p>` / commit=`git show <c> -- <p>` / workspace=`git diff HEAD -- <p>`+`cat` 未跟踪）→ 宿主 LLM 3 维度审查 → 按 Critical/High 必报、Medium 带上下文、Low 静默丢弃分级报告。
  - 3 维度 = 标准 + spec + **规则**（OCR 解析出的文件级规则组，NPE/线程安全/XSS/SQL注入等）；无 ocr 时规则维度不存在 → 2 维度。
- 已用本机 ocr v1.12.4 验证 `ocr delegate` 子命令与全部 flag 真实存在（`preview`/`rule`，别名 `d`；`-f json`；委托模式不支持 sarif）。
- 注意：委托模式 OCR 端不调 LLM，无需 `ocr config set` / LLM 环境变量。
- **踩坑复现**：Edit 又把 LF 文件整份翻成 CRLF（3 文件全中）。收尾必须用 python 二进制 `b.replace(b"\r\n", b"\n")` 还原，否则 `core.autocrlf=false` 下 git diff 全是噪音。
- 门禁：`node base/scripts/ship.mjs check` → 全部通过。
