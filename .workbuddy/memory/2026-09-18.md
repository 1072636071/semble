## jxx-to-spec：`.scratch` 写错目录的根因补全与二次加固

- 现象：agent 跑 `issue-flow.mjs to-spec` 时把 PRD 建到了错误位置，报错信息是「默认 `--root` 相对脚本自身位置（`../../.scratch`）」。
- 真因链：**本源早在 1.1.1 就修好了**（改 `resolveScratchRoot()` 锚 cwd），但**已安装副本不会自动更新**——
  `~/.workbuddy/skills/{jxx-to-spec,jxx-to-tickets}/scripts/issue-flow.mjs` 仍是旧的 `__dirname` 锚定版（hash 前缀 `7f6c71f5`，
  而 `.codebuddy/` 下已是新版 `e217e9f7`）。执行的是过期副本，所以防护全部失效。
- 教训：**改完本源必须跑 `node base/scripts/ship.mjs install`**，check-copies 只管仓库内三份副本，管不到安装目录。

### 本轮改动

- `base/scripts/issue-flow.mjs`：
  - 新增 `suspectRootReason(abs)` —— 命中工具安装目录段（`.workbuddy`/`.codebuddy`/`.claude`/`.qwenworkcn`）或就是用户 home 本身时判为可疑根。
  - `resolveScratchRoot()` 增加可疑根拦截：cwd 可疑时直接报错，不再向上"找到" home 下的 dotfiles 仓库而写进 `~/.scratch`。
  - 新增 `resolveDirArg(dir)`：`--dir` 传相对路径且 cwd 可疑时报错（原来 `path.resolve(opts.dir)` 会按错误 cwd 解析）。`next-issue`/`to-tickets`/`resolve-block` 三处接入。
  - 测试补 4 例（home 命中、安装目录段命中、dotfiles 误判、相对 `--dir` 拒绝）。
- 版本：`jxx-to-spec` 1.1.1 → **1.1.2**；`jxx-to-tickets` 1.2.2 → **1.2.3**。CHANGELOG 均已记。
- SKILL.md 指引：两个技能改用绝对路径示例，并写明「路径一律用绝对路径 + 改完必须 ship install」。

## 同类问题普查（其他生成文件技能）

- 扫 `base/skills/**/scripts/*.{mjs,js,py,sh}` 的 `__dirname` / `fileURLToPath(import.meta.url)` / `__file__`：
  除 `issue-flow` 外，**没有第二个脚本锚定自身位置**。仍有的四处都是仓库开发工具，可接受：

  - `skill-creator` / `skill-tester`：`node scripts/xxx.mjs` → `node <本技能目录>/scripts/xxx.mjs`，路径参数改绝对路径占位。

## 默认安装推荐名单 + 自动安装 runner（memorial 004）

- 新增 `tools/recommended-setup.json`（声明式清单，每项 `tier: required|recommended`，steps 多类型：install-script / bsk-install-skill / npm-global / skill-install / manual）+ `tools/bootstrap-setup.mjs`（零依赖 runner）。
- 用途：新同事 clone 后 `node tools/bootstrap-setup.mjs` 一键装必装插件（browser-skill、open-code-review 委托模式）。支持 `--required-only` / `--harness` / `--mirror off` / `--dry-run`。
- 关键设计：跨平台（Windows 走 ps1、Unix 走 sh）、幂等（verify 跳过）、失败不中断、人工步骤（浏览器扩展）标记 manual 不阻塞、镜像优先国内（npm npmmirror + ghproxy）、ocr delegate skill 用「npx skills add → verify → git clone+cp 兜底」链。
- 设计记录见 `docs/memorial/004-default-install-list/`；为何不复用 ship.mjs 见其 `adr/001-why-not-ship.md`。
