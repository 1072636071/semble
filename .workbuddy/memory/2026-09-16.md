## 诊断：jxx-to-spec / jxx-to-tickets 的 issue-flow.mjs 写错目录（未修，待决策）

**根因**：`DEFAULT_SCRATCH = path.join(__dirname, '..', '..', '.scratch')` 只在
`base/scripts/issue-flow.mjs`（`../../` = 仓库根）正确。commit 65f8b1bc 把该文件**逐字复制**
到 `base/skills/engineering/{jxx-to-spec,jxx-to-tickets}/scripts/`，深度 +2，
`../../` 落到 `base/skills/engineering/`；ship 派生安装到 `~/.workbuddy/skills/<skill>/scripts/`
后落到 `~/.workbuddy/skills/.scratch`。

**为什么静默**：`nextSeq` 对不存在目录返回 `01`（不报错）；`writeFileSafe` 用
`mkdirSync(recursive)` 自动建树；脚本只打印 `已创建 <错误路径>`；空目录 git 不可见。
实测复现：技能副本 `next-topic` → `01`（正确应为 `07`）；`to-spec --dry-run` →
`base\skills\engineering\.scratch\01-probe\PRD.md`。

**旁证**：`base/skills/.scratch`（空，09-16 08:25）是路径深度漂移留下的空壳。

**测试盲区**：`base/scripts/test/issue-flow.test.mjs` 全部传显式 `root` fixture，
默认 root 永不触发；技能内两份副本零测试覆盖。

**结论/待办**：默认 root 不应锚定脚本自身位置，应锚定 `process.cwd()` 并向上找
`.git`/`.scratch`；找不到时报错而非静默建目录；顺带收敛三份重复副本。
