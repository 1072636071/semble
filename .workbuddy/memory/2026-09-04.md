## gitee 在 agent shell 内无法自动认证（已解决一次）
- 现象：在 agent shell 执行 `git fetch origin` 报 `could not read Username for 'https://gitee.com': terminal prompts disabled`，且首次会卡 5 分钟。
- 根因：
  - 本机 PortableGit 凭据助手为 `helper-selector`（交互式 GUI 选择器），非交互 shell 一跑就卡死；`~/.gitconfig` 里 `credential.helperselector.selected=<no helper>`。
  - 本地 `~/.git-credentials` 只存了 `cnb.cool`，**没有 gitee 条目**；`credential.https://gitee.com.provider=generic` 实际就是读 store 文件，因无 gitee 条目而失败。
  - IDE 内之所以“自动”，是 IDE 自带 git 界面/终端注入了凭据；agent shell 没有这套注入。
- 可用解法（本次采用）：用 gitee PAT 通过 `url.insteadOf` 注入：
  `git -c "url.https://<user>:<TOKEN>@gitee.com/.insteadOf=https://gitee.com/" fetch origin`
  仓库 `jiangxiaocong/jwikis-skills` → gitee 账号用 `jiangxiaocong` 验证通过。
- 注意：`git credential approve` 写凭据被权限系统拦截；如需持久化建议改 `credential.helper` 配置或手动追加 `~/.git-credentials`（暂未做，避免破坏 IDE 机制）。
