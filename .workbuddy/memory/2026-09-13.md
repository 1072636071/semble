## 信任模型定型 + 宪章与工单修正（10:52）

用户澄清（原话）：「**人工不审核，不影响提交合并代码，我们认为 jxx-code-review 审核的技能是可信的**」。

**定型后的信任模型**（宪章新增「## 信任模型（前提）」节）：执行 agent 改代码 + 附可复现证据 + 验收分流 → **`jxx-code-review`（独立子 agent）复核证据可复现性与 spec 覆盖，不通过不得提交** → **人工只做体验 / UI 验证，不阻塞合并**。

**由此修正宪章**：

- 第四条「人工验证清单显式化」补一句 **不阻塞关单** —— 清单只需存在且条目完整，**允许长期未勾选**（是「待人工体验的待办」，非合并条件）。
- 新增两条铁律：① **复核者必须自己取证**（人工不看代码 ⇒ `jxx-code-review` 是**系统单点**，不得采信执行者提供的证据文本）；② **找不到 spec 必须标「未审」，不得静默通过**（否则「漏需求」检测消失 = **假绿灯**）。

**由此修正工单 06**（`.scratch/06-quality-charter-integration/issues/01-bind-charter-to-skill-layer.md`）：

- done 条件第 3 条：「无未勾选的人工验证项」→「**人工验证清单存在且条目完整（允许未勾选）**」。
- `jxx-code-review` 改动增一条：**堵假绿灯口** —— 无 spec 时显式标记「未审（无可用 spec）」，不得静默跳过（现行 §2 第 4 条正是「跳过并报告无可用 spec」）。
- 验收标准同步增「未审标记」一项。

**关键认识**：`jxx-code-review` 是这套体系里**唯一**的代码质量闸门，它的可靠性 = 整个信任链的可靠性。**它一旦采信文本而不取证，宪章全部条款同时失效。**
