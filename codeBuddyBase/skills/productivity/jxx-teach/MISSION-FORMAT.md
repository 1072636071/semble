# MISSION.md 格式

`MISSION.md` 位于工作区根目录。它记录用户学习该主题的*原因*。每个教学决策——接下来教什么、呈现哪些资源、设计哪些练习——都应追溯到这份文档。

## 模板

```md
# 使命：{主题}

## 为什么

{1-3 句话。用户追逐的具体现实目标。当他们拥有这项技能时，生活或工作会发生什么变化？避免"为了理解 X"之类的抽象框架——追问底层结果。}

## 成功的样子

- {用户将能够做到的一个具体、可观察的事情}
- {另一个具体的事情}
- {…}

## 约束

- {时间、预算、既有承诺、学习偏好、任何限制方法的因素}

## 超出范围

- {用户明确不想现在追求的相关主题——保护最近发展区}
```

## 规则

- **每个工作区一个使命。** 如果用户想学两个不相关的东西，那是两个工作区。
- **具体优于抽象。** "十月前跑完半程马拉松"优于"更健康"。"给团队发布一个 Rust CLI"优于"学 Rust"。
- **对模糊性提出质疑。** 如果用户无法说清为什么，先面试他们再写任何东西。糟糕的使命比没有使命更糟。
- **当现实变化时修订。** 使命会变。当用户的目标转移时，更新此文件——不要让过时的使命操控后续会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它已不再是罗盘而变成了计划。
