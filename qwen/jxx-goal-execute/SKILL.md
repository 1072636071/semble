# 目标自主执行循环

基于已固化的 `GOAL.md` 契约，自主拆解、执行、自检，直到验收全部通过才交付。

## 前提检查

启动前确认 `.goals/{name}/GOAL.md` 存在且包含 Goal、Acceptance、Budget。缺少必填字段则提示先使用 jxx-goal-contract 技能。

需确认语义审查已完成：`.goals/{name}/REVIEW.md` 存在且结果为"准奏"或"附条件准奏"。REVIEW.md 不存在或结果为"封驳"则提示先使用 jxx-plan-review 技能。

若 REVIEW.md 结果为"附条件准奏"——读取其中所有 ⚠️ 建议条目，写入 PROGRESS.md 顶部"每轮必读"块中，格式为：

```markdown
## 审查警告（本次执行留意）

- D{n}：<REVIEW.md 中的警告原文，逐条抄录>
```

执行循环每轮重读"每轮必读"块时自然看到这些警告，在对应维度上主动关注。

另需扫描 Acceptance 每条是否绑定 `（验证：...）`。发现无绑定的验收时：

1. 显式警告：这些验收无法命令化验证，循环判停将退化回 AI 自评。
2. 建议回 jxx-goal-contract 技能走"追加到已有目标"流程补齐验证命令。
3. 用户明确确认"先按现状执行"后才可继续，并在 PROGRESS.md 循环日志中记录该确认。

Constraints 和 Pause Conditions 是本技能的**熔断线与红灯**（见"护栏"），不是可选项。GOAL.md 缺少任一时：

1. 显式警告用户：该契约没有约束熔断和/或暂停红灯，循环将失去两类关键保护。
2. 建议回 jxx-goal-contract 技能补齐。
3. 用户明确确认"无约束/无暂停条件也要执行"后才可继续，并在 PROGRESS.md 循环日志中记录该确认。

如果 `.goals/{name}/PROGRESS.md` 存在且有执行记录，从中恢复进度（见"断点恢复"）。

### 独立启动

execute 不依赖 jxx-goal-mode 技能的路由——任何路径只要满足前提条件即可进入循环。它可被用户直接调用，也可被脚本/CI/自动化流程直接调用，共享同一套执行逻辑。

## 目标定位

收到执行请求时按以下优先级确定目标名称：

1. 用户明确指定名称（如"继续 linkcheck"）。
2. `.goals/_index.md` 中状态为 `执行中` 或 `已暂停` 的唯一目标。
3. `.goals/_index.md` 中有多个候选 → 列出候选，让用户选择。
4. 无任何目标 → 先使用 jxx-goal-contract 技能创建契约。

## 阶段 1 — 拆解

把目标拆成可独立验证的**纵向切片（vertical slice）**——每切片是一个面向用户行为的最小可交付单元，而非按层的水平切片。

- [ ] 每切片有独立的验收信号（完成后能单独验证）。
- [ ] 每切片显式标注关联的 Acceptance 编号（`#1`/`#2`…），写入切片状态表备注列。
- [ ] 切片之间显式标注依赖顺序。
- [ ] 切片集合覆盖 Goal 全部范围，无遗漏无重叠。
- [ ] 拆解结果写入 `.goals/{name}/PROGRESS.md`。

## 阶段 2 — 执行循环

每轮循环开始前重读 PROGRESS.md 顶部"每轮必读"块，并更新其中轮数与当前切片——该块是循环的状态锚点，凭记忆续跑一律视为违规。

每轮循环：

1. **选**——取下一个未完成切片。
2. **执行**——完成该切片；代码切片委托 jxx-tdd 技能或 jxx-implement 技能，研究子任务委托 jxx-research 技能。
3. **验证**——运行该切片关联验收条件绑定的验证命令（GOAL.md 中每条 Acceptance 的 `（验证：...）`），以命令实际输出判定通过/失败，并做整体回归（已通过切片不被破坏）。
4. **记录**——更新 `.goals/{name}/PROGRESS.md` 当前切片状态与所学。
5. **判停**——全部验收通过 → 阶段 3；否则记录所学，调整剩余计划，进入下一轮。

### 打断规则

循环默认**不打断用户**（push right）。仅以下情况停下来找用户：

- **触及约束**——任何动作将越过 GOAL.md 的 Constraints。
- **触发暂停条件**——任何动作将触发 GOAL.md 的 Pause Conditions。
- **预算耗尽**——达到预设轮数/时间上限仍未达标。
- **目标矛盾**——发现契约内部冲突或目标在现实中不可达成。暂停后引导用户回 jxx-goal-contract 技能重新走目标确认门（必要时使用 jxx-grill-me 技能收敛），修正契约后重新使用 jxx-plan-review 技能审查再恢复执行。
- **需改契约**——错误恢复的降级步骤需要修改 GOAL.md，必须先取得用户确认。

### 进度追踪

执行过程中维护 `.goals/{name}/PROGRESS.md`，格式（与初始化模板一致，含"每轮必读"块）：

```markdown
# 执行进度

- 目标名称：{name}
- 当前轮数：{N}
- 状态：执行中

## 每轮必读（执行任何动作前先读完本块）

- 当前轮数：{N} / 预算上限：{max}
- 当前切片：{当前切片}
- 本轮结束必须：跑验证命令 → 更新本文件（轮数 + 切片状态 + 循环日志）→ 对照 GOAL.md Acceptance 检查是否全部通过
- 禁止用"我觉得完成了"作为证据——每条验收的通过证据必须来自其绑定验证命令的实际运行输出
- 凭记忆续跑 = 违规：状态以本文件为准，不以对话记忆为准

## 固化日志

| 门  | 自检结果 | 独立检查结果 | 修正说明 |
| --- | -------- | ------------ | -------- |
| V1  |          |              |          |
| ... |          |              |          |
| V10 |          |              |          |

## 验收进度

| #   | 验收条件 | 验证命令 | 状态   | 证据 |
| --- | -------- | -------- | ------ | ---- |
| 1   | <验收1>  | `<命令>` | 待验证 | -    |

## 切片状态

| #   | 切片 | 状态     | 验证结果       | 备注 |
| --- | ---- | -------- | -------------- | ---- |
| 1   | ...  | ✅/❌/🔄 | 命令/文件/测试 | ...  |

## 循环日志

- **轮 {N}**：做了什么 → 验证命令输出 → 所学/调整

## 阻塞项

- <当前卡住的切片及原因>
```

`PROGRESS.md` 确保循环可中断后恢复——重新进入时先读"每轮必读"块再续跑。`PROGRESS.md` 是唯一权威状态，不以对话记忆为准。

### 宿主常驻规则（推荐）

技能是触发式加载的——长对话中技能正文会被挤出上下文，agent 会忘记自己在跑循环。对抗手段：把下面这段规则写入项目根目录的 `AGENTS.md`（或宿主每轮常驻注入的文件）：

```markdown
## 目标循环常驻规则

若工作区 `.goals/_index.md` 存在且其中有状态为"执行中"或"已暂停"的目标：
1. 处理任何请求前，先读 `.goals/{name}/PROGRESS.md` 顶部"每轮必读"块——了解有循环在场。
2. 若当前请求与目标相关：以 PROGRESS.md 为准推进，回复开头声明【目标：{name} | 轮数：N/上限 | 切片：X | 验收：Y/Z 通过】。
3. 若当前请求与目标无关：正常处理，首次回复提一句"目标 {name} 仍在执行中"即可，之后不再重复。
4. 状态以 PROGRESS.md 为准，不以对话记忆为准。
```

首次在某工作区启动循环时检查该文件是否含此规则；若无，建议用户添加（一句话提示，不阻塞启动）。

### 断点恢复

从断点继续时：

1. 读取 `.goals/{name}/PROGRESS.md`——**先读顶部"每轮必读"块**，再读全文。
2. 确认当前轮数、已完成切片、已通过验收。
3. 将"每轮必读"块的当前切片更新为恢复点切片。
4. 从下一个未完成切片继续执行。
5. 不重复已完成的工作——凭对话记忆"记得做过"不算数，以 PROGRESS.md 记录为准。
6. 更新 `_index.md` 状态为 `执行中`。

### 错误恢复

切片执行失败时：

1. **重试**——同一方法最多重试 1 次，调整参数或输入。
2. **换路**——重试仍失败则换一种实现策略，记录换路原因。
3. **降级**——换路也失败则将切片拆为更小子切片，或缩小该切片范围并更新 GOAL.md（需用户确认）。若降级涉及修改 GOAL.md，修改完成后必须重新经过 jxx-plan-review 技能（只审 D2 可行性 + D4 审计就绪性，不审全量 5 维），准奏后方可继续执行。若降级改变了目标本身（Goal 字段语义变化），则需退回 jxx-goal-contract 技能重新走目标确认门后再审查。封驳门不可绕过。
4. **跳过**——切片与核心目标无关时可标记为"跳过"，在 PROGRESS.md 中记录跳过原因，在交付时显式报告。
5. **熔断**——连续 2 个切片失败则暂停循环，向用户汇报卡点并请求决策。

## 阶段 3 — 自检与交付

逐条对照 `.goals/{name}/GOAL.md` 的 Acceptance，**逐条运行其绑定的验证命令**，以命令实际输出为通过证据——禁止用"我已实现 X"作为证据，禁止凭记忆或先前轮次的输出代替本轮实跑。

- [ ] 每条 Acceptance 的验证命令在交付前**实际重跑一遍**，输出原文摘录进证据。
- [ ] 未达标项显式列出，并说明卡点。
- [ ] 最终产物已就位（写入约定的交付位置）。
- [ ] 交付一份验收对照表写入 `.goals/{name}/EVIDENCE.md`（验收项 → 验证命令 → 命令输出摘录 → 通过/未通过）。
- [ ] 检查是否触发了 Pause Conditions——如有，在交付中显式标注。
- [ ] 更新 `_index.md` 状态为 `已完成` 或 `已失败`。

### 交付汇报格式

落盘 EVIDENCE.md 之外，给用户的交付消息统一为：

```
交付（目标：{name}，共 N 轮）：
- 验收：X/Y 通过，未通过项：<列出 + 卡点>
- 证据：.goals/{name}/EVIDENCE.md
- 跳过切片：<无 | 列出 + 原因>
- 触发的暂停条件：<无 | 列出>
- 契约改动：<无 | 已经用户确认的改动摘要>
- 最终产物位置：<路径>
```

## 工件持久化

| 阶段 | 文件 | 内容 |
| --- | --- | --- |
| 1-2 | `.goals/{name}/PROGRESS.md`（持续更新） | 拆解、进度、循环日志 |
| 3 | `.goals/{name}/EVIDENCE.md` | 验收对照表 |

## 护栏

- **约束即熔断。** 触及 Constraints 立即停，不"灵活变通"。
- **暂停条件即红灯。** 触发 Pause Conditions 立即停，报告用户。
- **预算上限。** 耗尽即停并汇报进展与卡点。
- **卡住要信息，不瞎猜。** 缺关键信息时明确索取。
- **不自我安慰。** 验收证据 = 验证命令的实际运行输出，不接受任何陈述。
- **状态在场。** 每轮先读 PROGRESS.md 顶部"每轮必读"块；凭记忆续跑 = 违规。
- **push right。** 默认不在循环中途打断。
- **可恢复。** 任何中断后读取 PROGRESS.md 即可续跑。
- **目标隔离。** 多个目标互不干扰，PROGRESS.md 和 EVIDENCE.md 各自独立。
- **可执行验证绑定。** 每条 Acceptance 的通过 = 其绑定验证命令的实际运行结果；没有命令绑定的验收 = 不合格，需先回 contract 补齐。

## 反模式

- **无限循环**——没有预算上限。设上限。
- **过程打断**——用户每步介入，退化回普通模式。让循环跑完。
- **自评通过**——用 AI 自己的陈述当验收证据。
- **凭记忆续跑**——不读 PROGRESS.md 就接着干。状态以文件为准。
- **无命令验收**——验收只写断言不写 `（验证：...）`。每条验收必须通过其绑定验证命令的实际输出判定。
- **忽略必读块**——不读"每轮必读"块就开始本轮动作。
- **跳过验证命令**——用"看起来没问题"代替跑命令。
- **忽略暂停条件**——Pause Conditions 不是建议，是红灯。
- **目标混淆**——同时操作多个目标但不区分进度。每个目标必须独立追踪。
