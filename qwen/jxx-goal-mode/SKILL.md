# 目标模式路由

以结果为导向的自主执行循环入口。用户只设定目标、验收标准与约束，AI 自主拆解、执行、自检，直到验收全部通过才交付。本技能是路由器，不直接执行工作。

## 路由决策树

收到用户请求后按以下规则分发：

1. **小任务**（步骤明确、一次性完成、预计 1-2 轮、改动限于单文件且无需运行验证命令且无跨文件调用点同步——三条全中才算）→ 说明"目标模式对此类任务只会增加开销"，建议直接执行，不进入循环。
2. **"列出目标"/"有哪些目标"** → 读取 `.goals/_index.md` 并展示所有目标及状态，询问用户要操作哪个。
3. **"继续 {name}"** → 检查 `.goals/{name}/` 状态：
   - 执行中/已暂停且 REVIEW.md 存在且审查距今 < 24h 且 PROGRESS.md 无契约改动记录 → 委托 jxx-goal-execute 技能断点恢复。
   - 审查距今 ≥ 24h 或有契约改动记录 → 快速复审查 D2 可行性 + D4 审计就绪性（约 30s），有 ⚠️ 无 ❌ 即可恢复，有 ❌ 则提示先回 jxx-goal-contract 技能修正。
   - REVIEW.md 不存在（旧目标从未审查）→ 委托 jxx-plan-review 技能全量审查后再恢复。
   - 契约中 → 委托 jxx-plan-review 技能审查，准奏后委托 jxx-goal-execute 技能开始执行。
   - 已完成/已失败 → 询问用户：重复还是新建？
   - 不存在 → 提示先创建契约。
4. **"重复 {name}"/"重做 {name}"** → 委托 jxx-goal-contract 技能（重复模式）。
5. **`.goals/` 已有目标且用户给了新目标** → 询问：新建 / 追加到已有 / 替换已有 → 均委托 jxx-goal-contract 技能对应模式。
6. **无 `.goals/` 或需要新建契约** → 委托 jxx-goal-contract 技能；契约固化完成后委托 jxx-plan-review 技能语义审查；准奏或附条件准奏后委托 jxx-goal-execute 技能；封驳则打回 jxx-goal-contract 技能读取 REVIEW.md 修正后重新审查。
7. **目标仍模糊** → 不启动循环，委托 jxx-grill-me 技能追问收敛后重新走 contract。

## 目标存储

目标存储结构（`.goals/{name}/` 目录、`_index.md` 索引、状态取值）的唯一权威定义在 jxx-goal-contract 技能，本技能只读取，不重复定义。

## 子技能职责

| 子技能 | 职责 | 何时调用 |
| --- | --- | --- |
| jxx-goal-contract | 契约固化：新建/继续/重复/追加，生成 GOAL.md | 需要创建或修改契约时 |
| jxx-grill-me | grill 追问：逐维收敛模糊目标 | contract 发现目标模糊时（由 contract 内部委托） |
| jxx-plan-review | 语义方案审查（门下省）：审可行性、覆盖、风险 | 契约固化后、执行前 |
| jxx-goal-execute | 自主执行循环：拆解→执行→验证→交付 | 语义审查准奏后 |

## 适用边界

**适合**：路径不确定、过程繁重的长任务——深度研究、长篇报告、批量修复代码、整理大量文献、撰写综述。

**不适合**：步骤明确的一次性小任务——翻译一句话、回答具体问题、单文件改名。此类任务直接执行，不要套用目标模式。

## 调用关系

- 契约固化：jxx-goal-contract 技能
- 目标收敛：jxx-grill-me 技能（由 contract 目标确认门内部委托）
- 语义审查：jxx-plan-review 技能
- 自主执行：jxx-goal-execute 技能
- 执行内部可委托：jxx-tdd 技能、jxx-implement 技能、jxx-research 技能
- 目标需先成规格文档：先使用 jxx-to-spec 技能
- 拆解纪律参考：jxx-to-tickets 技能
- 工作流需 spec 化：jxx-loop-me 技能
