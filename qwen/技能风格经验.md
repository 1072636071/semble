# Qwen 技能风格经验文档

本文档提炼 Qwen（千问办公助理）官方技能的写作规范，是本目录 31 个 jxx-* 技能在 2026-08 深度重写的统一风格依据。后续新增技能或优化既有技能，以本文档为准。

## 一、Qwen 技能的触发机制（风格的前提）

Qwen 平时只把每个技能的 `name + 一行 description` 提供给模型（渐进披露）；只有模型判断需要时，才加载 SKILL.md 全文。由此推出两条铁律：

- **description 是触发的唯一依据**。它必须让模型独立判断"该不该用我"：既要有足够的触发词覆盖，又要有明确的负向边界防止误触发。
- **正文是加载后的执行手册**。写给执行 agent 看，用命令式，直接可执行，不是给人阅读的介绍文章。

## 二、Frontmatter 规范

### name
- 与目录名一致，kebab-case，单行标量，不超过 30 个 Unicode 字符。
- 禁止 YAML 块标量（`|`、`>`、`|-`、`>-` 等）、禁止换行、禁止路径分隔符。
- 优化技能时**不改名**，即使名字不够理想（如 jxx-setup-matt-pocock-skills）——改名会破坏技能间互引。

### description（风格的核心）
- **单行普通字符串**，不超过 1024 个 Unicode 字符；禁止 YAML 块标量；无特殊字符时不加引号。
- **五段式结构**（按序书写，缺项可省略、顺序不可乱）：
  1. **能力定义**：一句话说清做什么、核心产出是什么。
  2. **适用场景**：何时使用，用"当用户……时使用"句式，枚举典型场景。
  3. **触发词**：直接枚举会触发的用户原话。格式：`触发词："……""……"。`
  4. **负向边界**：何时不用 / 不得触发。格式："不适用于……""……不要使用本技能""宽泛请求如 X 不得触发"。
  5. **技能间边界**：需要别的能力时指路。格式："如需 X 改用技能 Y。"
- 场景必须命中时用强约束措辞："**必须使用本技能**""严禁用……替代""必须先……再作答"。
- 官方范例（节选自系统内技能描述）：
  - excel："**凡是与 Excel/CSV 等结构化表格数据相关的任务，无论用户是否上传文件、也无论任务看起来多么简单——都必须使用本技能。**……本技能不负责获取外部信息。"
  - deep-research："如果通过简单的对比分析……就可以解决用户的问题，无需调用此SKILL。"
  - local-file-clean："【必要条件】用户原话必须明确涉及以下至少一项……宽泛的清理请求如【清理一下Downloads】，不得触发该Skill。仅输出方案，绝不自行删除。"
  - finance-data："触发短语：'股价'、'行情数据'、'涨跌'……"
  - qwen-faq-search："……必须调用本技能获取官方答案，禁止凭自身知识作答；不确定时倾向于调用。"

### metadata.version
- 语义化版本。description 变化会改变触发行为，**提升 minor**（1.0.0 → 1.1.0）；仅修错别字、不动触发语义才用 patch。
- 无 version 字段的技能补 `metadata.version`，从当前状态记为 1.1.0（视为已含本次风格化）。

### 不使用的字段
- Qwen loader 认可的可选字段仅：`when_to_use`、`effort`、`allowed-tools`、`license`、`compatibility`、`metadata`。
- Claude Code 特有字段（如 `disable-model-invocation`、`argument-hint`）在 Qwen 风格中不使用，重写时移除。

## 三、正文风格

- **命令式、流程优先**：开头一两句说清技能做什么，随后直接给可执行步骤；不写背景铺垫和营销性形容。
- **核心工作流留在 SKILL.md**；长篇参考资料（格式规范、模板、示例、检查表、主题库）下沉到 `references/`，并在 SKILL.md 中写清"何时读取"。
- **重复且要求确定性的操作**放 `scripts/`；**输出要复用的模板**放 `assets/`。
- 不重复内容、不深层引用链（references 不要再引用 references）。
- 保留原文的全部实质规则与知识；重写是重组与压缩，不是发明新流程。
- **跨技能引用**：写"使用 jxx-xxx 技能"，不用 slash command（`/jxx-xxx`）——Qwen 通过技能名调用。
- **修复失效引用**：如 jxx-goal-mode 原引用的 `/jxx-to-issues` 实为 jxx-to-tickets；jxx-tdd 根目录原有 tests.md / mocking.md，本次已中文化整理并移入 references/（勿在根目录与 references/ 同时保留同一参考文件）。

## 四、目录结构约定

- SKILL.md 直接位于技能根目录，是普通文件。
- 不新增 README、安装指南、CHANGELOG 等旁支文档；已有的旁支文档属历史遗留，保留但不作为风格组成部分，也不依赖其内容。
- `evals/` 为测试资产，与风格无关，不改。
- 技能根目录散落的参考文件（如 ADR-FORMAT.md、HTML-REPORT.md）统一移入 `references/`，并同步修正正文链接。

## 六、实战经验（本次重写沉淀）

- **批量委派必须核验**：子任务报告"已完成"不等于文件已落盘。每批完成后用 git status / 回读关键行核验，发现虚报立即重做，不追加信任。
- **同质技能先画边界矩阵再动笔**：grill 家族 5 个技能、goal 家族 4 个技能极易互相误触发；先把"谁管什么、何时改用谁"列成矩阵，再逐条写进各自的负向边界与指路段。
- **文件移动用 git mv**：参考文件下沉 references/ 时用 git mv 保留历史，正文链接同步改为 `references/xxx.md`，避免相对链接断裂。
- **同一参考文件不得双份**：根目录与 references/ 同时存在同名参考文件会造成引用歧义，迁移后删除原位置。
- **块标量是触发杀手**：`description: >` 多行写法在部分 loader 下解析异常或展示为多行，触发判断退化；一律压成单行。
- **版本提升是触发变更的信号**：description 改动会改变技能被加载的概率，升 minor 让调用方能从版本感知"触发行为变了"。
