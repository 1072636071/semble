把手动流程变成向导：一个交互式 bash 脚本，每一步都精确告诉用户要做什么，捕获他们粘贴回来的值，并在结束处写出配置文件。

## 何时使用

- 有人必须执行手动多步流程，agent 无法代劳（Web 控制台、注册表单、密钥生成、OAuth 授权）。
- 步骤超过约 3 个，或某一步产出的值是后续步骤的输入。
- 出错概率很高，你希望每个值都被捕获而不是丢在聊天记录里。

## 如何构建

复制 [template.sh](template.sh) 到仓库中合适的位置（`scripts/`、`bin/`，或已有的工具位置），然后**只编辑 STAGES 标记以下的部分**。标记以上是向导库——不要手改。

每个 stage 是一个人做的步骤。每个 stage 内部：

- `say` / `step` / `note` 给出指令——用户要点什么、在哪里、以什么顺序。
- `open_url` 在用户的浏览器中打开页面（跨平台，含 WSL）。
- `ask` / `ask_secret` 捕获值；`write_env` / `set_secret` 将其写入 `.env` / GitHub。
- 在人可能失败的地方用 `confirm` 设门；`pause` 表示"做完后按 Enter"。

将 `TOTAL_STAGES` 设为实际的 stage 数。

## 构建之前

1. **走完真实流程**（或在脑中精确走一遍）。每个 URL、按钮名称和字段标签都必须正确——写错指令的向导比 checklist 还糟。
2. **决定值的去向。** 模板支持 `.env` 和 GitHub 密钥（通过 `gh`）；如果你的栈需要别的，写一个小函数模仿 `write_env`。
3. **保持 stage 原子化。** 一个 stage = 屏幕上的一个概念性步骤。如果 stage 里有 5 个 `step`，考虑拆分。

## 反模式

- **不要为 agent 能自动化的步骤写向导。** 向导是给人用的；如果 `curl` 或 `gh api` 能做到，就那样做。
- **不要把密钥打进聊天或日志。** 用 `ask_secret`，并尽早写入存储。
- **不要捕获用户已有文件的值。** 如果 `.env` 里已有值，库会将其作为默认值提供——重新运行是安全的。

## 与其他技能的边界

- agent 可自动化的步骤 → 直接用命令行工具，不使用本技能。
- 需要梳理工作流 spec 而非生成执行脚本 → 使用 jxx-loop-me 技能。
